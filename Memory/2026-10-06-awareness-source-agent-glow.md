# 自感知生命周期与流光状态

## 现象

- 源文件删除后旧实现只把笔记标成不可用，Markdown、索引和版本备份仍留在记忆库。
- 用户前台 Agent 正在长任务时，自感知仍会并发调用后台模型。
- 旧流光只做小幅往返摆动，且截图常落在透明首帧；开始与消失只有简单透明度变化。

## 原因

- `handleUnlink` 没有走“删除笔记文件 + 状态 + 索引 + 版本目录”的完整清库语义。
- Agent 事件流没有区分 `awareness-*` 后台会话与用户 / 自动化会话，自感知队列缺少忙态闸门。
- CSS 动画使用 `alternate` 往复且只改变换；主进程在 220ms 后直接隐藏，无法容纳完整退场。

## 影响

- 已删除源文件仍可能被 Agent 工具读到，造成陈旧记忆与隐私残留。
- 前台任务和后台文件分析争用模型、抢 token，也让用户感觉系统“同时干很多事”。
- 流光看起来像静态渐变或闪烁，无法表达一次分析开始、持续处理和结束。

## 结论与做法

- 源文件删除必须同步删除对应 Markdown、状态项、`INDEX.md` 条目和 `versions/<noteId>/`；
  启动 / 扫描时核对应用离线期间消失的源文件。监控根本身不可访问时只跳过核对，不误删全库。
- 自感知用 `setAgentBusy` 闸住 `processQueue`；只忽略 `awareness-*` 会话，其他用户 / 自动化
  Agent 请求存在时暂停启动新任务，当前分析允许收尾，队列在 Agent 全部结束后自动继续。
- 流光持续态用单向 `background-position` 与横向光带流动，不使用 `alternate` 往复；
  入场从低位、强模糊展开，退场在约 560ms 内上移、压缩、模糊后由主进程隐藏。
- capture 的流光场景必须先等待入场完成再截图，否则会得到全透明 PNG；DOM 探针同时检查
  `animation-direction: normal`、无限循环、横向光带与根节点入场动画。

## 2026-10-06 流光自然化修订

首版增加流动后仍像一条横向扫描线。改为多束错速软光：宽泛光用多个径向渐变缓慢呼吸，
中层光带以不同相位漂移，核心电流降低到 1.5px 并柔化边缘，横向光团改成模糊的椭圆光斑。
所有周期不再使用 `alternate` 或匀速线性回环；入场从中心舒展，退场向外弥散。
capture 探针额外等待 650ms 对比前后背景位置 / 光团透明度，避免只证明“声明了动画”却实际静止。

## 2026-10-06 真实极光参考后的重构

搜索结果中的真实极光照片显示：主体不是顶部横线，而是从上方垂落的竖向光幕 / 光帘，
亮度集中在若干不规则光柱，颜色边缘柔和且随时间缓慢错相晃动。按这个依据删除横向扫描线与
横向光团结构，改为「底层色晕 + 左右错相光帘 + 中央核心光幕 + 呼吸柔光」五层组合。
capture 断言同步改成检查竖向 `repeating-linear-gradient`、三层光幕动画、入场和真实运动变化。

## 2026-10-06 光帘效果删除

竖向光帘仍被判定为过于具象、像屏幕上的布帘。最终删除光帘、竖向光丝、左右错相层和横向光团，
只保留单层低强度顶部柔光与缓慢呼吸；capture 只断言柔光层、入场动画和真实呼吸变化，
不再要求任何光帘 / 扫描线结构。

## 2026-10-06 保留光幕并加内部流光

用户确认截图中的竖向光幕形态需要保留，并要求在此基础上补流动感。最终恢复光幕本体，
在其内部叠加两条宽而软的左→右流光带，光幕颜色分布也沿同一方向循环流转；两条带使用不同速度
但不再反向，亮度在两端归零。不恢复硬边扫描线或横向光团，capture 同时检查光幕、两条流光、
颜色流转和 650ms 内的真实位置变化。
