## 本次发布链路上的三个卡点

1. **`release.mjs` 拒绝脏工作区**：`Design/notification-banner-prompt.md` 是未跟踪文件
   （本轮需求书），脚本直接 `工作区不干净：发布包应来自确定的提交` 退出（tag / 上传都还没开始）。
   处置：把它作为设计文档提交（与 `Design/betav2-spec.md` 同级）—— 归档需求书比每次发布前
   手工挪走更省事。
2. **Center 更新源的公开 URL 形状容易记错**：是
   `GET /api/updates/current`（返回 `{ current: {...} }`，**多一层 `current`**）、
   `GET /api/updates/latest.yml`、`GET /api/updates/<资产名>`（安装包走 Range）；
   写成 `/api/updates/file/<名字>` 会落到登录门禁后面 → `E_UNAUTHORIZED`（不是发布失败）。
3. **`AURORA_CENTER_PASSWORD` 不在环境里**：`--publish-center` 必须由用户当场提供管理员密码
   （账号固定 `admin`）。凭据不确定时最多试 1 次，撞到 429 要等满 60 秒。

## 口径（沿用 / 新增）

- 打包前**先停 dev 客户端**（`electron-vite dev` 会占 `node_modules/.pnpm/electron` 与 `out/`），
  版本号改完先 `pnpm install --frozen-lockfile`（`Already up to date`，不写盘）再跑 `release.mjs`，
  否则会被 `verify-deps-before-run` 的自动安装打断（老坑）。
- 发布命令拆两步更稳：`--notes-file … --publish`（构建 + 打包 + verify-update + tag + GitHub），
  然后 `--skip-package --publish-center --center-url http://120.24.223.65:8787 --center-user admin`
  （不重复打包、跳过已存在的 tag）。**不加 `--push`**：GitHub HTTPS 被掐，推源码走
  `git push git@github.com:LinePixel2025/Aurora.git main --follow-tags` + 手动对齐 tracking ref。
- 发布完成判据（本次逐条实测）：三资产齐全（exe / blockmap / latest.yml）+ tag 正文与 notes
  逐字一致 + GitHub body 与 notes 一致 + 本地 / Center / GitHub 的 `latest.yml` sha256 相同 +
  Center 安装包 Range 206。
- Center 服务器代码版本线仍独立（本次未换装：Center 仍是 0.5.0，不建 tag、不上传 GitHub）。
