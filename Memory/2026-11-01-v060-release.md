# v0.6.0 双投发布（2026-11-01）

- 桌面 **v0.6.0** 已双投：annotated tag `v0.6.0`（带完整 Release Notes，指向发布提交 `0f20bfd`）、
  GitHub Releases 三资产与 Aurora Center 更新源一致。
- 三资产：`Aurora-Setup-0.6.0.exe`（**203,448,524 B**）、`.exe.blockmap`（212,752 B）、
  `latest.yml`（341 B，sha256 `D8B22D67…E85AFC`）；GitHub / Center / 本地三份 `latest.yml`
  **逐字节相同**，Center `/api/updates/current` 返回 0.6.0，安装包 Range → **206**。
- 配置 Schema 仍 **v39**（无迁移、`notifications.size` 取值与默认值不变）；插件 API 仍 **v1**；
  Center 服务器仍 **0.5.2**（本版无 center 代码改动，不换装）。
- 本版内容：Computer Use v39.2（两层状态胶囊 520×88 / 结束即回前台 / 提示词强化）、
  流光提醒大屏可读性（卡宽按显示器比例 + `cqw` 流体字号 + 提示音三声重写 / 试听）、

  `chat-model-picker` 恒红探针）。

## 原因 / 本轮踩到的两个点

1. **先推 tag 再建 Release 的顺序这次生效了**：上一版（v0.5.9）`gh release create` 在远端还没有
   tag 时自动建了轻量 tag、Release 挂到了前一个提交。本轮按
   `release.mjs`（构建打包校验打 tag，不上传）→ `git push origin main` → `git push origin v0.6.0`
   → `release.mjs --skip-package --publish` → `--skip-package --publish-center` 拆成四步，
   `gh release create` 读到的是已推送的 annotated tag，`git rev-list -n 1 v0.6.0` 与 Release
   指向均为发布提交。
2. **「Release 正文乱码」是一次假警报**：用 Node `https` 拉
   `api.github.com/repos/.../releases/tags/v0.6.0` 校验正文时，先后两次读到正文里出现
   U+FFFD（长度 4957 / 4959，坏字符位置每次都不同），一度以为 `gh release create --notes-file`
   在 Windows 上按 GBK 读了文件并导致发布说明被写坏。
   实际用 `curl.exe` 连续拉三次、以及把响应存成文件后用 Node 比较，正文与
   `docs/release-notes/v0.6.0.md` **归一化后完全一致**（4951 字符、无 U+FFFD）；
   本地 tag 对象里的正文也逐字一致。即**存储侧没问题，是校验链路上的偶发传输 / 解码乱码**。

## 影响

- 若把偶发乱码当成「GitHub 正文已损坏」去反复 `gh release edit`，会在发布完成后继续改动远端
  发布记录，既浪费一轮上传窗口，也可能把本来正确的正文覆盖成半成品。
- 只按一次 HTTP 响应判断资产 / 正文一致性不可靠：长度、坏字符位置都会变，看起来像数据问题。
- 发布顺序若再退回「`release.mjs --publish` 一步到位」，v0.5.9 的轻量 tag 错位会重演
  （Release 挂在发布提交的前一个 commit，源码页面与安装包错位一版）。

## 结论与做法

- 发布照旧拆四步，tag 必须**先 push** 再 `gh release create`；发布后核对
  `git rev-list -n 1 v0.6.0` == Release 的 tag 指向 == 发布提交。
- **校验发布正文 / 资产一致性时，用 `curl.exe -o <文件>` 落盘后再比较（或对多次响应取哈希）**；
  Node `https` / `Invoke-WebRequest` 的单次读取出现 U+FFFD 或长度抖动时，先怀疑校验链路，
  换一条独立通道复核，不要直接改远端。
- 三源一致性判据（沿用）：本地 / Center / GitHub 的 `latest.yml` **sha256 相同**、
  安装包与 blockmap 的 size 相同、Center 安装包 Range 返回 206、
  Center `/api/updates/current` 的 version 与 `latest.yml` 一致。
- 管理员密码只当次使用、不落盘、不进 Memory；本版发布说明见
  `docs/release-notes/v0.6.0.md`，同步更新了 `README.md`、`docs/README.md`、`docs/04-roadmap.md`。
