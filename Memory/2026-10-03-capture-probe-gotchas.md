# 截图与冒烟验收口径

## 现象

1. 探针正文是 template literal（`apps/desktop/src/main/capture.ts`）：字符串**内部**注释写反引号会提前终止它——要么 `TS1005`，要么被解析成字符串拼接而 `tsc` 一声不吭。
2. 反斜杠少一层：本意 `/\s+/`、`/^\+/`，模板层先把 `\+` 吃成 `+`，渲染层收到非法正则 `/^+/`。这类错**不报在解析期**（`tsc` 与探针字符串护栏的前两条都看不见），只在 V8 编译时炸成报告里一句 `Script failed to execute`。
3. 字符串里的语法残渣（如多一个 `)`）同样绕过 `tsc` 与 `pnpm test`，只在 `AURORA_CAPTURE` 跑到那张图时红。
4. 场景互相污染：前一条关掉跟随没恢复，后一条 `chat-follow-burst` 长期 FAIL。
5. 同一段语义的判据写了两份（`pass` 与 `conditions` 表）并漂移：报告里每条都 `true`、探针恒定 FAIL。
6. 量到的是解析值而不是事实：没有左边框时 `border-left-color` 解析成 `currentColor`。
7. 夹具过期：项目根改按会话解析后，13 条断言连续多轮恒红，测的全是「越界拒绝」。
8. 抖动：同一份代码连跑全量，失败项组合每轮不同（四条根因见「结论与做法」）。
9. 当前基线：冒烟 **263/263**（约 40s）；全量截图 **113** 条 checks（按 **8 组窗口**组织）。

## 原因

- 探针正文以**字符串**形式存在，不经过 `tsc` 的语法校验，只有 V8 真正编译它时才暴露，报错还会丢上下文。
- 所有场景共用同一个渲染进程与页面，前一条不恢复自己的状态，后一条就在别人的残局上跑。
- 「存在性」（DOM 里有没有）与「可用性」（矩形在不在可视区、状态机对不对）是两回事；只查存在性的判据必然全绿。
- 夹具是按当时口径写死的：实现口径一变，它测的不再是被测行为，而是「按新设计的拒绝路径」——以**恒红**的形式持续收税。
- 负对照型判据（「不该出现 X」）在调用根本没成功时恒真；缺「调用成功」这个前提就只能算半个断言。
- 累计型指标与机器负载强相关；写死数值的断言与「正常演进」冲突。
- 全量要重建窗口、跑 113 个场景，固定成本高；迭代期在改动中跑还会与 `electron-vite dev --watch` 的重建交错（半成品产物 → 假红 / 挂死）。

## 影响

- 恒红会训练人忽略红：真实的回归混在里面没人看，排查时还会把它误判成自己引入的。
- **红着没人看见**与**绿着其实没测**（探针自己把要测的状态摆好，bug 永远不会被它发现）两类假信号，都会让人在错误前提上改代码、白跑截图。
- 迭代期每步跑全量，验证成本随改动次数线性增长。

## 结论与做法

### 探针写法

- 探针字符串里**不写反引号**（注释用「」或单引号）；能不用带反斜杠的正则就别用，非用不可时数清层数。
- 同一段语义的判据**只写一份**：让 `pass` 直接取 `conditions` 那张表的乘积。
- **量事实，别量解析值**：判断「有没有这条边」取宽度而不是颜色，并在正确时机量（折叠态、点击之前）。
- 每条场景自带前置与收尾，用应用自己的入口按钮恢复状态；**前置归 act，判定归 check**，不要用 `mode.set` / `location.reload()` 自愈（都比如实 FAIL 更糟）。
- 要测状态机，就写一条完全不碰状态、只读应用自己留下结果的探针（`CHAT_TRACE_FOLD_CHECK`）。
- 场景构成以 `report.json` 的实际条目为准，不按固定张数校验；当前按 **8 组窗口**（edge-bar / chat / settings / automation / onboarding / memory / widget / banner）组织。
- 护栏在 `apps/desktop/src/main/capture.probe-strings.test.ts` 三条（反引号拼接 / JS 解析 / V8 编译）；**加了新护栏不等于旧探针安全**，改探针每次自查。
- 失败判定 = `ok === false` **或**（`checked === true` 且 `result == null`）**或** `result.pass === false`；只按 `pass === false` 会把纯截图场景误判成失败。
- 已知盲点：`chat-ctx-empty-tools` 的 payload 只有 `{ok, reason, detail}`、没有 `pass`，按上述任何口径都判不了它失败（待修）。
- `AURORA_CAPTURE` 的 userData **自动隔离**（单独使用也隔离，探针会改配置）。

### 夹具

- 口径变了**必须同改夹具**（例：项目根改按会话解析后，夹具仍只设全局 current → 恒红）；修夹具跟上新口径，别去「修」边界判定。
- 判据：连续多轮失败项**逐字相同**（不是抖动）+ 详情出现「按设计」的拒绝文案 → 先怀疑夹具过期，再怀疑实现。
- 负对照必须真能失败：加判据先问「调用失败时这条会不会也成立」，会成立就先断言调用成功。
- 累计阈值第一次红不要改实现：先隔离重跑该场景（回绿即环境噪声）；真要调，按「夹具规模变了必须重新标定」连夹具一起调。
- 断言别写死会被「正常工作」改变的数值：改成 `>=`，或用与改动前实测值比较。
- 桩判断「第几轮」看**最后一条 user 消息之后**有没有工具结果（`hasToolResultSinceLastUser`），不是看整段历史。
- 夹具要覆盖「字段缺一半」的分支：给桩加专用分流造现场（`SKILL_ONLY_MARKER` 就是为「有工具调用、无思考增量」那一轮加的）。
- capture / smoke 夹具改配置**只能走 `settings:update` IPC**；种会话文件必须赶在第一次 `chat:history` 之前。
- 基线不是绿的，说明断言或夹具过期了：**先把基线修绿再动被测代码**。

### 预算

- 迭代期**只跑定向**：`AURORA_CAPTURE_ONLY`（**子串**匹配，`'chat.png'` 连带命中 `theme-chat.png`；特殊值 `failed` = 只重跑上次没过的，上次全绿则一张不跑、退出码 0）。
- 用 `AURORA_CAPTURE_WINDOWS` 切窗口组；筛选跑缺前置场景会产生假 FAIL，看到红先问「是不是筛选跑的」。
- **每轮必须独立输出目录**（同目录会覆盖上一轮 `report.json`）。
- **全量截图只在代码冻结后的验收阶段跑**；迭代期不用全量「看一眼」。`pnpm test` 同理：迭代期跑相关子集，全量放最后。
- 验收口径本身不降级；「截了没有」只看日志 count 与 `report.json`，**退出码 0 不等于截到了**。
- 全量跑期间不要改源码（`electron-vite dev --watch` 会在编辑中途重建 → 假红 / 挂死）。
- 聚焦冒烟用 `AURORA_SMOKE_ONLY`（段级分片）；跨进程续跑用 `AURORA_SMOKE_PHASE='resume'` + `AURORA_SMOKE_WORKSPACE=<同一目录>`；提交前仍必须跑全量。

### 抖动四条根因（同一份代码、失败组合每轮不同）

1. `chat-sidebar`：渲染层启动期永久丢 `mode:changed`（旧接线先 `await Promise.all([settings.load(), modes.load()])` 再 `bind()`，且 `mode.set` 在主进程已是目标值时不 emit）。修法：先订阅再加载 + 各 store 的 `loadGate`（`stores.ts:41`）保证晚到的首读应答不盖掉更晚的广播；哨兵 `CHAT_SIDEBAR_SCRIPT` 断言「面板卡片推出的模式 === `mode.list()`」。
2. `chat-archive`：身份键取了会漂移的文本（`.nav-item` 含 `.item-time` 相对时间）。修法：换成 `data-session-id`（`SessionRow.vue:63`）；act 有界轮询等 toggle，就绪状态写 `window.__auroraArchiveProbe`（`capture.ts:8573`），check 读到 `ready !== true` 时显式 FAIL。
3. `chat.png`：插入填充块后只 `await wait(150)` 就一次性读数，而吸底是观察者 + 一帧对齐才落位。修法：有界轮询（50ms 步进、上限 1000ms）等真实结果，`pass` 判据不变、附 `timedOut`；**有界**是关键（吸底真坏时它永远不会跟上，探针不派发输入事件不会自愈）。
4. `chat-stream-burst`：绝对最大值判据对单点离群敏感。修法：**离群容忍 + 灾难闸门**——主判据 `secondMax*`（110 / 160）+ 闸门 200 / 260（`capture.ts:6684`）；同一轴上别保留旧的最大值主判据，否则新闸门是死代码。
- **隐藏窗口里没有 rAF**：Chromium 在隐藏页面不派发 rAF → promise 永不 settle → 整轮 capture 挂死、`report.json` 一张不写。等帧一律 `Promise.race(帧, 120ms)` + `document.hidden` 走定时器；恢复可见 / 获得焦点时 `restartGuard()`，并先取消在途句柄再重排。
- **反向复核要人为制造缺陷**（确定性注入陈旧 store、旧身份键、关掉吸底、每帧插 130ms），不要等小概率自己复现；注入必须落在被测链路上。
- 等待固定毫秒不是保证，等真实结果才是：把「等一会儿」改成「等到那个事实成立为止」，并给上限 + 超时如实回报。
