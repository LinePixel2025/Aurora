# capture 探针的编写与判据口径

## 现象

1. **探针正文是 template literal 字符串**（`apps/desktop/src/main/capture.ts`）：
   - 字符串**内部**的注释写反引号字符会提前终止模板字符串，直接 `TS1005`，且报错位置极具误导性
     （后半截被当成代码解析）。
   - **反斜杠也要多写一层**：探针里本意是 JS 的 `/\s+/`、`/^\+/`，文件里少了那一层，模板层会把
     `\+` 吃成 `+`，渲染层收到**非法正则 `/^+/`**。这类错**不报在解析期**（`tsc` 与
     `capture.probe-strings.test.ts` 的第二条都看不见，TS 不校验正则 pattern），只在 V8 编译那段脚本时
     炸成报告里一句无信息量的 `Script failed to execute`（曾为此白跑两轮截图）。
2. **字符串里的语法错绕过 `tsc` 与 `pnpm test`**：`SETTINGS_FIELDS_SCRIPT` 里删白名单时留下一行
   **多余的 `)`**，只在 `AURORA_CAPTURE` 跑到那张图时变成 `Script failed to execute` —— 它已经在
   两次全量截图的报告里红着（2026-09-30 21:06 / 22:00 可查），没人看见。
3. **探针之间会互相污染**：`chat-follow-burst` 长时间 FAIL，根因是它前面那条 `CHAT_AUTO_SCROLL_SCRIPT`
   把跟随关掉后没恢复。
4. **同一段语义的判据写了两份**：`pass` 与 `conditions` 表漂移过一次 —— 报告里每条都 `true`、探针恒定 FAIL。
5. **量到的是解析值而不是事实**：`border-left-color` 在"没有左边框"时解析成 `currentColor`；
   展开动画中途的 `border-width` 是 `0.666667px`。
6. **筛选跑会产生假 FAIL**（2026-10-01 实测）：`chat-model-picker` 的 CHECK 依赖排在它**之前**的场景
   先把 provider 造出来，只跑 `settings-llm,model` 时它恒报 `restored:null`。
7. **空 `AURORA_CAPTURE` 曾被解析成空列表** = 一张不截、退出码 0（已修，但判据仍不能靠退出码）。
8. **探针替应用做决定**：`CHAT_TRACE_ACT` 会自己先把轨迹收成折叠态再量几何 —— 它测的是
   "折叠态长什么样"，所以状态机坏了它照样 PASS。
9. **别用全量 capture 当探针**：一轮 3–5 分钟且必须串行重建。"跟丢"那一轮最贵的一次绕路，就是用
   20 多轮全量截图去问一个用 20 行临时 HTML 就能回答的问题。
10. **绿灯会骗人**：`pnpm typecheck` / `pnpm test` / 大多数探针一路是绿的，行为却可以是坏的。

## 原因

- 探针正文以**字符串**形式存在，不经过 `tsc` 的语法校验，只有 V8 真正编译它时才暴露，而报错信息会丢失上下文。
- 所有场景共用同一个渲染进程与页面，前一条场景不恢复自己的状态，后一条就在别人的残局上跑。
- "存在性"（DOM 里有没有）与"可用性"（矩形在不在可视区、状态机对不对）是两回事，只查存在性的判据必然全绿。

## 影响

不按这套口径写探针，会得到两类最贵的假信号：**红着没人看见**（报告里 FAIL 被当成噪声）与
**绿着其实没测**（探针自己把要测的状态摆好，bug 永远不会被它发现）。两者都会让人在错误的前提上改代码、白跑几轮截图。

## 结论与做法

- 排查阶段先用**最小复现**（一个临时 HTML + 同一段 JS，几秒一轮）把"浏览器到底会不会那样表现"钉死，
  再回仓库改实现。
- 探针字符串里**不写反引号**（注释用「」或单引号）；能不用带反斜杠的正则就别用，非用不可时数清层数。
- **每条场景自带前置与收尾**，用应用自己的入口按钮恢复状态，不依赖别人的自律。
- 同一段语义的判据**只写一份**：让 `pass` 直接取 `conditions` 那张表的乘积。
- **量事实，别量解析值**：判断"有没有这条边"取宽度而不是颜色，并且必须在**正确的时机**量
  （折叠态、点击之前）。
- **一次性把仪器插全**（引擎自己的读数 vs 探针 `querySelector` 的读数、计数器、节点身份标记）再跑，
  不要每轮只加一个数字。
- 要测状态机，就写一条**完全不碰状态、只读应用自己留下的结果**的探针（现例 `CHAT_TRACE_FOLD_CHECK`）。
- **筛选跑出的 FAIL 先问"是不是筛选跑的"**，再用全量复跑确认，别直接去改代码；
  「截了没有」只看日志里的 count 与 `report.json`，退出码 0 不等于截到了。
- 护栏在 `apps/desktop/src/main/capture.probe-strings.test.ts`：第二条把「静态开头是 `(`」的
  template literal 还原成源码（`${}` 换成占位符）再交给 TS 解析器；第三条把模板层 cook 过的文本交给
  `new Function` 编译，能带行号指出非法正则。**加了新护栏不等于旧探针安全**：每次改探针都要自查。
- **场景构成以 `report.json` 的实际条目为准，别按固定张数校验**：四个窗口 + 提示条两态 + 设置页各页
  （含六页新门控与旧深链别名 `settings-legacy-tts-alias`）+ BetaV2 主界面三栏
  （左栏门控 / 右栏开关与 Work / 思考块 / 快速会话）+ 各条 DOM 探针场景
  （面板 / 收起 / 自动滚底 / 门控 / 拖动 / 思考等级 / 模型列表与模型选择 / 真实写盘 / 提示条收尾图）。
- 只截部分窗口用 `AURORA_CAPTURE_WINDOWS='edge-bar,chat'`，再细一级用
  `AURORA_CAPTURE_ONLY='<PNG 文件名子串>'`（逗号分隔，特殊值 `failed` = 只重跑上次 `report.json` 里没过的那几张，
  上次全绿则一张不跑、退出码仍为 0）。命令结束后进程自行退出；userData **自动隔离**（探针会改配置），
  无需再手动同开 `AURORA_SMOKE=1`。规则见 docs/07 §5.3。
