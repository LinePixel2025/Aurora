## Center 换装要点（0.5.0 → 0.5.1）

- **SSH 必须带专用密钥**：`ssh -i ~/.ssh/lineweb_aliyun root@<IP>`；默认密钥是 `Permission denied (publickey)`，不是服务器没开。
- 流程照 `packages/center/deploy/README.md` §1/§2（**`dist-web` 必须新鲜**，镜像只 COPY 它）：`shared build` → `center build` → `pnpm deploy --legacy` → 删 src/web/verify/deploy/tsconfig/vite → 带 Dockerfile + compose → tar → scp → 解压 → `docker compose up -d --build`。
- **`.env` 不在部署包里，解压不会覆盖它**：`AURORA_CENTER_SECRET` 保持原值，旧密文可继续解密；备份清单必须含 `.env`。
- `docker compose config` 会把 `AURORA_CENTER_SECRET` 打印成明文 —— 排障时别把这条输出贴进日志 / 记忆。
- 换装后核验：容器 healthy、`/` 200、`/api/updates/current` 正确、`/p/<id>/<version>/<path>` 200 且带 CSP。
- 市场列表路由是 **`GET /api/plugins`**（详情 `/api/plugins/:id`、下载 `/api/plugins/:id/download`），没有 `/api/plugins/marketplace` 这条（写错 404 `E_NOT_FOUND`）；同版本不可覆盖，重发先 unpublish。

## 本次发布链路上的卡点

1. **打包前必须停 dev 客户端**：`electron-vite dev --watch` 占 `out/`，与 `electron-builder` 读 `out/` 竞争；`taskkill /T`（不带 `/F`）杀不干净，需 `/F` 并确认没有自动重启的 dev。
2. **`--publish-center` 需要 `AURORA_CENTER_PASSWORD`**（账号 `admin`）；脚本一次登录成功，未触发 5 次 / 60 秒登录限速。凭据失败时最多试 1 次，然后问用户要。
3. 双投命令拆两步：`--publish`（构建 + 打包 + verify + tag + GitHub）→ `--skip-package --publish-center`（不重复打包、跳过已有 tag）。

## 插件适配口径（用户问「是否需要通知插件修改」）

- 仓库与市场里**没有名为「通知插件」的插件**；已装的是 `com.classmanagement.board`（2.2.0）与 `com.meterlab.tokenlens`（0.1.1）。
- **声明式面板**：只要清单有 `contributes.panels` 且设备在线 + 总闸开，Center 自动出现，**零改动**。
- **页面型面板**：页面必须从**本 Center 市场 zip** 取资源；`window.auroraPlugin.request/onEvent` 与桌面 preload 同名同形，**插件代码不用改**，但**同版本必须已发布到该 Center 市场**，否则提示「该版本未发布到本 Center」。当前市场只有 class board 2.2.0 与 hello 1.0.0，Token Lens 0.1.1 **未发布** → 它在 Center 里不会有入口。
- **通知能力（`notifications` 权限 / `ctx.notify` / `ctx.banner`）与镜像无关**：Center 只镜像侧栏面板，小组件与提醒永远不上网；插件不需要为了 Center 改通知相关代码。
