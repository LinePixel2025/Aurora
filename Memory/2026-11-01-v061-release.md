## 原因 / 本轮踩到的一个点

- **Center 更新源的资产下载路径是 `/api/updates/<文件名>`，不是猜的 `/api/updates/download/…`**：
  探测安装包 Range 时按后者发请求，落到未知路径兜底进了登录门禁，回 401 —— 差点误判
  「安装包下载坏了」。`server.ts` 的公开更新源路由（docs/09 §10）共三条：
  `/api/updates/current`（**JSON 视图** `{current:{version,files:[{name,size,sha512,…}]}}`，
  不是 electron-updater 的原始 yml）、`/api/updates/latest.yml`（**原始 yml**，与本地产物
  逐字节可比）、`/api/updates/<文件名>`（资产，支持 Range）。

## 影响

- 三源一致性核验若拿 `/api/updates/current` 的响应体哈希去和本地 `latest.yml` 比，
  **必然不等**（它是 Center 自己的 JSON 包装）—— 正确判据：`current.version` /
  `files[].size` / `files[].sha512` 与本地 yml 字段一致，**或**直接拉
  `/api/updates/latest.yml` 做逐字节哈希。
- Range 206 探测要用真实资产路径，401 时先怀疑「路径不对落进门禁」，别急着下结论
  「下载功能坏了」。

## 结论与做法

- 三源核验固定三步：① 三份 `latest.yml` 哈希（本地 / Center `/api/updates/latest.yml` /
  GitHub `releases/download/<tag>/latest.yml`）；② Center `/api/updates/current` 的
  version / size / sha512 字段比对；③ Center 安装包
  `curl -H "Range: bytes=0-0" http://<host>/api/updates/Aurora-Setup-<版本>.exe` → 206 +
  `content-range: bytes 0-0/<size>`。
- GitHub Release 正文校验：`curl.exe -s api.github.com/repos/LinePixel2025/Aurora/releases/tags/<tag>`
  落盘后取 `body` 与 `docs/release-notes/vX.md` 归一化（`\r\n → \n` + trim）比较。
- 管理员密码只当次使用（`AURORA_CENTER_PASSWORD` 环境变量传入 `--publish-center`），
  不落盘、不进 Memory、不进命令历史以外的任何文件；上传走直连 IP
  `http://120.24.223.65:8787`（Cloudflare 免费档有 100MB 请求体上限，203MB 走隧道会 413）。
- 发布前全量验收口径照旧不降级；Center 两个临时目录用例（`model-gateway.e2e` /
  `usage`）在满负载下会偶发 `ENOTEMPTY` / `EPERM`，单独复跑通过 + 全量复跑全绿即可判环境竞态。
