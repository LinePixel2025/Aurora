# 界面文案 / 输入卡 / scoped 样式

## 现象

1. **文案「冗杂」被用户连续两轮点名**（2026-09-29）。
2. **`-webkit-line-clamp` 挂在 `<td>` 上导致整表横向溢出**（2026-10-03 实测）：
   单元格参与表格布局，挂上去会脱离 `display` 语义。
3. **输入卡被顶成一条设置工具栏**：权限 / 模型 / 思考三枚控件做成 40px + 逐枚边框。
4. **占位文案换行后第二行看不见**：textarea 的高度由内容决定（空内容 = 一行）。
5. **Vue scoped 样式外泄到子组件根节点**（2026-10-02 实测）：父组件的 `data-v-*` 会加到子组件**根元素**上，
   父子**同名类**互相污染 —— 实测把父级「离屏抽屉」的定位套到了子组件上，面板直接跑到屏幕外。

## 原因

- scoped 只隔离"选择器作用域"，不隔离"属性被加到哪个元素"；父组件给子组件根节点注入的 `data-v-*`
  让父级规则同样命中子组件根元素。
- 表格单元格的 `display` 语义被截断类改写后，表格布局的宽度计算失去约束。
- 样式越"厚"越像设置面板，越不像对话输入区。

## 影响

- 文案冗长会让用户反复提同一件事；删过头又会丢掉边界 / 后果 / 修复路径，导致用户误操作。
- 样式外泄的症状（面板跑到屏幕外）看着像定位逻辑坏了，实际是父级同名类命中；且**过渡中途量到的是中间态**。

## 结论与做法

- **文案口径**：区组说明段 **≤45 汉字**、字段 hint **≤40 汉字**，各只写 1 句；
  **不写 `docs/xx §n` 这类文档引用**；删的是冗余，**边界 / 后果 / 修复路径必须保留**。
  改文案后要同步核对探针里断言了原文串的场景（如 `chat-composer-slash`）。
- 截断类 `.clamp-2` **不要挂在 `<td>` 上**：挂**内层** `<span>` / `<p>`（现例 `SkillsSection.vue`）。
- **输入卡两条硬口径**（2026-09-29 减负轮，docs/07 §2.3）：① 权限 / 模型 / 思考三枚控件一律
  `--control-h-xs`（28px）+ pill 圆角 + **静止态零边框**（悬停才浮 `--fill-2`），三者尺寸与状态样式
  **逐字对齐**；② 占位文案只留一句（`输入消息…`），键位提示挂工具行右侧的 `.composer-hint`。
- 给子组件写样式要么用**独占类名**、要么用 `:deep()` 明确穿透，**不要**指望 scope 隔掉同名类；
  这类问题要在**正确的时机**取读数（过渡中途量到的是中间态）。
- 终端底色是固定黑（2026-10-03 用户口径）：`TerminalPanel` 里就一份 `XTERM_THEME`
  （`background: '#000000'`）与 `.tp-host { background: #000 }`，**不要再按 `prefers-color-scheme` 分两档**
  （浅色系统下白底黑字正是被用户点名的问题）；`.xterm` 元素本身透明（xterm 把主题背景画进 canvas），
  判据取容器 + `.xterm-viewport`。
