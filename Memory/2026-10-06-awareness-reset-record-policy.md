# 自感知重置与分析记录口径

## 现象

- 旧设置页只有“清空历史”，用户想重建整套记忆时没有安全入口。
- 文件监听事件会先写 `observed` / `queued` / `analyzing`，没有内容变化也会留下多条记录。
- 设置按钮悬停时会位移；指针停在边缘时按钮可能在光标下进出，产生误悬停 / 误按观感。
- 鼠标点击按钮后焦点会留在按钮上，之后按 Enter / Space 可能再次触发上一次操作。

## 原因

- “清空历史”只清运行记录，不会删除笔记、队列、用量、版本备份或隐藏的 `awareness-*` 会话。
- 分析记录把过程状态和终态写进同一列表，缺少“只有实际内容版本变化才记一条”的过滤器。
- `.interactive:hover` 对按钮执行 `translateY(-1px)`，命中区域会随悬停状态移动。
- 原生按钮保留鼠标点击后的焦点；键盘激活语义因此可能落到用户已经不关注的按钮上。

## 影响

- 重置范围不清会误删用户文件，或留下隐藏会话 / 旧用量，看起来“没有真正重置”。
- 未变化记录持续堆积会掩盖真正需要关注的文件变化。
- 按钮位移和残留焦点会让用户觉得没有点到却触发了操作，破坏设置页可信度。

## 结论与做法

- 自感知重置只删除 Aurora 管理的笔记、`INDEX.md` 条目、队列 / 记录 / 最近使用 / 建议 / 用量 /
  版本备份与 `awareness-*` 会话；保留配置、源文件和知识库目录中的无关文件。
- 重置完成后恢复监听但**不自动扫描**，避免意外 Token 消耗；旧状态加载时丢弃过程记录。
- 分析记录只写内容变化后的 `done` / `error` / `conflict`，删除源文件写 `skipped(delete)`；
  `observed` / `queued` / `analyzing` 和“内容未变化”不写记录，进度只走运行状态。
- 设置窗按钮悬停不位移、只换色；`AppButton` 在鼠标点击后释放焦点，键盘激活仍保留正常焦点。
