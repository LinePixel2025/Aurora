# 隐私说明

本页说明 Aurora 在你这台电脑上**存了什么、存在哪、什么时候会联网**。
设计原则一句话：**数据不出本机，除非是你自己配置的服务。**

## 1. 一句话总结

- Aurora **没有**自己的服务器，**没有**账号体系，**没有**遥测 / 埋点 / 崩溃上报。
- 你的文件、会话、分类记录、配置全部存在本机用户数据目录里。
- 只有这几种情况会联网：调用**你自己配置**的 AI 模型、连接**你自己配置**的 MCP 服务器、
  把回复交给**你自己配置**的 TTS 服务朗读、检查更新（只访问公开的 Releases 仓库）、
  读取**你自己配置**的 ClassIsland 桥接端点；
  你确认放行的命令自己发起的网络请求不在此列，也不经 Aurora 转发（见 §4）。
- 凭据（API Key / MCP 环境变量）用 Windows 自带的加密能力加密后落盘，永不写成明文。

## 2. 数据存在哪

全部在 `%APPDATA%\Aurora\`（即 `C:\Users\<你>\AppData\Roaming\Aurora\`）：

| 文件 / 目录 | 内容 | 你能做什么 |
|---|---|---|
| `config.json` | 全部设置（科目列表、课表、代理、MCP 服务器、窗口位置…）。**凭据字段是密文** | 可读可改；「设置 → 高级 → 导出脱敏配置」会生成一份把凭据替换为 `***` 的副本 |
| `sessions\*.json` | 对话历史（你说的话与模型的回复、工具调用记录） | 可在对话窗查看 / 清空；直接删文件也可以 |
| `classification.json` | 分类流水（最近 500 条：文件名、判定科目、依据、是否修正） | 设置页可清空 |
| `file-awareness\` | 文件自感知索引、持久队列、最近使用记录、运行历史、忽略记录与笔记版本 | 设置页可清空历史或完整重置；重置会同时删除隐藏的 `awareness-*` 后台会话 |
| 知识库 `INDEX.md` + `<格式>\<首次感知日期>\` | 根索引汇总笔记标题、来源、标签与摘要；每个源文件一份 Markdown 笔记 | 可直接阅读、备份或整体移动；源文件消失时对应笔记、索引项与版本备份会同步删除，重新配置知识库后旧笔记会自动迁移 |
| `logs\aurora-YYYY-MM-DD.log` | 运行日志，**已脱敏**，按天轮转保留 7 天 | 设置页可打开目录 |
| `skills\` | 你的自定义 Skill（`SKILL.md`） | 完全由你控制 |

**卸载**：Aurora 的卸载程序不会主动删除这个目录（避免误删你的对话记录）。
想彻底清干净，卸载后手动删掉 `%APPDATA%\Aurora\` 即可。

## 3. 凭据如何保护

- AI 模型的 API Key 与 MCP 服务器的环境变量（可能含 token）经 Electron `safeStorage`
  加密后，以**密文**（形如 `v10:…` 的 base64）写入 `config.json`。
- 解密只发生在**运行时内存**里，且只在即将发起请求时进行。
- 设置界面的「只读显示」与 `settings:get` / `settings:changed` 两条 IPC 通道
  **只回传「是否已设置」这个布尔值**，密文本身不会进入界面进程。
- 若系统的加密能力不可用（极少数企业机器会禁用），Aurora **不会退化成明文**，
  而是让凭据只驻留内存 —— 重启后需要重新填写。启动日志里会有明确告警。
- 日志、错误信息与「导出脱敏配置」中的凭据一律替换为 `***`。

## 4. 什么情况下会联网

Aurora 的所有出网请求都源自**你的配置**，没有硬编码的服务地址（更新源除外，见下）：

| 场景 | 目标 | 发送的内容 |
|---|---|---|
| AI 对话 / 分类判定 / 上下文摘要 | 你在「设置 → AI 模型」里填写的 `baseURL` | 你的提问、会话历史、被归类文件提取出的文字；**开了图片输入时还包括你拖入的图片本身**（见下） |
| 文件自感知分析 | 你在设置中跟随的主模型，或显式选择的后台模型 | 仅在显式同意后，发送你选定目录内受支持图片 / 文档的元数据、截断到 24KB 的结构化正文证据、图片内容（所选模型开启视觉输入时）和相关笔记摘要；显式后台模型不可用时暂停，不暗换主模型 |
| 「测试连接」 | 同上 | 一次最小请求，用于验证地址与 Key |
| MCP 工具调用 | 你在「设置 → MCP」里配置的服务器 | 模型决定的工具参数 |
| 朗读（TTS） | 你在「设置 → 语音」里填写的 TTS `baseUrl` | **被朗读的那条助手回复文本**（截断到 `tts.maxChars`），不含会话历史、不含文件内容 |
| 检查更新 | 公开的 Releases 仓库（打包时内置） | 只读取版本信息，**不发送任何本地数据**；客户端不带任何凭证 |
| ClassIsland 桥接 | 你填写的本地文件 / `127.0.0.1` 端点 | 只读，不发送任何内容 |

**TTS 的边界**：**开启朗读后，被朗读的回复文本会发送到用户配置的 TTS 服务**（朗读是用户主动触发的行为，
或由 `tts.autoRead = true` 在回复结束后触发）。**未配置或未朗读时不出网**：
`tts.enabled = false`、`tts.active` 为空、或这次回复没有被朗读（没点按钮且未开自动朗读），
都不会有任何 TTS 请求发出。音频是即时播放的产物，**不落盘**，会话历史里仍然只有文本（见 06 §13）。

**命令自己的联网不算 Aurora 的出网**：你在确认卡片里放行的 `git clone`、`pip install`
这类命令可能自己访问网络，请求由那条命令发出，**不走 Aurora 的代理设置，也不经 Aurora 转发**
（Aurora 只是启动它并采集输出，见 §6）。

**图片输入的边界**：**只在你在「设置 → AI 模型 → 高级参数」里为该 provider 打开
「支持图片输入」后，图片才会随消息发出去**。默认是**关**的：关着时拖入的图片不会出网，
只会以一行「内容未读取（当前模型未开启图片输入）」进入上下文（模型看不到图）。
开启后，拖入的图片会以 base64 形式随请求发送到该 provider 的 `baseURL`，并且在**同一会话的后续
轮次里会被重新发送**（会话历史只存**本地路径**，每次组装上下文时按路径重读，因此文件内容
始终以本机为准）；请求里恒定带 `store: false`（不要求服务端留存会话）。
想收回这个能力，把开关关掉即可 —— 之后的新请求里不再出现图片。
本地预览用的缩略图（附件 chip 上那张小图）走 `chat:readAttachment`，**只在本机读盘、不出网**。

**请注意**：当你把资料交给云端模型时，文件内容会离开本机——这是使用云端 AI 的固有含义，
不是 Aurora 额外的行为。想避免出网，可以：

- 使用本地模型（「AI 模型」预设里的「本地 / 自定义」，指向 Ollama / vLLM 等本地服务）；
- 或在「设置 → 模式 → ClassRoom → 分类行为」里关掉自动分类，只手动与模型对话。

代理设置只改变请求的**转发路径**，不会改变上面的数据流向。

## 5. 日志与导出

- 日志写入 `%APPDATA%\Aurora\logs\`，按天一个文件，保留 7 天，超期自动清理。
- 写入前统一脱敏：字段名匹配 `apiKey` / `token` / `authorization` / `secret` /
  `password` / `credential` / `envEnc` 的，值一律替换成 `***`。
- 日志只记**元数据**（文件名、时长、错误码、状态），不记录文件正文与对话正文。
- 「导出脱敏配置」生成的是完整配置的副本，凭据位置为 `***`，可安全分享给他人排障。

## 6. 权限与系统能力

Aurora 是桌面应用，不需要管理员权限。它会用到：

| 能力 | 用途 | 能否关闭 |
|---|---|---|
| 读写你指定的「智慧感知文件夹」 | 文件分类 | 不配置该文件夹即不启用 |
| 全局快捷键注册 | 唤出 AI 交互窗 | 可在设置里改绑；占用失败不影响其他功能 |
| 系统通知 | 分类完成、课前提醒 | 由 Windows 通知设置控制 |
| 读取前台窗口标题与应用名 | 让模型知道你在用什么程序 | 「系统感知」的一部分，采集失败会降级为「未采集」，不阻塞 |
| 读取电源 / 网络状态 | 同上 | 同上 |
| 监听你选择的目录并读取 Windows 最近使用记录 | 文件自感知 | 不开启功能、不同意正文出网、或移除目录即停止；目录外最近文件只记录路径 |
| 开机自启 | 常驻托盘 | 设置页可关，默认关闭 |
| 打开资源管理器窗口 | 课前打开科目文件夹、点通知打开目录 | 关掉课前提醒即不触发 |
| 执行你确认过的 PowerShell 命令 | 让 AI 帮你跑命令 | 设置 → 电脑操控的总开关 / 终端开关，关掉即不注册该工具 |
| 读 / 写**模型指定**路径的文本文件 | 让 AI 帮你读 / 写文本文件 | 设置 → 电脑操控的总开关 / 文件开关；读取**不需要**逐次确认 |
| **精确替换**文本文件里的片段 | 让 AI 改代码 / 改配置里的几行，不必整篇重写 | 同上（`edit_file` 与 `write_file` 共用文件开关）；**每一次都弹确认卡片** |
| 按文件名匹配 / 按正则搜索**模型指定**目录的文件 | 让 AI 自己找文件、找代码位置 | 设置 → 电脑操控的总开关 / 「文件检索」开关；只读、**不弹确认**，但会递归扫描整个搜索根 |
| 用默认程序打开文件或网址 | 打开模型给出的文件、文件夹、网址或程序 | 设置 → 电脑操控的总开关 / 打开开关 |

这些能力属于「电脑操控工具」（见 [用户手册 §9](./10-user-guide.md#9-让-ai-帮你操作电脑)）：
命令以**你当前的用户身份**执行（**不是**管理员），能力与你自己在 PowerShell 里敲同样的命令**相当**
（略宽：以 `-NoProfile -NonInteractive -ExecutionPolicy Bypass` 启动，比默认执行策略宽松）；
跑命令 / 写文件 / 精确替换 / 打开路径**每一次**都会先弹确认卡片（展示参数原文，**超长会截断并标注**），
**60 秒不响应或处于勿扰时段一律按拒绝处理**，不会静默执行。

**`edit_file` 没有备份、也没有撤销**：它把改动直接写进原文件（原子写只保证「写盘过程不会写坏」，
**不保证改动内容可回滚**）。改错了只能靠你自己的版本控制 / 备份 / 编辑器历史恢复 ——
想改代码的话，先把项目放进 git 是最省事的保险。

**Agent 改文件会在本机留副本（v14 起）**：`write_file` / `edit_file` 在真正写盘**之前**，
会把文件的**原内容**存一份到 `%APPDATA%/Aurora/backups/<会话 id>/`（每条快照一个 `.snap`
内容文件 + 一份 `index.json` 索引）。这些副本**只落在本机**，不会出网；
默认每个文件最多留 20 份、单份不超过 512 KiB、整个目录不超过 200 MiB（设置 → 智能与工具 →
「文件备份」可调；关掉开关后写文件不再留底，改动将不可回滚）。
它们记录的是**文件被 Agent 改写前的原文**，因此同样可能包含敏感内容 ——
要清理可以在资源管理器里直接删 `backups` 目录，或在该页点「立即清理」。
回滚（右栏「文件备份」卡）会把文件恢复到某一份快照，**回滚本身也会先留一份快照**，
所以回滚同样可以再撤回。

**免确认命令模式（`agent.tools.terminal.allowPatterns`）只影响「弹不弹卡片」，不改任何出网行为**：
它是设置页里一份**只存在本机**的命令模式白名单（写在 `config.json` 里，见 §2），
不会改变 §4 的数据流向，也不会被发送给任何服务；命中的命令仍由你本机的 PowerShell 执行。
命中只跳过确认卡片（**仍写本地审计日志**），**不是权限放宽**——能力与你自己在 PowerShell 里
敲同一条命令完全一样，列表为空时行为与从前一致。这份列表只能由你在设置页维护，
AI 的「改自己的设置」碰不到它（详见 06 §11.7）。

**读取与检索都是免确认的，且内容会出网**：`read_file` / `list_dir` / `grep` / `glob` 标记为安全级、不弹卡片；
读到的文本会作为工具结果**发送给模型**（与你自己粘贴文本给它相同），并写入本地会话文件
（`%APPDATA%/Aurora/sessions/*.json`）。工具**不限制**读取范围，路径由模型决定，
所以不要让它去读你不希望外传的文件（私钥、`.env`、`.git-credentials` 等）。
**v13 起多了两处差异，值得知道**：
① **登记了项目**时，文件类工具与 `run_command` 的 `cwd` 都要过项目根的 realpath 前缀校验 ——
读 / 写项目根以外的路径会被**直接拒绝**（写类工具在确认卡片上放行后可以越界，读类工具不行）；
项目根边界不改变任何出网行为，只改"能不能碰本机文件"。
② **只读档下**，读取与检索照常，但写文件 / 执行命令 / 打开路径 / 写待办这几类工具**根本不注册**，
因此这一段里关于"写入会改本机文件"的披露在只读档下不适用。

**不做的事**：不录屏、不读键盘输入、**不模拟鼠标 / 键盘**、**不读取其它进程的内存**、
不访问通讯录 / 相机 / 麦克风、不修改系统设置、不以管理员身份运行、不安装驱动或服务。

MCP 服务器以你显式配置的**参数数组**启动，**绝不经过 shell** ——
因此配置里的参数不会被解释成 shell 命令。
Skill 目录下的 `scripts/` **永远不会被自动执行**（技能只提供指令文本）。

## 6a. Aurora Center（远程控制）的数据与边界

- **桌面端只保存**：Center 地址、配对令牌（safeStorage 密文，同 API Key 链路）、
  本机 clientId。不缓存远程会话内容（会话历史本来就落在本地会话存储里，与普通会话一致）。
- **Center 服务器保存**：用户账户（scrypt 口令哈希）、配对令牌哈希（明文只显示一次）、
  客户端登记表、经 `center_send_file` 上传的文件副本。**远程会话内容只转发、不落盘**。
- **明文可见性**：Center 可以看到全部远程会话明文（转发路径上的服务器天然可见）——
  这是"管理员可见所有客户端"产品语义的一部分；敏感环境请把 Center 部署在自己控制的内网。
- **出站方向**：桌面端 → Center 是**客户端发起的出站 WebSocket**，不开放任何入站端口；
  不启用 Center 时（默认）零出站、零行为变化。`center.*` 整组对 AI 的 `set_setting`
  只读 —— AI 不能自行启用或改向这个外发通道。

## 7. 你可以怎么核对

不信任说明文档是合理的。以下方式可以自行验证：

1. **看配置文件**：打开 `%APPDATA%\Aurora\config.json`，确认凭据字段是
   不可读的密文而不是你的 API Key。
2. **看网络**：用任何抓包 / 防火墙工具观察 Aurora 的出网目标，
   应当只出现你自己填写的模型地址、MCP 地址与 Releases 仓库。
3. **看源码**：本项目源码可复核。所有出网请求集中在
   `packages/agent-core/src/llm/` 与 `packages/agent-core/src/mcp/`；
   代理与网络栈接线在 `apps/desktop/src/main/net.ts`；
   脱敏逻辑在 `packages/shared/src/config/store.ts` 的 `redactKeys`。
