## 1. 安装

从 [Releases](https://github.com/aurora-desktop/aurora-releases/releases) 下载
`Aurora-Setup-<版本>.exe` 并双击安装。

### 关于 SmartScreen 的提示

安装包目前**没有代码签名**，Windows 首次运行会显示蓝色的
「Windows 已保护你的电脑 / 未知发行者」。这是未签名程序的正常提示，不是病毒告警。

继续方式：点「更多信息」→「仍要运行」。

> 为什么不做签名：代码签名证书需要按年购买。Aurora 是本地工具，源码与产物都可复核
> （见 [隐私说明](./11-privacy.md)）。接入证书后这条提示会自动消失。

### 系统要求

- Windows 10 / 11（64 位）
- 无需单独安装 .NET 或 Node

## 2. 首次启动：引导五步

首次启动会弹出引导向导，五步完成基础配置：

1. **欢迎**：说明 Aurora 做什么（常驻托盘，随时可用）。
2. **AI 模型**（必填）：选择预设（DeepSeek / OpenAI / 本地），填 `baseURL`、
   **模型名**与 **API Key**。填完必须点「测试连接」——它会真的发一次请求，
   失败会告诉你具体原因（Key 错、地址不通、模型名不存在）。
3. **选择模式**：默认推荐 **ClassRoom**（学生场景，当前唯一完整实现）；
   Work / Code 目前是占位（见 [已知限制](../AGENTS.md)）。
4. **模式设置**：ClassRoom 会走四步对话式引导（感知文件夹 → 科目 → 科目文件夹 → 课前提醒）。
5. **完成**。

引导随时可以重跑：「设置 → 模式 → 重新引导」。

> **API Key 存在哪？** 用 Windows 自带的加密（Electron `safeStorage`）加密后写入
> `%APPDATA%\Aurora\config.json`，**不会**明文落盘；界面与导出里只显示「已设置」。
> 详见 [隐私说明](./11-privacy.md)。

## 3. 三个日常窗口（另有仅首次启动出现的引导窗）

| 窗口 | 怎么打开 | 用途 |
|---|---|---|
| **提示条** | 默认常驻在屏幕右缘；托盘菜单可显隐 | 8px 竖条（唯一常驻入口）；**悬停**展开面板看状态 / 模式 / 最近消息，**点击**呼出 AI 交互窗 |
| **AI 交互窗** | 点提示条；或托盘菜单 / 全局快捷键 | 完整对话：Markdown、流式回复、工具卡片、会话列表、分类流水 |
| **设置窗** | 托盘菜单「设置」 | 常规 / 模式 / AI 模型 / Skill / MCP / 电脑操控 / 高级 |

> 首次启动还会出现**引导窗**（欢迎 → AI 模型 → 模式选择 → 模式设置 → 完成），配好之后不再自动出现；
> 想重跑走「设置 → 模式 → 重新引导」。四个窗口的完整规格见 [UI 规格](./07-ui-spec.md)。

> 「AI 服务窗」（顶置输入框 / 小圆球）已在 v0.6.0 后的前端刷新中**删除**，常驻入口收敛为
> 「提示条 + 托盘」；旧配置里的服务窗几何由配置迁移 v4 自动清理。

**对话窗支持拖拽发送文件**：把 PDF / Word / 文本 / 图片拖进对话区，
Aurora 会提取其中的文字交给模型（单个文件最多取 8000 字，一次最多 5 个）。
扫描版图片的文字**不会**被识别（OCR 暂未启用），只会带上文件名与尺寸。

**多会话**：对话窗**左栏**是新对话按钮 + 会话列表（单行标题 + 相对时间）——
点一条即切换，点「新对话」新建。左栏顶部还有一个固定的「**快速对话**」项：
那是**提示条面板**那侧用的快速会话（与主界面的普通会话相互独立，数据同一份），
点它就切过去接着聊。左栏、右栏都能用头部 / 左栏底部的按钮折叠起来。
窗口标题栏右侧是 Windows 式按钮：「最小化」真最小化，「关闭」= **直接隐藏窗口**
（正在生成的回复在后台继续，再打开就能看到结果）。

**输入框**（对齐主流 Agent 桌面端的动线，自下而上是 输入区 → 工具行 → 上下文详解条）：

- **输入**：`Enter` 发送、`Shift + Enter` 换行；输入框会随内容自动长高（最多 200px，再多就内部滚动）。
  直接把文件拖进来即成为附件。
- **`/` 命令**：敲 `/` 会在输入框上方弹出候选，分两组：
  - **命令**（选中即执行）：`/new` 新对话、`/clear` 清空消息区、`/stop` 停止回复（回复中才有）、
    `/subagents` 子代理页面、`/settings` 打开设置；
  - **技能**（选中只补全）：你的全部技能，例如 `/system-status`——补全后接着写需求即可
    （`/system-status 现在几点`）。`@技能名` 也仍然认，但不再有补全提示。
  用 `↑` `↓` 选、`Enter` 或 `Tab` 确认、`Esc` 关掉。
- **权限模式**（工具行最左，盾牌图标）：两档 —— **变更前确认**（默认）＝ 写文件 / 执行命令 /
  MCP 工具 / 改设置执行前都会先弹确认卡，你点「允许一次」才执行；**完全权限**＝ 不再逐次询问，
  直接执行（仅写日志留痕）。切到完全权限要点**两下**（第二下才是确认），因为它等于把确认闸门
  一直敞开。这一项与「设置 → 智能与工具」里的同名开关是**同一个设置**。
- **上下文详解条**（输入框最底部）：显示这一轮真正送进模型的**上下文占用**
  （`已用 / 窗口` + 进度条 + 百分比）与本会话累计 token；点开看明细（输入 / 输出 / 累计 /
  窗口 / 消息条数 / 字符数 / 当前模型）。
  - 「窗口」来自「设置 → AI 模型 → 编辑 → 高级参数 → **上下文窗口**」——不填（= 0）时只显示
    用了多少 token，不显示比例（分母未知就不猜）；
  - 占用到 60% 变黄、85% 变红，看到变色就该考虑开新对话了；
  - 模型服务没返回用量时这里会如实写「暂无用量数据」，不会拿字符数估一个数糊上去。
- **语音输入**：配好 STT 后输入框右侧出现麦克风按钮（没配置就不显示这个按钮），
  点一下开始录音、再点一下停止并把识别结果追加进输入框。

**思考等级**：输入框旁边有个「思考」下拉（`auto` / `low` / `medium` / `high`），
改完**下一次提问**就按新等级走，不用进设置页、也不用重启。
它与「设置 → AI 模型 → 高级参数与连接测试」里的那一项是**同一个设置**，改哪边都一样。
`auto`（默认）表示不指定，兼容性最好。还没配置模型时这个下拉是灰的——
先在「设置 → AI 模型」里配一个并选中即可。

**切换模型**：输入框旁边还有个「模型」下拉，列出你在「设置 → AI 模型 → 编辑 → 模型列表」
里维护过的候选模型，选一个就换成它（同样**下一次提问**生效，不用重启）。
它与模型页的「当前使用」标记是**同一个值**：在模型页改，下拉跟着变；在下拉里改，模型页也同步。
候选列表本身在模型页维护——「拉取模型列表」把服务返回的模型并进列表，「+ 手动添加」自己填一个 id；
删掉正在用的那一项**不会**替你换模型，只会提示「当前模型已不在列表中」，改哪个由你决定。
当前模型不在列表里时，下拉会显示成「`<模型名>`（不在列表中）」，不会悄悄换成列表里的别的模型。
还没配置模型时，这个下拉和「思考」下拉一样是灰的。

## 4. ClassRoom：自动分类你的资料

设置好「智慧感知文件夹」后，**把文件拖进这个文件夹**，Aurora 会自动判断它属于哪个科目
并移动到对应科目文件夹，同时弹出通知（点通知可打开目标文件夹）。

判定顺序（越靠前越省钱、越快）：

1. **文件名规则**：文件名里含科目名，或命中你配置的关键词 → 直接归类，不调用模型。
2. **内容判定**：读取文件内容（PDF / Word / PPT / Excel / 文本）后交给模型判断科目。
3. **兜底**：置信度低于阈值或判断失败 → 进「待分类」文件夹并通知你确认，**不猜**。

**就地修正**：在 AI 交互窗的「分类流水」里，每条记录都能改成其他科目。修正后：

- 文件会被移到新科目文件夹；
- 这条修正会**沉淀成规则**，下次同类文件名直接命中规则，不再消耗模型调用。

**不移动文件**：如果只想要流水记录、不想让 Aurora 动你的文件，
在「设置 → 模式 → ClassRoom → 分类行为」里关掉「自动移动文件」。
此时文件会留在原地，Aurora 也不会重复处理同一个文件。

## 5. 课前自动打开科目文件夹

开启后，每节课**上课前 5 分钟**，Aurora 会：

1. 发一条系统通知（含科目与剩余分钟数）；
2. 自动打开该科目的文件夹，等你的资料就位。

课表有两种来源：

- **手动维护**（默认）：在「设置 → 模式 → ClassRoom → 课程表」里逐条添加
  （星期 × 开始 / 结束时间 → 科目）；
- **ClassIsland 联动**：见下一节。

勿扰时段（「设置 → 高级」）内不会提醒，也不会补发。

## 6. 接入 ClassIsland 课表

如果你用 [ClassIsland](https://classisland.tech/) 管理课表，可以让 Aurora 直接读它，
不必再手动维护一份。

**为什么要装一个桥接插件？** ClassIsland 是 .NET 应用，跨进程通信走命名管道，
且没有 HTTP API，Aurora 无法直接读取。桥接插件在 ClassIsland 内部把课表写成一份
本地 JSON，Aurora 只读这份文件（或它在 127.0.0.1 上开的只读端点）。

### 步骤

1. 构建并安装桥接插件：见
   [`integrations/classisland-bridge/README.md`](../integrations/classisland-bridge/README.md)
   （需要 .NET SDK 8.0+，用
   `dotnet build -c Release -p:ClassIslandDir="<ClassIsland 安装目录>"` 构建，
   然后把 `AuroraClassIslandBridge.dll` 与 `manifest.yml` 复制到 **ClassIsland 的插件目录**：

   ```
   <ClassIsland 安装目录>\data\Plugins\aurora-classisland-bridge\
   ```

   注意不是 `%APPDATA%\ClassIsland\...` —— 应用数据目录下的 `data\Plugins\` 才是插件位置
   （`<ClassIsland 安装目录>\data\Config\Plugins\<插件 id>\bridge.json` 是它的配置）。
   也可以直接用随仓库发布的插件包 `dist/AuroraClassIslandBridge-v3.0.zip`
   （压缩包根目录含 `manifest.yml` + 插件 dll）。
2. 重启 ClassIsland，确认插件被加载（「设置 → 插件」里能看到「Aurora 桥接 3.0.0.0」，
   日志里也有加载记录），并确认它写出了 JSON 文件
   （默认 `%APPDATA%\ClassIsland\aurora-bridge\schedule.json` 与同目录 `status.json`）。
3. 在 Aurora：「设置 → 模式 → ClassRoom → 课程表」
   - 「课程表来源」选 **ClassIsland 联动**
   - 「数据来源」选 **JSON 文件**（填上面那个文件路径）或 **本地 HTTP 端点**
     （填 `http://127.0.0.1:17945/schedule`）
4. 点「**测试连接**」。成功会显示今天有几节课；失败会给出具体原因。
5. 想让 Aurora（或它背后的 AI）**通过 ClassIsland 弹提醒**时：插件版本需为 **v3**，
   同一设置区里有「**发送测试提醒**」按钮 —— 点一下，ClassIsland 上应弹出提醒，
   按钮旁会显示结果；失败会给出原因（插件不是 v3 / 命令通道关闭 / 端点不可达 / 超时）。

### 让 Aurora 调用 ClassIsland 的提醒（v3）

桥接插件 v3 起开放一条**入站提醒通道**（Aurora → ClassIsland），两个入口：

- 设置页的「发送测试提醒」按钮；
- 让 AI 用 `classisland_remind` 工具发（例如「用 ClassIsland 提醒我十分钟后交作业」）。

它把提醒交给 ClassIsland 自己的提醒服务弹出（提供方名为「Aurora 桥接」，
自定义提醒走其中新增的「Aurora 提醒」渠道），因此**是否弹出、是否朗读仍由
ClassIsland 的「设置 → 提醒」决定**：如果你在那边关掉了这个提供方或渠道，
Aurora 会收到一条「已发送但未展示」的失败结果 —— 这是提示，不是故障。

> **不会重复提醒**：Aurora 自己的课前提醒（系统托盘通知 + 打开科目文件夹）与
> ClassIsland 的课程提醒（插件按它对时服务自己发）是**两条独立通道**，
> 默认不会互相触发。Aurora 在课前提醒触发时**不会**顺手再往 ClassIsland 发一条。

### 需要注意

- **科目名要一致**：桥接数据里的科目名必须和 Aurora 科目列表里的名称相同，
  否则该节课会被跳过（Aurora 会在设置页与日志里给出告警）。
  两边叫法不同时，在桥接插件的配置里做一次映射。
- **课表里没有今天** → 显示 0 节课，课前提醒自然不触发（这是正常的，不是坏了）。
- 桥接不可用（插件没装 / 文件被删 / 端点超时）时，Aurora 会**当作今天没有课**继续运行，
  不会影响其他功能。
- **课前提前分钟数**可在「设置 → 模式 → ClassRoom → 课前提醒」里改（1–30，默认 5），
  改完即时生效；它同时也决定 Aurora 读取桥接数据的超时口径（`读取超时`）。
- 目前只同步「星期 × 节次 → 科目」，单双周、临时调课不在此列。

## 7. 快捷键与提示条

### 全局快捷键

默认是 `Alt+Space`：在任何程序里按下都能显示 / 收起 AI 交互窗。

> **`Alt+Space` 很可能注册失败**——它是 Windows 的系统窗口菜单键，通常已被系统占用。
> 设置页会明确显示「已注册」还是「被占用」。若被占用，改成 `Ctrl+Alt+空格`、
> `Ctrl+Shift+A` 之类即可（必须包含修饰键）。

改完保存立即生效，无需重启。快捷键只支持带修饰键的组合（避免误吞全局按键）。

### 提示条

- **透明度**：0.2 ～ 1.0，保存立即生效。
- **独立勿扰时段**：可以让提示条在某个时间段自动隐藏（例如晚自习时段不想被挡）。
  这与「设置 → 高级」里的勿扰时段是**两回事**：后者管的是主动打扰
  （课前提醒、敏感工具确认），本项只管提示条自己是否显示。

## 8. 网络代理

如果模型服务需要走代理（常见于国内访问 OpenAI，或公司网络要求），在
「设置 → 高级 → 系统代理」里填写，例如：

```
http://127.0.0.1:7890
```

也可以只写 `127.0.0.1:7890`（会自动补 `http://`）。支持 `socks5://`。

保存后**立即生效**：模型对话、「测试连接」、MCP 的 HTTP 传输都会走这个代理。
留空表示直连。改完不需要重启。

## 9. 让 AI 帮你操作电脑

v0.7.0 起，Aurora 不只会聊天，还能在**你每一次点头之后**替你动手做事。

| 它能做 | 举例 |
|---|---|
| **跑一条 PowerShell 命令** | 「看看当前目录有多少文件」「在当前目录跑一下 `git status`」 |
| **读写文本文件** | 「把 `notes.txt` 读给我听」「在桌面建一个 `待办.md`，写上今天的三件事」 |
| **列目录** | 「把这个文件夹里的 txt 列出来」 |
| **用默认程序打开** | 打开文件、文件夹、网页，或已安装的程序 |

改代码相关的三件事（**带行号读文件、精确替换几行、按内容或文件名检索**）在下一节单独讲。

每次执行都是**独立的一次**：Aurora 不维持常驻终端，上一条命令里的 `cd`
不会带到下一条（需要换目录时，直接在话里把路径说清楚）。

### 每一次都会问你

跑命令、写文件、打开路径这三类操作，**每一次调用**都会弹出确认卡片，卡片里带着
参数原文——要执行的命令原文、要写入的内容、要打开的路径。你据此决定：

- 点「允许」：执行这一次；
- 点「拒绝」或**不理会**：不执行，模型会收到「用户拒绝执行」，对话继续往下走。

> **60 秒内没有响应**，或者当前正处于「设置 → 高级 → 勿扰时段」内，
> **一律按拒绝处理** —— 不会静默执行，也不会排队等你回来。
>
> 卡片会把过长的参数**截断显示**（并标出被截断）：`write_file` 的参数本身没有长度上限，
> 所以**内容很长的写入不要只看卡片开头就点允许**——看不全就点拒绝，或让模型改成分几次写小文件。

读文件、列目录、内容与文件名检索都不属于敏感操作，不会逐次打扰你。
**但要留意**：它们读到/列到的内容会随对话**发送给模型**（与你自己粘贴文本给它是一回事），
并保存在本地会话记录里；模型也知道路径由它自己决定，所以不要让它去读你不想外传的文件
（例如私钥、`.env`）。

### 怎么开、怎么关

在「设置 → 电脑操控」（侧栏「AI 能力」组里排在 MCP 后面的那一项）集中管理：

- **总开关**：关掉后这八个工具（跑命令 / 读文件 / 写文件 / 精确改文件 / 列目录 /
  内容与文件名检索 / 打开）一个都不注册——模型完全看不到它们，也就不会再弹确认卡片；
- **终端 / 文件 / 文件检索 / 打开**四个分开关：只想保留一部分能力时按需关掉
  （例如关掉「打开」，但继续允许读写文件；「文件检索」管 `grep` / `glob`）；
- **工作目录**：**执行命令**时的缺省起点，留空表示你的用户主目录。注意它**只是默认工作目录，
  不是沙箱**——访问这个目录之外的位置不会被拦下，工具结果里会回带**真实的绝对路径**；
  确认卡片展示的是模型的**原始参数**（要解析出绝对路径就得先执行，所以卡片里可能看到相对路径）。
  读 / 写 / 列目录 / 精确改文件这几个工具不使用这个设置，它们的相对路径按应用自身目录解析；
  **「文件检索」是个例外**：它的缺省搜索根就是这里的工作目录（留空回落用户主目录）。

所有开关**改完立即生效**，不需要重启。

### 你可以这样说

- 「把这个文件夹里的 txt 列出来」
- 「在桌面建一个 `待办.md`，写上今天的三件事」
- 「打开下载文件夹」
- 「看看当前目录的 git 状态，有冲突就告诉我」

### 风险提示（请务必看）

- 命令是以**你当前的用户身份**执行的，能力**等同于你自己在 PowerShell 里敲同样的命令**：
  删文件、改注册表、装软件都在射程内。Aurora **不做命令黑名单**（黑名单总能被绕过），
  真正的安全边界就是「**每一次都问你**」——所以点「允许」之前，请看清卡片里的原文。
- 「设置 → 高级 → 敏感工具确认」关掉后，上述三类操作**不再逐次询问**，会直接执行。
  这个开关的定位是**减少打扰，不是安全加固**；除非你明确知道自己在做什么，否则保持默认开启。
- 命令自己发起的网络请求（例如 `git clone`、`npm install`）走它自己的网络配置，
  **不经过 Aurora 的代理设置**，也不经 Aurora 转发。
- Aurora **不会**模拟鼠标 / 键盘、不截图录屏——它代替不了你点击界面、填表单，
  只能执行命令与文件操作。

### 顺带一句：思考等级

「设置 → AI 模型」里展开某个 provider 的「高级参数与连接测试」，可以设置**思考等级**：

| 取值 | 含义 |
|---|---|
| `auto`（默认） | 请求里**不带**这个参数，兼容性最好；不知道选什么就保持默认 |
| `low` / `medium` / `high` | 逐级要求更多思考；模型不支持时报错就改回 `auto` |

重活（长文推理、复杂排查）选 `high` 通常更靠谱，代价是更慢、更费 token。

> 思考等级是**按 provider 存**的，所以它对该 provider 下的**所有模型**都生效：
> 在对话窗换个模型，等级不会跟着变（这是当前的已知取舍）。

### 它也能改自己的设置

除了替你操作电脑，AI 还能改 **Aurora 自己的配置**：你可以直接说「把思考等级改成 high」
「关掉电脑操控里的终端开关」，它改完**立即生效、不用重启**。

**每一次改动都会先弹确认卡片**（和上面的命令 / 文件确认是同一套），卡片里写着改的是哪个字段、
改成什么值——看清楚再点「允许」。

有几类字段它**碰不到**（这是有意的）：

- **凭据**（API Key、MCP 环境变量）——只在你的机器上加密存储，既不让 AI 读回也不让它改写；
- **网络代理**——写错会让 Aurora 连不上模型，连改回来的机会都没有；
- **窗口位置与尺寸**——改坏会出现难以复现的窗口怪状；
- **配置的 Schema 版本**（决定旧配置怎么迁移）；
- **引导 / 首次运行标记、开机自启、全局快捷键**——这些会改变启动路径或抢占系统热键；
- **敏感工具确认开关**（「设置 → 高级 → 敏感工具确认」）——关掉它等于让 AI 自己摘掉确认闸门，
  属于自我提权，所以这条只能由你在设置页手动关。

这份黑名单由「设置 → 高级」里的 `readonlyPrefixes` 承载，但它**只能在默认黑名单之上追加限制**：
你加进去的前缀会立刻生效，而默认那几条**始终生效、不能通过配置放开**——把某一项从数组里删掉、
甚至把数组清空，那条路径依旧改不了（清空只是回到默认项）。想让 AI 更放得开是做不到的，
只能让它更束手束脚。另外，这份黑名单本身也不能由 AI 修改（它的值是一个数组，工具只接受标量）。

除此之外，AI 只能改**配置 Schema 里真实存在**的字段名：拼错的路径会被直接拒绝，
不会悄悄往配置里塞一个没人认识、也永远不会生效的字段。

> 注意：「设置 → 电脑操控」的**总开关**只管「让模型看不见那 8 个动手工具」，
> 不是把 AI 锁死。总开关关掉后，`set_setting` 仍然注册，AI 仍可（在用户确认后）改
> `agent.tools.*` 把总开关打回来——写入以当前分组值为基底深合并，不会把同分组的其它字段抹掉
> （在那之前，它只是没法替你跑命令、读写文件）。这一点请知情。

## 10. 让 AI 改代码

上一节讲的是「让它替你动手」；这一节是**改代码 / 改配置**这条链路上的三件事：
带行号地读、精确地改、按内容或文件名找。它们都是「电脑操控工具」的一部分，
开关与安全边界见上一节。

### 读：`read_file` 会带行号，也支持从任意位置读

读出来的内容每行前面有一个 `<行号>: ` 前缀（行号从 1 开始、相对文件开头）。示意：

```
文件：C:\project\src\main.ts（共 812 行 / 24310 字节；本次显示第 1–2 行）

1: import { app } from 'electron'
2: import { createWindow } from './window.js'
```

- **默认只返回开头 2000 行**（最多 5000 行）：大文件不会一次全塞进对话。
- **要读后面的部分，用 `offset`**：它是**起始行号**（1 起始，不是「跳过多少行」）。
  你可以直接说「读这个文件第 4000 行往后的 50 行」。
- 单行超过 2000 字符会被截断并标注原长度；超过 16 MiB 的文件只解析开头，
  这时模型会改用 `grep` 定位（见下）。
- **行号前缀只是给你和模型看的**：把它连同前缀一起复制去当 `edit_file` 的原文会匹配不到，
  改文件时要**去掉前缀**。

### 改：`edit_file` 是精确替换，不是整篇重写

`edit_file` 只替换你指定的那一小段（`oldString` → `newString`），其余部分**逐字节保持原样**
（包括文件原本的 CRLF / LF 行尾）。它有几条硬规则，都是为了**不改坏文件**：

- **改之前必须先读过这个文件**（同一会话里 `read_file` 读过即可）——否则直接拒绝并提示先读。
  这条挡住的是「凭记忆改文件」。
- **`oldString` 必须在文件里唯一**：命中多处会被拒绝，模型需要**扩大上下文**（多带前后几行）
  让这段文字唯一；确实要全局改名时，显式用 `replaceAll`。
- 找不到 `oldString`、`oldString` 为空、新旧内容相同——一律拒绝，**不会写盘**。
- 文件**同时含 CRLF 与 LF 行**（混合行尾），或含孤立的 `\r` 时**拒绝改动**：
  宁可不改，也不把整个文件的每一行都改成同一种行尾。
- **单文件上限 1 MiB**：超出的文件请分块 `write_file`，或用命令（脚本 / 格式化工具）处理。

> ⚠ **`edit_file` 没有备份、也没有撤销。** 它把改动直接写进原文件——原子写只保证
> 「写盘过程不会写坏」，**不保证改动内容能回滚**。改错了只能靠你自己的 git / 备份 /
> 编辑器历史恢复。想让它改代码，**先把项目放进 git** 是最省事的保险（隐私说明里也是这条口径，
> 见 [11 §6](./11-privacy.md#6-权限与系统能力)）。
> 另外它和写文件一样是敏感操作：**每一次调用都会弹确认卡片**。

### 找：`grep` 搜内容、`glob` 找文件名

| 想找 | 用 | 例子 |
|---|---|---|
| 某段代码 / 某个符号在哪 | `grep`（按**正则**搜文件内容） | 「搜索 `createReadTracker` 在哪些文件里出现过」 |
| 哪些文件的**名字**符合某个模式 | `glob`（按文件名模式匹配） | 「列出所有 `**/*.test.ts`」 |

- 两者都是**只读、免确认**的工具：结果只回带路径（`grep` 另带行号与命中行），
  拿到位置后模型会用 `read_file` 的 `offset` 跳过去读那一段——不必再逐层列目录。
- 它们会**递归扫描整个搜索根**（缺省就是「设置 → 电脑操控」里的工作目录，留空即你的用户主目录），
  但会自动跳过 `node_modules` / `.git` / `dist` / `out` / `build` / `.next` / `coverage` / `.turbo`
  这八个目录，并跳过二进制文件。
- 单次结果条数有上限（缺省 **200** 条，可在「电脑操控」页的「文件检索」栏调，上限 1000），
  另有扫描预算；触顶会**如实标注「结果被截断」**，不会假装已经找全。
- 内容扫描的单文件上限是 **1 MiB**（更大的文件直接跳过）；`glob` 只比文件名，不受这条限制。

### 少弹几次卡片：免确认命令模式

用起来最烦的其实是「每条命令都弹一次确认」。如果你有一些**每次都想放行**的命令
（比如 `git status`、`npm run build`），可以在「设置 → 电脑操控 → 免确认命令模式」里
加几条**命令模式**（配置字段 `agent.tools.terminal.allowPatterns`）：命中的命令
**不再弹确认卡片**，直接执行；没命中的照旧逐次确认。

- 匹配规则是**整条命令的 glob 全串匹配、大小写不敏感**：`*` 匹配任意字符（可以为空）、
  `?` 匹配一个字符。**是全串匹配**，所以 `git *` 不会命中 `echo git`。
- 模式里**只允许字面字符、`*` 和 `?`**：出现别的东西（尤其是花括号 `{}`）会被拒绝保存——
  `{a,*}` 这类写法编译出来相当于「放行所有命令」，是会悄悄拆掉闸门的写法，所以整类禁掉。
- 命中后**仍会写一条审计日志**（记下命令与命中的模式），「为什么这次没弹卡片」可回溯。
- **它只是「减少打扰」，不是安全加固**：命中模式的命令会**无人确认地执行**，
  身份与能力和你自己在 PowerShell 里敲同一条命令没有区别。要安全边界就**保持列表为空**，
  或只加你完全确定无副作用的读操作。
- 这份列表**只能你自己在设置页维护**：AI 的「改自己的设置」明确碰不到它
  （否则它给自己加一条 `git*` 就等于摘掉自己的确认闸门，属于自我提权）。

### 你可以这样说

- 「读一下 `src/main/index.ts` 第 300 行附近，看看这个函数怎么写的」
- 「把 `user-store.ts` 里那个 5000 毫秒的超时改成 30000」（它会先读、再精确替换，然后弹卡片确认）
- 「在项目里搜索所有用到 `legacyApi` 的地方」
- 「列出所有 `**/*.test.ts`」

## 11. 常见问题

**Q：API Key 会不会被上传到别处？**
不会。凭据只在本机加密存储，只在调用**你自己配置的**模型服务时使用。
详见 [隐私说明](./11-privacy.md)。

**Q：为什么「测试连接」通过，但对话报错？**
两者走同一条网络路径了，若仍不一致，最可能是模型名不对——部分服务对
`/models` 列表宽松，但真正对话时要求精确的模型名。看日志
（「设置 → 高级 → 打开日志目录」）里的错误码会更清楚。

**Q：文件被分类错了怎么办？**
在 AI 交互窗的「分类流水」里点该条记录，改成正确科目。文件会被移过去，
并且同类文件名下次会自动按你的修正处理。要重置历史：设置页的「清空流水」
（不会删除已沉淀的规则）。

**Q：怎么把日志发给我看？**
「设置 → 高级 → 打开日志目录」，把当天的 `aurora-YYYY-MM-DD.log` 发出来即可。
日志已自动脱敏（API Key、token、password 等一律替换为 `***`），保留 7 天。

**Q：改了课程表要重启吗？**
不需要。课程表、模型配置、代理、日志级别、快捷键都是**改完即生效**。

**Q：托盘图标不见了？**
Windows 可能把它收进了隐藏图标区（点任务栏的 `^`）。Aurora 关掉窗口只是隐藏，
不会退出；要退出请右键托盘图标 → 退出。
