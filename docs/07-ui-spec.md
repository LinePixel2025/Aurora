# 07 · 窗口与交互设计规格

状态：`已定稿`（v1 基线）

## 1. 设计原则

- **轻**：默认占用最小（服务窗 + 提示条），完整窗口按需展开。
- **顺**：所有展开 / 收起带过渡动画，不突兀。
- **聚**：视觉统一（深色主题为主、跟随系统）、状态指示一致（AI 状态灯全局同色语义）。
- **隐**：业务窗口无任务栏图标，托盘为唯一管理入口；所有窗口可一键隐藏。

## 2. 窗口规格

### 2.1 AI 服务窗（Service Dock）

- **形态**：无边框、置顶、半透明背景；**两态折叠**（v0.5.1 起）：
  - **收起态**：56×56 圆形浮球（深色玻璃底 + 极光渐变环 + 状态点），常态保持此形态以最小化占地；
  - **展开态**：320×56 输入条（状态点 + 单行输入框 + 发送按钮）。
- **行为**：
  - 收起态点击球心 → 展开为输入条并聚焦输入框；
  - 展开态 `Esc`、或输入框失焦且输入为空 → 收起；消息发送完成后自动收起；
  - 每次服务窗被**重新显示**时重置为收起态（由主进程执行）；
  - 展开 / 收起保持浮球**水平中心与底边不变**（向左右 / 上方生长），并 clamp 在工作区内；
  - 输入消息回车 → 发送到“快速会话”，回复以小 AI 交互窗口展示；
  - 点击窗口（输入框以外区域）→ 拉起小 AI 交互窗口，迷你窗**水平居中对齐服务窗**；
  - 输入框支持前缀快捷操作：`@`（调 Skill）、`/`（快捷指令：新会话 / 打开完整窗口 / 隐藏服务窗 / 设置）；
  - 右键菜单：隐藏服务窗 / 打开交互窗 / 设置 / 退出。
- **拖动**：收起态拖球体外圈（渐变环区域）、展开态拖左侧 grip；中心按钮标 `no-drag`，不影响点击。
- **位置记忆**：只记忆位置（x / y）与多显示器归属；尺寸由当前折叠态决定，**不跨态记忆**（否则收起态会被写成上一次输入条尺寸）。
- **状态点语义**：闲置（灰）→ 思考 / 执行中（呼吸蓝）→ 有未读结果（橙点）→ 异常（红）。

### 2.2 右侧提示条（Edge Bar）

- **形态**：贴屏幕右缘竖条（宽约 8px），悬停或点击展开为约 200×全高面板，置顶、可穿透性可配。
- **内容**：AI 状态灯 + 当前模式图标 + 最近消息预览（展开态）。
- **行为**：点击 → 从右侧滑出完整 AI 交互窗口（桌面层，可覆盖任意应用）；展开面板含“打开对话 / 设置 / 隐藏”快捷入口。
- **可配置**：显示 / 隐藏、透明度、静默时段。
  - 实现状态（v0.6.0）：`general.edgeBar.opacity` 保存后即时应用（`setOpacity`，范围 0.2–1.0）；
    `general.edgeBar.quietHours` 由 `main/edge-bar-scheduler.ts` 每 30s 判定，**仅控制提示条自身显隐**，
    与 `advanced.quietHours`（控制主动打扰：课前提醒 / 敏感工具确认）职责分离、互不影响。
    可见性只在状态翻转时切换，避免反复 show 把用户刚手动隐藏的提示条拉回来。
  - 未实现：`可穿透性可配`（尚未接入 `setIgnoreMouseEvents`）。

### 2.3 AI 交互窗口（Chat Window）

- **完整对话**：Markdown、代码高亮、流式渲染、工具执行卡片（可展开查看细节）、附件与文件拖拽发送。
  - 实现状态（v0.6.0）：**附件拖拽已落地** —— 路径解析在 preload（`webUtils.getPathForFile`，Electron 32+ 已移除 `File.path`），
    文本提取复用分类管线的 utilityProcess 提取器（单文件上限 8000 字、单条消息最多 5 个）；提取失败的附件会在上下文里**如实标注「未读取」**，不假装已读。
    小窗（2.4）同样支持拖拽。
- **尺寸**：约 420×640，可调、位置记忆；会话历史列表。
  - 实现状态（v0.6.0）：**多会话列表已落地**（`chat:sessions` 列表 + `chat:newSession` 新建 + 切换）。
    标题取首条用户消息前 24 字（不额外调用模型生成标题），按最后消息时间倒序；
    空会话显示为「新会话」且不落空文件（首条消息才创建）。窗口默认会话仍为 `main`，老数据继续可读。
- **联动**：由提示条拉出（贴右缘滑出）；失焦默认不自动隐藏（可配置），可一键收起回提示条。

### 2.4 小 AI 交互窗口（Mini Chat）

- **精简对话**：气泡 + 流式文本 + 工具状态点（无完整执行卡片）。
- **尺寸**：约 320×480；锚定服务窗弹出，与服务窗同显同隐。
- **会话**：与服务窗共享“快速会话”；提供“展开到完整窗口”（会话迁移到交互窗）。

> **新增（v0.4.0 / v0.5.0）**：
> - **分类流水**（`ClassificationLedger.vue`）：可折叠区块，默认收起，展示
>   时间 / 文件 / 状态 / 科目 · 来源 · 置信 · 依据，支持「改到其他科目」「打开所在文件夹」「清空流水」；
>   交互窗与设置页共用同一组件（分别给 20 / 50 条）。
> - **敏感工具确认卡片**（`SensitiveToolCard.vue`）：挂在交互窗顶部，展示工具名与参数摘要、
>   到 `expiresAt` 的倒计时与进度条（≤15s 变红），「拒绝 / 允许一次」回执。
>   主进程在推送确认请求时会**主动显示并聚焦交互窗**，避免交互窗未打开时确认不可见而静默超时。

### 2.5 设置窗口

- 单窗口分栏：**常规** / **模式** / **AI 模型** / **Skill** / **MCP** / **高级**（日志、代理、静默时段）。
- **关闭入口（v0.5.1 起）**：本窗无系统标题栏（`frame: false`），因此侧栏品牌区自担标题栏职责——
  整行可拖动（`drag-region`），右侧提供「✕ 隐藏」按钮；按 `Esc` 等效。
  按 docs/02 §2.2 约定，此处「关闭」= **隐藏窗口**（不退出应用，退出只走托盘菜单）。
- 模式页：三模式卡片选择，展示当前模式引导状态与“重新引导”按钮。
- **实现说明（v0.4.0 / v0.5.0）**：ClassRoom 在当前模式下的完整配置集中在
  `settings/components/ClassroomSection.vue`（由模式页渲染）：感知文件夹（含「打开文件夹」）、
  科目列表增删改 + 每科目标文件夹与关键词、课程表编辑（星期 / 起止时间 / 科目）、
  课前提醒开关、分类行为（自动移动 / 置信阈值 / 兜底文件夹）、分类流水（默认展开）。
  高级页新增「敏感工具确认」开关（`advanced.confirmSensitiveTools`）。

### 2.6 首次安装引导窗口

- 向导式：欢迎 → AI 模型（baseURL / API key / 模型名 + 测试连接）→ 模式选择 → 完成；完成后进入托盘常驻并显示服务窗（流程详见 08 §3）。

## 3. 窗口间状态机

```
托盘 ──▶ 服务窗 / 交互窗 / 设置 / 引导
服务窗 ──输入──▶ 快速会话（迷你窗展示回复）
   └──点击──▶ 迷你窗 ──展开──▶ 交互窗（会话迁移）
提示条 ──点击──▶ 交互窗（贴右缘滑出）
```

- **规则**：迷你窗与交互窗同屏互斥（同一会话同一时间只在一个窗口）；服务窗随时可隐藏；隐藏服务窗时迷你窗一并隐藏。
- **全局快捷键**：唤出 / 隐藏服务窗 `Alt+Space`（可在设置中改）。
  - 实现状态（v0.6.0）：**已落地**（`main/hotkey.ts`）—— 启动时注册、退出前注销、
    设置改绑即时生效（幂等：值未变不重复注册，避免闪断窗口）、注册失败会把真实原因回传设置页。
  - **冲突是预期路径**：`Alt+Space` 是 Windows 的系统窗口菜单键，常被系统占用。
    此时设置页显示「被占用」并给出可操作建议，用户改绑即可 —— 不静默失败，也不报成 bug。
  - 格式校验拒绝**不含修饰键的裸按键**（如 `F5`）：那会吞掉全局按键，属于用户误操作。

## 4. 通知与反馈

- **系统通知**：分类完成（点击打开对应文件夹）、课前提醒、引导提醒。
- **窗口内 Toast**：错误提示（LLM 失败、MCP 断开、分类失败）与可恢复操作入口。

## 5. 视觉方向（建议基线）

- 深色为主、半透明毛玻璃质感；主色取极光绿 → 蓝渐变（呼应 Aurora），状态色语义统一（蓝 = 运行中、橙 = 未读、红 = 异常）。
- 字体：系统 UI 字体栈（Segoe UI Variable / 微软雅黑）。
- 窗口圆角 8～12px，统一 8px 间距栅格；所有动画 120～200ms ease-out。
- 详细视觉以实际 UI 开发时的设计稿为准，本节约束的是风格方向而非像素。
