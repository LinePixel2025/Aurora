# Aurora v0.1.1 更新说明

发布日期：2026-09-25 ｜ 安装包：`Aurora-Setup-0.1.1.exe`（Windows x64，未签名）

这一版是**对话流的缺陷修复版**，修复 v0.1.0 实测报告的两个显示问题：多轮对话时**消息顺序错乱**（刚发出的提问被压到整轮回复之后），以及**「已深度思考」内容重复出现两次**。两个问题同源，都是 v0.1.0 的「对话顺序与归属」重构在界面层落地时的实现缺陷，落盘的会话数据（`sessions/*.json`）本身一直是正确的——只影响实时对话窗口的显示，历史记录没有损坏。

配置 Schema 无变化（仍是 v10），安装包直接覆盖升级即可。

---

## 🐛 修复一：同一会话第二轮起，刚发出的提问被压到整轮回复之后

### 现象

从同一会话的**第二次提问**开始，刚发出的用户消息会逐渐「沉底」——界面上它出现在 AI 的全部回复（思考块 / 正文 / 工具卡）之后，看起来像对话顺序完全错乱。第一轮提问则完全正常。

### 根因

v0.1.0 重构了消息排序：界面消息不再「到一条追加一条」，而是按主进程事件携带的序号 `seq` **插入到正确位置**。但这里有一个被忽略的角落——

- 用户**自己发送**的消息气泡是界面本地立即创建的，此刻主进程还没分配 `seq`（序号随事件流稍后才到），所以这条气泡**没有 seq**；
- 排序函数按 seq 找插入位置时，扫描会**跳过没有 seq 的消息继续往前找**；
- 于是从第二轮起（列表里已经有带 seq 的回复了），每条新回复都越过这条无 seq 的提问气泡，插到它前面。

第一轮为什么正常？因为挂载时列表里全是无 seq 的历史消息，新回复没有「可越过」的对象，只能追加到末尾——恰好是正确位置。这也是它隐蔽的原因：只在同一窗口持续对话的第二轮之后才显现。

### 修复（两层）

1. **排序不再越过无 seq 的本地消息**：自己刚发的气泡、发送失败提示在时间上一定晚于列表中它之前的所有内容，新消息不能插到它前面。排序扫描遇到无 seq 消息时**立即停在它后面**。
2. **给本地气泡补 seq**：主进程在每轮开始时广播的 `user-message` 事件本来就会到达界面，现在它命中「同一条消息」的去重判断时，会把主进程分配的 seq / 时间**对齐回本地气泡**——发送方与旁观窗口从此有完整一致的排序依据。

## 🐛 修复二：「已深度思考」重复出现两次

### 现象

一轮带工具调用的回复里，如果**第一轮有思考、后续轮没有**，最后那条回复（如「已发送 ✅ …」）的上方会再出现一个「已深度思考」折叠块，内容与第一条**完全相同**——思考过程显示了两遍。

### 根因

思考过程是逐字流式到达的，而那一轮的助手消息要等整轮流结束才落盘，所以界面按「轮次」分桶暂存思考增量，等同一轮的正文 / 工具事件到达时再绑定到对应消息上。问题出在**请求收尾**：

- 收尾时会把「当前正在接收的思考」固化到最后活跃的消息上，兜住还没绑定上的尾巴；
- 但这个「当前思考」镜像**只在收到思考增量时更新**——最后一轮如果模型没有返回思考（比如工具结果回填后直接作答），它保留的仍是**上一轮的全文**；
- 于是收尾固化把上一轮的思考又灌进了收尾消息 → 同一份思考显示两次。

### 修复

收尾固化改为**只处理从未绑定到任何消息的思考草稿**（无主桶）：凡是已经通过正文 / 工具事件绑定到消息上的思考，收尾时一律不再碰。原有兜底语义保留——真正的「思考尾巴」（模型思考完却没输出正文的罕见轮次）仍然不会丢。
