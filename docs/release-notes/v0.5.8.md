# Aurora v0.5.8

本次版本汇总 **v0.5.7 → v0.5.8** 的全部更新：修复页面型插件面板在 Aurora Center 上
**调用参数被多包一层**导致的核心缺陷——网页端切视图永远回到桌面最后停留的视图，输入内容
提交后不生效（`add-task` / 公告等写操作报「请先输入事务内容」）。同时把页面调用超时与服务器
对齐、页面自行导航离开后主动断流，并把 Center 与桌面共享面板视图状态的口径写进文档。
配置 Schema 仍为 **v38**，无迁移；插件契约不变，**插件无需修改**。Aurora Center 服务器
同步升级到 **0.5.2**（版本线独立：不建 tag、不上传 GitHub Releases），本次双投的仍是
桌面安装包的三个更新资产。

## 一、修复 Center 页面型面板参数丢失（根因）

- 中继链路 `plugin.panelData → readPluginPanelData → invokePanel` 曾复用声明式面板的
  `{ params, values }` 包装，而页面约定与桌面 `plugins:pageRpc` 都是**直传**；插件的
  `asParams()` 只做对象判定，包装对象也通过，于是 `view` / `weekOffset` / `text` 等字段
  全部变成 `undefined`。
- 表现为：Center 上点视图标签无效（`save-view` 把旧的 `ui.view` 原样写回），输入事务 /
  公告后提交提示「请先输入事务内容」/「请提供通知内容」，内容不落地。
- 修复：page 分支直传 `params`；单测断言 `invokePanel` 第 4 参形状与默认 `refresh` / `{}`。
  桌面 `plugins:pageRpc` 行为不变。

## 二、Center 允许改桌面视图（既定口径）

- 页面型面板直接读写插件自己的 `ui` 状态，不做隔离。Center 的切视图 / 切周会写回桌面
  同一份状态；桌面已打开的面板在下次加载 / 收到插件事件后跟随。
- 需要两端即时同步时由插件在写操作后 `ctx.ui.panelEvent` 推送，宿主不做通用回放。
- 文档已同步：docs/12 §6.5、docs/15 §7.1。

## 三、页面超时与导航断流

- 页面侧请求超时 15s → **25s**（高于服务器 pending 20s）：避免页面先报超时、写操作却
  已落地，用户重试造成重复写入。
- 桥在 `pagehide` 时上报带每帧令牌的 `bye`；父页收到后清空在途、退订、移除 iframe 并
  提示刷新，不再把 `plugin.event` 投给导航后的新文档。实测导航后旧文档的 `event.source`
  已不等于 `contentWindow`，因此用 `__auroraBridge` 令牌归属，避免误判与跨帧干扰。
- `verify:web` 的 `plugin-page` 场景新增「离开断流提示 + 刷新恢复」断言。

## 四、兼容与升级

- 配置 Schema 仍为 **v38**，无迁移；无新设置项。
- 插件清单 / 权限 / 宿主 API 不变；**插件无需修改**。
- 桌面 `plugins:pageRpc` 与页面型小组件路径不受影响。
- 页面型面板仍需从**本 Center 市场**发布同名版本取资源；沙箱能力基线（opaque origin、
  无 storage / modal / fetch、资源仅市场包）已写入 docs/12 §6.5 与 docs/15 §7.1。
