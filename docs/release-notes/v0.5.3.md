# Aurora v0.5.3

本次版本汇总 **v0.5.2 → v0.5.3** 的全部更新，集中在插件页面 RPC 与桌面小组件标题栏：
修复页面型桌面小组件的请求被误拦截、补齐页面动作的 `message` / `error` 回传，
并新增 `hideCloseButton` 清单字段，让插件可以请求宿主不渲染标题栏右上角的「隐藏小组件」按钮。

配置 Schema 保持 **v36**，没有新增迁移；Aurora Center 代码版本线仍独立。

## 一、页面型小组件 RPC 修复

- `plugins:pageRpc` 的桌面小组件分支此前复用 `PluginManager.invokeWidget`，而后者保留了
  「没有声明式 `schema` 就拒绝」的旧守卫，导致所有页面型小组件（`entry`）的 `load` /
  写动作都收到「页面型小组件请通过小组件页面打开」；
- 本版移除该守卫：页面型小组件经 `plugins:pageRpc` 正常转发到插件的 `invokeWidget`；
  旧声明式通道（`plugins:widgetData`）仍拒绝页面型小组件，安全边界不变；
- 回归测试覆盖「页面型小组件可调用」与「声明式通道仍拦截」两种路径。

## 二、页面动作结果透传

- 页面型面板 / 页面型小组件的 `invokePanel` / `invokeWidget` 现在会把插件返回的字符串
  `message` 与 `error` 与 `data` 一起原样交给页面；
- 成功提示与业务错误不再被静默丢弃，页面可以在自己的状态条里显示插件给出的文案；
- 声明式面板 / 小组件仍只消费 `schema` / `toast`，行为不变。

## 三、桌面小组件 `hideCloseButton`

- `contributes.widgets[]`（`slot: "desktop"`）新增可选字段 `hideCloseButton`，默认 `false`；
  设为 `true` 时宿主不渲染标题栏右上角的「隐藏小组件」按钮，标题栏只保留标题与拖拽区；
- 隐藏 / 恢复仍可在 设置 → 插件 → 对应小组件 →「显示在桌面」操作；
- `slot: "edge-bar"` 声明 `true` 会被清单校验拒绝；旧宿主会静默忽略未知字段；
- 字段进入插件摘要与安装预览，开发目录热更新时窗口会按新值重建；
- `plugin-dev-kit` 的校验器、契约、开发指南与检查清单同步。

## 四、兼容性与升级说明

- 配置 Schema 仍为 **v36**，无迁移；已有配置、会话、插件与布局文件原样使用；
- 未使用新字段的插件行为不变；使用 `hideCloseButton` 的插件建议把 `minAuroraVersion`
  设为 `0.5.3`；
- 页面型小组件在 v0.5.2 上无法加载；本版起恢复正常，班级事务台 v2.1.1 已把最低宿主提到 `0.5.3`；
- 安装包仍为 Windows x64、未签名；首次运行 SmartScreen 提示时选择「更多信息 → 仍要运行」。
