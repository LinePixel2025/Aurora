# Aurora v0.2.8 更新说明

发布日期：2026-09-29 ｜ 安装包：`Aurora-Setup-0.2.8.exe`（Windows x64，未签名）

这一版修三件事：

1. **自动化不再能"自己给自己排活"** —— Agent 模式触发的会话既不能改自动化、也不能触发自动化，
   而且它拿到的系统提示词也不再是普通对话那套（它知道自己在无人值守地干活）；
2. **自动化支持调用次数** —— 给一条自动化设个次数上限，用满后它自己停用，不会无限期跑下去；
3. **启动要求管理员身份** —— 启动时若未提权会自动请求 UAC 以管理员身份重启，
   少掉一批"命令跑了但被权限拦住"的失败。

**有一处配置迁移**：Schema 升到 **v20**（新增 `general.requireAdmin`，默认开启）。
覆盖安装即用，你已有的设置一个都不会被改（包括你已经关掉的那些开关）。

> ⚠️ **第一次启动会弹一次 UAC**：出厂档要求以管理员身份运行。如果你不想每次都弹，
> 到「设置 → 常规 → 以管理员身份运行」关掉即可（重启后生效）。
> 开机自启同样会弹一次（没有用计划任务做最高权限自启）。

---

## 🤖 一、自动化的两条硬边界

起因是「自动化里的 Agent 能改自动化设置、还能自己触发自动化」：一条按时唤醒的自动化，
跑起来的会话如果再能创建 / 触发自动化，就变成了**不需要你点头也能不断给自己排后台动作**的闭环。

现在这是一条被两侧同时焊死的边界：

- **看不见**：自动化会话的工具面里没有 `automation_create` / `automation_update` /
  `automation_delete` / `automation_run` 四个写类工具 —— 提示词的工具清单、请求体的工具表、
  执行时的查表三处同时摘除，普通会话完全不受影响；
- **做不到**：即使被绕过（例如子代理从父表取工具），这四个工具在执行层也会直接拒绝并回一句
  「自动化运行中的会话不能管理或触发自动化」，一次都不会落到真实的存储上。

只读的 `automation_list` / `automation_history` 保留 —— 看看自己属于哪条自动化、上次跑成什么样，
对完成任务有帮助，而且没有副作用。

**自动化会话的系统提示词也换了**：普通对话那套人设的第一条策略是「缺少信息时先问一个最关键的问题」，
而无人值守时这一问会挂到超时。现在自动化会话用的是**后台执行体**人设（自己查证、自己决定、
做完汇报），并额外注入一段「本次运行」说明：任务指令就是全部需求、不要新建/修改/触发自动化、
破坏性操作仍走确认卡片（无人应答按拒绝处理）、收尾如实报告哪些没做成。

## 🔢 二、调用次数：用满就停，不再无限期跑

自动化定义新增两个字段：

- **调用次数上限**（`maxRuns`，编辑器里叫「调用次数」）：0 = 不限，最大 100000；
- **已调用次数**（`runCount`）：触发即 +1（手动点「立即运行」也计入），内置自动化不计数。

语义是「**用满的那一次照常执行，然后自动停用**」——最后这一次是你想要的，不该被吞掉。
计数**累计不清零**：重新启用不会让它复活，要接着用请提高上限，或在编辑器里点「重置计数」
（一键把已调用次数归零）。手动触发一条已用尽的自动化会明确告诉你原因
（「调用次数已用尽（3/3）：请提高上限或重置计数」），而不是含糊地说"已停用"。

界面上：列表卡片在模式徽章旁多一枚次数徽章（`3/10`），用尽时转成警示色并提示；
编辑器里有「调用次数」一行与「重置计数」按钮；Center 网页端的自动化视图同步支持
（服务端零改动，定义本来就是原样转发的）。

**顺手修掉一个小毛病**：编辑器保存时不再无条件启用该自动化 —— 此前"编辑一次"会把一条
停用中的自动化顺带打开，现在编辑只改你改过的东西。

## 🛡️ 三、启动要求管理员身份（新配置，出厂开启）

`run_command` 与文件工具跑在**当前用户权限**下。未提权时，写 `C:\Program Files`、
改系统设置、`net session` 这类操作会直接失败，你看到的是「AI 说做了，其实没做成」。
这一版把这条缝焊上：**启动时若当前进程未提权，用 UAC 重新拉起一个管理员实例并退出自己。**

四条边界，都是为了不把"要求权限"变成"打不开"：

- **不无限重拉**：被提权拉起的实例带 `--aurora-elevated` 标记，看到标记就不再尝试提权；
- **拒绝了也能用**：你在 UAC 上点「否」时，程序**继续以普通权限启动**并记一条日志，
  不会卡在启动阶段；
- **只在安装版强制**：开发态（`pnpm dev` / 自测）默认跳过，需要验证时用环境变量
  `AURORA_REQUIRE_ADMIN=1` 打开；
- **探测失败按"已提权"处理**：拿不到结论时宁可不重启；
- **换账户守卫**：如果你的账户不在管理员组，UAC 会要求填管理员账户密码，程序会以**那个账户**
  运行、看不到你原来的数据。这种情况程序会识别出来：自动关掉「以管理员身份运行」、
  弹一条说明并退出 —— 重新启动即可（原数据一直都在）。

提权只提高"能做什么"，**不改变权限判定链**（越界仍要确认、写前快照、项目根边界照旧）；
它也不是沙箱。

## 🔧 四、其它

- 设置页「常规」新增「以管理员身份运行」开关（AI 改不动它：与权限档位、确认闸门同款只读口径）；
- 「Agent 可修改的设置」清单补一句提示：管理员提权与循环预算、写前快照同属只读，
  免得模型反复尝试必然被拒绝的写入；
- 自动化页与设置页的运行时探针补齐（次数徽章文案与用尽态、编辑器次数输入可用、
  常规页提权开关常显）；
- 单测新增约 30 条（引擎计数与自动停用、工具层的会话边界、运行档、提权决策表、
  `filterTools`、提示词「本次运行」小节、v19 → v20 迁移），全仓 **1859 个用例全绿**。

## 升级须知

- **覆盖安装即用**，配置自动迁移到 v20（只补 `general.requireAdmin: true`）；
- 如果你**不希望**每次启动都弹 UAC，安装后先去「设置 → 常规」把「以管理员身份运行」关掉；
- 安装包仍未签名，首装会出现 SmartScreen「未知发行者」提示，选择「更多信息 → 仍要运行」。
