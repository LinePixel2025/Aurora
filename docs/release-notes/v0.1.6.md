# Aurora v0.1.6 更新说明

发布日期：2026-09-27 ｜ 安装包：`Aurora-Setup-0.1.6.exe`（Windows x64，未签名）

这一版的主题是 **「兑现承诺 + 敢用的最后一公里」**：v0.1.5 更新说明末尾**如实披露的三个已知问题**，
在这一版**全部修掉**；此外，一轮独立安全审查指出的「零弹卡越界写入」逃逸链也在这一版封死。

配置 Schema 停留在 **v15**（本版无新增迁移），直接覆盖安装即可。

---

## ✅ 一、上一版三个已知问题，全部修复

### 1. 自动续轮不再丢上下文

v0.1.5 默认开启的「自动续轮」（轮次用完后自动再续）在第二轮发出的请求里**没有本轮提问、
也没有上一轮的工具结果**，模型可能**重复执行已经做过的写文件 / 跑命令操作**。

- 修复：续轮的每一轮都**重新读取会话历史**再组装请求——第二轮带上了本轮提问与上一轮的工具结果，
  模型看到的是完整的"已做过什么"，自然接着做剩下的。
- 配套回归护栏：单测钉住「续轮请求带本轮提问与上一轮工具结果」，这个问题不会再悄悄回来。
- 上一版的临时规避（把「自动续轮次数」改成 0）**可以放心改回默认值**了。

### 2. AI 改不动自己的「闸门」了

v0.1.5 披露：`agent.loop.*`（轮次 / token 预算）与 `agent.snapshots.*`（写前备份）当时 AI 的
`set_setting` 也改得动。这一版：

- 两者都进了**只读黑名单**：AI 的 `set_setting` 一律拒绝（拒绝原因会写明"这是你自己的停止闸门 / 回滚保险"）；
  用户在**设置页**调整不受影响（设置页不走 AI 的黑名单）。
- 顺带把黑名单配置自身（`advanced.readonlyPrefixes`）也进了黑名单——AI 往里追加路径等于自己收紧自己
  （自我 DoS），放宽则本就不生效，两个方向都不该让 AI 碰。

### 3. 配了项目后，命令真的落在项目根里

v0.1.5 披露：配了当前项目后，不指定 `cwd` 的 `run_command` 与不指定根的 `grep` / `glob`
仍落在用户主目录（越界 / 失败 / 静默错位三选一，都不对）。这一版：

- 缺省工作目录 / 搜索根按**三级回落**接线：**当前项目根 > 设置里的「工作目录」> 用户主目录**。
  配了项目后，AI 不写绝对路径的命令与检索都默认在**项目根**里执行——与「AI 现在知道自己在哪个项目里」
  的心智终于对齐。
- 设置页「打开工作目录」按钮走**同一个**三级回落：配了项目时打开的就是项目根，
  与命令实际落地目录一致（v0.1.5 里按钮按字面读「工作目录」配置，配了项目时会与实际分叉）。
- **没配项目时行为与以前完全一致**（回落用户主目录 / 「工作目录」配置）。

## 🔒 二、封堵「零弹卡越界写入」逃逸链（独立安全审查）

一轮独立安全审查指出：在「完全权限」档下，AI 可以在项目根内先建一个**指向根外的目录联接
（junction / 符号链接）**，再对链接路径调用 `write_file`——判定端看到的是根内字符串（免确认），
执行端跟着链接**穿透到根外**写盘成功。全程**零弹卡**。

修复方式是把「免掉项目根边界校验」这个特权**收紧到只有你亲自点过确认卡片**的调用：

- 确认判定从「放行 / 拒绝」扩为**四态**：拒绝、你当次点放行、你当次点「本会话都允许」、
  以及**机器放行**（完全权限档根内免确认 / 免确认命令模式 / 无项目 / 「本会话都允许」记住后的自动放行）。
- **只有前两种（你当次真的看过卡片）**才免掉边界校验；机器放行照常执行，但项目根的
  realpath 兜底**保留**——根内链接指向根外的写入会被拒绝，且不弹卡（没有可免的确认，也不该放行）。
- 对你的日常使用**无感知**：项目内的正常读写、命令执行一切照旧（实测验证过）；
  唯一的语义变化是「本会话都允许」记住之后的连续操作**不再额外免掉边界校验**——
  它依然让你少弹卡，只是"越过项目根"这种事在任何自动放行路径下都做不成了。

## 🔧 三、其他修复

- **写坏配置的回滚会通知重建**：AI 改配置触发"写后校验失败 → 回滚"这条防御路径时，
  现在会补一次变更通知，避免个别工具停留在坏配置上直到下次改动（防御路径，生产极难触发）。
- **脱敏逻辑归位**：凭据脱敏从 IPC 层拆成独立模块（单一真相源），行为零变化；
  顺带让配置端口的单测摆脱了 Electron 依赖。
- **测试与冒烟增强**：新增切项目竞态（fail-closed）回归用例；整机冒烟自测新增
  「根内链接指向根外被拒」场景，166 项全过。

---

## ⚠️ 仍是已知限制（不是 bug）

- 三档权限 + 项目根前缀校验**不是** OS 级沙箱：`run_command` 仍以当前用户权限执行，
  没有作业对象 / 容器 / 受限令牌。项目根边界拦的是"Aurora 工具自己越界"，拦不住命令内部调用的
  其他程序越界。
- 无当前项目时不做边界校验（行为与 v0.1.2 之前一致）。
- 全局快捷键 `Alt+Space` 在 Windows 上常被系统占用，注册失败属预期路径，改绑即可。
