# Aurora v0.8.3

本次版本汇总 **v0.8.1 → v0.8.3** 的全部更新（v0.8.2 未单独发版）。主题是**接入少填一步**
（Center 固定官方地址、只保留网页授权登录）、**官方模型开箱可用**（四类默认开启、选模入口
并入各模型管理页）与**添加流程弹窗化**（AI 模型 / 语音 / 生图 / MCP 统一改成独立弹窗）。

本版配置 Schema **v46 → v47**（一条自动迁移：四类官方模型的 `enabled` 置 `true`，
**已选 `model` 原样保留**）；插件 API 仍为 **v1**；Aurora Center 版本线不变（**0.7.0**，
本次不升）。已有配置 / 会话 / 子代理 / 插件 / 自动化数据全部保留。

## 一、Center 接入：固定官方地址 + 只保留网页登录

过去接入 Center 要填服务器地址、再输 Center 账号密码；自托管改向也依赖手填地址。
本版把接入路径收敛成一条：

- **地址固定**：`center.serverUrl` 的默认值与设置页展示都固定为 `CENTER_SERVER_URL`
  （`http://120.24.223.65:8787`）。设置页只有一段**只读文本**，不再提供地址输入、不可改向。
- **只保留设备授权登录**：Aurora Center 页只剩「登录账户」按钮 —— 点击后主进程打开浏览器进入
  Center 网页确认页，用户在网页登录 / 注册并确认，客户端后台轮询拿到令牌后自动接入。
  设置页**删除** Center 账号输入、登录密码输入与「密码登录」按钮。
- **兼容保留**：`center:login` IPC 与服务器端 `POST /api/client/login` 仍在（旧链路 / 测试可用），
  只是设置页不再调用；密码照旧不落配置、不进日志。
- **存量 `serverUrl` 不迁移**（避免静默切走自托管用户），在下一次保存或登录时规范到固定地址。
  自托管 Center 需要改 `CENTER_SERVER_URL` 后重新构建客户端。

## 二、官方模型默认开启，选模入口并入模型管理

- **四类官方模型默认开启**：`center.officialModels` 的语言模型 / 生图 / TTS / STT 四类
  `enabled` 出厂即 `true`；登录 Center 后无需再找开关。
- **迁移 `v46 → v47`**：把存量配置四类的 `enabled` 置 `true`，**已选 `model` 原样保留**；
  `center` 分组缺失时不凭空造对象，重复执行幂等。
- **Center 页「官方模型」区组已移除**：Center 页只保留连接设置 / 远程控制许可 / 连接状态。
  选模入口并入对应模型管理页 ——
  - **语言模型**：「AI 模型」页「默认模型」下拉的「Aurora Center 官方」分组（`<optgroup>`）。
    选中官方项会同时写 `llm.active = 'center-llm'` 与 `center.officialModels.llm`；
    本机 provider 一个都没有、但官方目录可用时**也渲染这张下拉**，否则官方模型没有选模入口。
  - **TTS / STT / 生图**：各自 provider 列表顶部一条**只读官方行**
    （`center-tts` / `center-stt` / `center-imagegen`），行内下拉写
    `center.officialModels.<cap>.model`，选中即 `enabled: true`；官方行不能编辑凭据 /
    Base URL / 模型项，也不能删除。
  - **官方行的出现条件**：`enabled` 为 `true`，**或**该能力的目录 / 镜像 provider 可用 ——
    即使配置被外部改成 `false`，只要目录可用仍有入口选回来。
- **切回本机不改官方选择**：在 AI 模型页选本机模型只改 `llm.active`，官方选择保留，
  仍可作为会话级模型来源；Center 离线或模型被停用时回落本机并在首次回落提示一次。

## 三、添加流程统一为独立弹窗

设置页里五处「添加」以前是页内展开的小表单，与编辑卡混在一起；本版统一改成**模态弹窗**
（`<Teleport to="body">`、`role="dialog"`）。Esc / 点遮罩 / 取消都关闭且**不写配置**，
提交成功才落盘：

- **AI 模型**：工具行只剩「+ 添加 Provider」，删除「保存全部」。弹窗内是预设 chips
  （DeepSeek / OpenAI / 本地兼容）+ provider id / 接口类型 / baseURL / API Key / 模型名与
  必填校验；重复 id 就地提示。提交成功后弹窗关闭并**自动打开该 provider 的编辑卡**，
  继续配置模型列表与高级参数。
- **TTS**：「添加 TTS 模型」弹窗包含 id / 接口协议 / baseURL / API Key / 模型名 / 音色 /
  语气指令 / 语言 / 语速 / 音频格式；接口协议文案统一由 Schema 常量提供（单一来源）。
  提交成功后自动打开编辑卡（继续拉模型列表、试听）。
- **STT**：「添加语音输入模型」弹窗包含五个字段与「接口协议」，切换协议时 baseURL /
  模型名的提示文案随之改写。
- **生图**：「+ 添加生图模型」走同一个添加弹窗，提交成功后自动打开编辑卡。
- **MCP 服务器**：「添加服务器」弹窗包含名称 / 传输方式 / 命令与参数（stdio）或 URL（HTTP）/
  环境变量 / 自定义请求头（仅 HTTP）；名称沿用资源名规则（禁 `.`）且不许重名。
  MCP 没有独立编辑卡，提交成功后列表直接出现新行。
- **空状态口径**：只在「本机列表与官方行都为空」时才显示空状态卡，不再因为官方行存在就
  误判为空。

## 升级说明

直接覆盖安装即可。本版有一条 `v46 → v47` 自动迁移：四类官方模型的 `enabled` 置 `true`，
已选模型保留；如果没有配置 Center，官方模型不会生效（连接器仍由总开关控制）。
Center 地址变为固定值属于默认值变化，存量 `serverUrl` 不迁移，下一次保存或登录时生效；
自托管 Center 用户请改 `CENTER_SERVER_URL` 后重新构建客户端。
