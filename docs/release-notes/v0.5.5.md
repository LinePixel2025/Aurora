# Aurora v0.5.5

本次版本汇总 **v0.5.4 → v0.5.5** 的全部更新：修复插件注册的独立界面（页面型桌面小组件）
在 Aurora 启动后永久空窗、Center 官方语言模型抢占用户默认模型、插件重启后已打开界面不重载；
插件配置与桌面小组件管理改为独立窗口 `plugin-config`。

配置 Schema 保持 **v36**，没有新增迁移；插件清单契约不变。Aurora Center 代码版本线仍独立
（不建 tag、不上传 GitHub Releases），本次双投的仍是桌面安装包的三个更新资产。

## 一、插件独立界面启动空窗修复

- 根因：桌面小组件窗口在 `registerIpc()` 之前创建，渲染层挂载时调用的
  `plugins:list` / `settings:get` 还没有 handler，`ipcRenderer.invoke` 直接 reject；
  渲染层又未捕获、且在订阅 `plugins:changed` 之前中断，页面型小组件因此永久停在
  「小组件暂无内容」。
- 主进程：`WidgetManager` 新增 ready 门，窗口创建推迟到 IPC 注册完成之后；
  `plugins:changed` 改为投递 chat / settings / edge-bar / plugin-config 与全部桌面小组件窗口。
- 渲染层：小组件「先订阅、再加载」，加载失败有界重试并提供「重试」入口；页面型面板 /
  小组件订阅插件变化后自动 reload webview，声明式面板自动重拉 schema。
- 页面型面板并发挂载的地址暂存改为按插件 partition FIFO，避免 A 面板的 URL 被登记给
  B guest 的竞态。
- 实测：隔离真实 userData 启动后，两张页面型桌面小组件都挂上 webview 并显示插件内容，
  主进程日志不再出现 `No handler registered`。

## 二、用户默认模型优先于 Center 官方模型

- `llm.active` 恢复为全局默认的**唯一事实来源**：
  - 设置读取层不再因 Center 官方语言模型开启而改写 `llm.active`；
  - Provider 工厂只有 `llm.active === 'center-llm'` 时才构造官方 Provider，
    并用「选中 → defaultModel → 首个」解析官方模型与目录参数；
  - 会话模型选择器的全局解析顺序同步改为「本机 active 优先，官方只作可选来源」。
- AI 模型页「默认模型」下拉新增「Aurora Center 官方模型」分组：选中官方会同时写
  `llm.active`、`center.officialModels.llm.enabled` 与模型；选本机模型即切回本机。
- Center 页语言模型开关：首次开启（或从该页显式改模型）把默认切到官方；关闭时若当前默认
  仍是官方，回落到首个可用本机 Provider；用户已切回本机时，开关启停不再覆盖该选择。
- 兼容说明：旧配置里「官方启用 + 本机 active」的现场升级后直接按本机 active 生效，
  这正是本次用户诉求；官方仍可作为会话级来源。

## 三、插件重启重载与独立配置窗口

- 重启插件后 `plugins:changed` 全量广播：已打开的页面型面板 / 小组件重载 webview，
  声明式面板重拉 schema；设置页与插件窗口重拉状态并给出「已重启，面板与小组件已刷新」提示。
- 设置 → 插件列表收敛为「总览 + 启停 + 配置入口」；单个插件的配置、桌面小组件显隐与层级、
  权限与扩展点、启用 / 信任 / 重启 / 回滚 / 打开目录 / 日志 / 卸载收进独立窗口
  `plugin-config`（单例、默认 880×760、最小 620×520、关闭 = 隐藏、原生 Acrylic）。
- 配置表单支持脏态、恢复清单默认值、保存成功反馈；插件变化时只重拉元数据，不清空未保存草稿。
- 新增探针 `plugin-config.png`；设置页插件列表探针同步改为验证「配置」入口与不再内联表单。

## 四、兼容性与升级

- 配置 Schema 仍为 **v36**，无迁移；已有配置、会话、插件安装态与小组件布局原样使用。
- 插件清单与插件进程 API 不变，已安装插件无需升级或重装。
- 语言模型默认行为变化见第二节；没有 Center 账号 / 官方目录时完全不受影响。
- 桌面安装包继续双投 GitHub Releases 与 Aurora Center 更新源，三个资产版本保持一致。
- Windows x64、未签名；首次运行 SmartScreen 提示时选择「更多信息 → 仍要运行」。
