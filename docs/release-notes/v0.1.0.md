# Aurora v0.1.0 更新说明

发布日期：2026-09-25 ｜ 安装包：`Aurora-Setup-0.1.0.exe`（Windows x64，未签名）

这一版是**三个方向的成体系增强**：把 ClassIsland 联动从「Aurora 单向读课表」做成**双向**（Aurora 能读课堂状态，也能让 ClassIsland 弹提醒）；把对话里「深度思考 / 工具调用」的展示顺序、归属与动效整体修一遍，并给子代理一个**独立页面**；再统一图标体系与一批动效。

配置 Schema 从 v9 升到 **v10**（新增 `modes.classroom.preClassLeadMinutes`，走迁移链自动补齐，旧配置无需手工改动）。安装包直接覆盖升级即可。

---

## 🏫 ClassIsland 联动升级到 v3（本轮最大的一块）

### 背景：上一版只做了一半

v0.6.0 落地的桥接插件是**单向数据源**：ClassIsland 把课表写成一份本地 JSON，Aurora 只读。
插件 v2 虽然已经会写出「课堂状态快照」（是否在上课 / 当前科目 / 下节课），但那份代码**从未在真机跑过**——机器上装的一直是 9 月 19 日编译的 v1，Aurora 侧拿到的 payload 里根本没有 `status` 字段。

### 桥接插件 v3（`integrations/classisland-bridge/`）

- **课堂状态快照升到 v3**：在原有 `onClass` / `currentSubject` / `nextSubject` / `nextStartTime`
  之外，新增 `currentStartTime` / `currentEndTime` / `nextEndTime`——界面上因此能显示
  「上课中 数学 08:00–08:45」这样的完整时段，而不只是科目名与开始时间。
  取不到的字段一律**不写**（不编造）。
- **新增入站提醒通道**（这就补上了"双向"）：Aurora 原子写一份 `command.json` 到课表文件同目录，
  插件用 `FileSystemWatcher`（600ms 防抖 + 30 秒兜底轮询）读到后，经 **ClassIsland 自己的提醒服务**
  弹出提醒，并把结果原子写回 `command-result.json`（`ok` / `error` / `handledAt`）供 Aurora 校验。
  HTTP 模式则走 `POST /notify`（同一份 JSON 契约）；`GET /schedule` 行为不变。
  新增开关 `enableCommandChannel`（默认开）。
- **命令按 `id` 去重、按时间过期**：同一条命令不会弹两次；`createdAt` 超过 10 分钟的命令直接跳过
  ——避免"重启 ClassIsland 后把上节课的提醒又弹一遍"。
- **修掉一个真机才暴露的缺陷**：ClassIsland 的通知宿主会读 Avalonia 控件的样式属性并做线程校验，
  而命令通道是在**后台线程**触发的（v2 的上课 / 课前提醒恰好在 UI 线程上，所以一直没暴露），
  表现为提醒静默失败、日志里是 `Call from invalid thread`。v3 统一切回 UI 线程发送。
- **修掉插件自身日志全丢的问题**：原来在 `Initialize` 阶段解析 logger，那一刻容器还没就绪、
  解析结果是 null，导致插件所有日志静默丢弃（真机排查时等于睁眼瞎）。v3 改惰性解析。
- 插件版本升到 **3.0.0.0**，插件包 `dist/AuroraClassIslandBridge-v3.0.zip`；
  README 按**实测结果**重写（含数据契约表、命令通道契约、HTTP 路由与错误码、排障条目），
  并修正上一版「可在 ClassIsland 插件设置页调整」的错误说法（插件没有注册设置页，
  `bridge.json` 需手工编辑）。

### Aurora 侧接线

- **课堂状态进感知摘要**：新增 `PerceptionSummary.classStatus`，系统提示词里多一行
  「课堂状态：上课中（数学 08:00–08:45）；下节课 语文 09:20–10:05」——
  **不在上课且没有下节课时整行省略**。AI 因此能直接回答"现在上什么课""下节是什么"，
  而不必自己拿当前时间去推算课表（`timetable` Skill 与 ClassRoom 模式提示词已同步）。
- **主界面右栏「课堂状态」卡**：显示是否上课中、当前科目与时段、下节课科目与时段；
  数据由桥接快照驱动，字段缺失时显示「暂无课堂状态（等待桥接数据）」。
- **Aurora 可以调用 ClassIsland 的提醒**（新增能力，三条入口）：
  - **Agent 工具 `classisland_remind`**：让 AI 把提醒交给 ClassIsland 弹出
    （参数 `body` 必填，`title` / `channel` 可选）。**桥接未配置时这个工具不进工具表**，
    模型看不到它就不会瞎承诺；配好后自动出现，无需重启。
  - **设置页「发送测试提醒」**：ClassRoom → 课程表 → 提醒通道，一键验证链路，
    就地显示成功耗时或失败原因。
  - **IPC 通道 `classisland:notify`**（供上面两条与未来的消费方使用）。
  - 说明：Aurora 的**课前提醒本身仍然只走系统通知**，不会顺手再让 ClassIsland 弹一条
    ——否则会和 ClassIsland 自带的上下课提醒叠成两条。
- **课前提前分钟数可配**：此前「下一课开始前打开科目文件夹」的窗口恒为 5 分钟，现在由
  `modes.classroom.preClassLeadMinutes`（1–30，默认 5）决定，改完**立即生效**（每次检查即时读取）。

### 真机验证（不是"仅编译通过"）

插件 v3 已编译（0 error / 0 warning）、装进本机 ClassIsland **2.1.0.1**、重启并实跑验证：

- 日志确认插件以 `3.0.0.0` 被加载、提醒提供方与「Aurora 提醒」渠道注册成功；
- `schedule.json` 内嵌 `status.version = 3`（含当前课的起止时间），`status.json` 同步写出；
- **提醒真的弹出来了**（日志 `处理通知请求` + 屏幕上可见的覆盖层提醒，两种渠道都试过），
  文件模式端到端耗时约 **690ms**，HTTP 模式 `POST /notify` 返回 `ok: true`；
- 过期保护实测：把 `createdAt` 设成 20 分钟前的命令被跳过、不弹、不写回执；
- Aurora 侧解析器对拍真机产出的 JSON：29 节课、零告警、status 各字段正确。

> **要注意的两点**：① ClassIsland 的覆盖层提醒**会排队**（每条约 10 秒），连续发送时第 2 条的
> 显示时间会晚于处理时间，这属于 ClassIsland 通知服务的行为；② 插件与 ClassIsland 自带的
> 「上下课提醒」内容相近，同时开启会看到重复提醒，建议只用其一。

## 💬 对话展示：深度思考与工具调用的顺序、归属与动效

### 修掉两类真实的"顺序错乱"

| 现象 | 根因 | 现在的处理 |
|---|---|---|
| 工具卡跑到别的回复里 / 挂到消息列表末尾 | 事件**没有任何序号**，渲染层只能"来一条建一条、新建就 push 到末尾" | 每个事件带 `seq`（会话内单调递增，由主进程统一分配），渲染层**按序号插入到正确位置** |
| 多轮工具调用时，第二条回复带上了第一轮的**思考全文** | 思考增量没有消息 id（那轮消息要等流结束才落盘），渲染层只能按请求全局累积 | 事件带 `round`（第几轮工具调用），渲染层按「请求 + 轮次」分桶，再由同轮的文本 / 工具事件把思考绑到正确的消息上 |
| 请求结束后界面还在继续长内容 | 请求 id 过滤在"当前无活动请求"的窗口期形同虚设 | 已结束的请求被记下来（最近 64 条），**其迟到事件一律丢弃**；本地主动停止也会立刻标记 |
| 历史水合把正在流式的消息"换掉"，输入指示与工具卡闪一下甚至消失 | 水合是「服务端快照整体替换本地」 | 改为**按 id 合并**：内容取更长的一份，本地的流式状态（进行中 / 错误 / 附件 / 思考）优先保留 |

新增的内核单测覆盖：事件序号单调递增、思考与同轮文本 / 工具卡同号、子代理进度事件早于工具终态卡片。

### 动效

- **思考块**：流式期间卡头有一道扫光、正文尾部有光标，块内自动跟到最新一行；
  结束后收起为「已深度思考」摘要行（原有口径不变）。
- **工具卡**：运行的卡片叠一层低对比度扫光；状态翻到完成 / 失败时状态点弹一下（一次性）；
  卡片进场上浮淡入，同一轮的第 2、3、4 张依次错开 40 / 80 / 120ms。
- **Agent 正文**：除末尾光标外，最后一行有**渐隐的"湿润边缘"**，流式结束即变清晰。
  刻意**不做逐字打字机**：正文是 `v-html` 渲染的 markdown，Vue 对 `v-html` 不做 DOM diff，
  按节点挂动画会在每个字符块上重放（快速流式时整块停在半透明），按帧做真打字机则要
  每帧重新解析 markdown——遮罩方案既有"还在写"的观感，又零额外开销。
- 循环类动画（旋转指示器 / 流式光标 / 三点等待）统一走新的时长令牌
  （`--dur-spin` / `--dur-caret` / `--dur-bounce`），不再散落写死的 1s / 1.1s / 1.4s。

## 🤖 子代理（SubAgent）独立页面

此前 `task` 工具派生的子代理在界面上只有主对话里一张折叠卡：**看不到过程**（子循环的文本与工具调用不外传），**也读不到产出**（报告全文只回传给主代理）。现在：

- **实时进度上报**：子代理每走一步（一段文本、一次工具调用开始 / 结束）就上报一份快照，
  经事件流实时推到界面——卡片上能看着它"长"出步骤，不必等它跑完。
- **工具卡展开体 = 运行轨迹**：进度条 + 步骤时间线（每步用的是哪个工具、拿到什么结果）+ 报告。
- **左栏新增固定项「子代理」**（带运行数角标，有在跑时用强调色）：把**主区**切到子代理页面，
  集中展示本会话的全部运行——状态、耗时、工具调用数、每一步在干什么、最终报告，
  任务指令可折叠查看。它不是会话：切过去**不动**当前会话、不清空消息，输入区照旧，
  随时切回来（页头「回到对话」或点任意会话）。
- **重启后仍可回看**：子代理快照随工具卡一起持久化在会话文件里，历史运行不会因为关掉窗口就消失。
- 子代理的对话过程**依然不落会话存储**（上下文隔离是它的设计目的），页面上看到的是这份快照。

## 🎨 图标体系与其它动效

- **引入 [lucide](https://lucide.dev) 图标库**（`lucide-vue-next`，ISC 许可）：渲染层此前全是手写内联 SVG
  与字形字符（`›` / `▸` / `↓` / `×`），四个窗口的线宽与视框各不相同。现在统一经
  `renderer/shared/icons.ts` 具名再导出（只登记用到的，构建时摇树），四个窗口、设置页导航、
  折叠箭头、窗口按钮、朗读 / 复制按钮全部换成同一套描边风格；**工具卡按工具名给语义图标**
  （读文件 / 跑命令 / 搜网页 / 派子代理一眼可分，未知工具退到扳手、MCP 退到拼图）。
- 设置页导航图标重挑：通用 / 模式 / AI 模型 / 语音 / 智能与工具 / 系统各有语义更贴的图标。
- 子代理页面的进度条带滑动块、步骤逐条浮现；左栏角标在运行时有出现动画。
- 提示条面板的操作按钮、任务清单的状态圈（进行中为旋转弧、完成为实心对勾）同步换新。

## ⚙️ 配置与兼容性

- **Schema v9 → v10**：新增 `modes.classroom.preClassLeadMinutes`（整数 1–30，默认 5）。
  迁移是幂等的、只补缺失键、不覆盖你已写的值；旧配置文件升级后无需任何手工操作。
- 桥接插件的 `schedule.json` **结构版本仍是 1**（只在内嵌的 `status` 里加了字段），
  Aurora 对多余 / 缺失字段都宽容——旧版插件继续可用（只是没有课堂状态与提醒通道）。
- 设置页「模式 → ClassRoom」新增「提前分钟数」与「提醒通道」两处，**只在课表来源为
  ClassIsland 且已配置课程时出现**（未满足条件时整块不渲染，不是灰掉）。

## 🐞 顺带修掉的问题

- **切到 ClassIsland 后课堂状态卡一直空着**：状态快照只在「感知摘要组装」时才顺手刷新，
  而右栏卡片是独立轮询 `classisland:status` 的 —— 刚把课表来源切过去时新 provider 还没读过任何
  数据，卡片会停在「暂无课堂状态」直到下一轮。现在该接口在缓存过期（15 秒）时自己重读一次。
  截图探针正是这样发现的（第一版拍到的就是一张空卡）。
- **历史读不出来**：把工具卡从存储形状转成界面形状时直接读 `arguments`，而夹具 / 早期数据里
  只有 `input`，异常会让整份 `chat:history` 失败——界面表现为**打开就是空白**。
  截图探针抓到并已修（含回归测试）。
- 设置页「模式」页的 ClassRoom 配置区在 720 高的窗口里量不到新字段（截图证据缺失），
  截图脚本现在会把新增控件滚进视野再拍。
- 桥接插件 README 里「插件设置页可调」与「安装路径」两处与实现不符的说法已改正。
