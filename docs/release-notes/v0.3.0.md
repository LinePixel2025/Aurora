# Aurora v0.3.0 更新说明

发布日期：2026-10-01 ｜ 安装包：`Aurora-Setup-0.3.0.exe`（Windows x64，未签名）

这是 v0.2 系列之后的**第一个大版本**，跨了 **71 个提交**，按主题分成六块：
**会话三分（左栏重构）**、**执行轨迹与自动跟随**、**图片进模型 + Responses API**、
**生成参数随模型走**、**全仓审查后的一轮稳定性与安全大修**、**一批界面细节**。
另有 **Aurora Center 服务端同步更新**（认证限速、CLI 停服保护等，需与桌面端同版本上线）。

**有两处配置迁移**：Schema 从 **v21** 升到 **v23**（v21 → v22 加图片输入与接口类型，
v22 → v23 把生成参数下沉到模型级）。覆盖安装即用，已有设置与凭据一个都不会被改。

---

## 🗂️ 一、会话三分 —— 左栏按「工作边界」重新组织（新）

这是本版最显眼的变化。主界面左栏的会话列表从一条平铺的列表，拆成三个分区，
**每个分区的会话落在各自不同的工作目录、享受各自不同的权限边界**：

1. **项目对话**：绑定到某个项目的会话。每个项目分组标题旁带一个 `+`，
   在该项目根下开新会话；项目根就是这个会话的权限边界（根内免确认、越界逐次确认）。
2. **工作目录对话**：不绑项目、但属于「工作」空间的会话，边界取激活模式的工作目录
   （当前是 Work 模式的 `modes.work.workspaceDir`）。
3. **Agent 对话**：默认分区。**目录固定为 `桌面\Aurora`**（刻意不做成配置项），
   历史会话与顶部「新对话」按钮都落在这里。

配套的三件事：

4. **每个会话都有边界根了**。以前「没配项目 = 没有任何边界 = 完全不弹确认卡」，
   现在未标记的历史会话会归入 Agent 分区、以 `桌面\Aurora` 为边界根 ——
   **权限比过去更紧，这是有意的行为变化**（旧语义已不存在，见下方「升级与兼容」）。
5. **项目分组可折叠**，分区标题醒目化，项目卡有了入场 / 收拢动效；
   修掉了「绑定的项目已被删除」时会话从列表里整体消失的问题（现在归入 Agent 分区显示）。
6. **真删除会话**：会话行的删除是**真删**（此前只归档），带二次确认；
   删除会跨窗口同步（其他窗口里的同一会话立刻消失）。运行中的任务不会被删掉。
7. **设置页新增「会话管理」页**：项目管理从「通用」页迁入这里，并加上完整会话列表
   （归档 / 两步删除）。

## 🧵 二、执行轨迹与自动跟随

8. **「思考 + 工具调用」合并成一条执行轨迹**：此前思考块与工具卡是两种各自为政的卡片，
   一条消息里的过程被拆得七零八落。现在它们收进同一个**轨迹容器**：左侧一条时间线、
   每个节点是软胶囊样式、整体限高内部滚动、展开用 grid 动画。
9. **任务完成后轨迹自动折叠**，只留一行可点开的摘要，不再一直占着消息区。
10. **自动跟随三处修复**（这一块是用户连续报障后逐个钉死的，都对真实滚轮做了 CDP 级复现）：
    - **「跟丢」**：跟随状态只由**真实输入**关闭，不再被程序自己的滚动事件误判；
      容器被重建时观察者会自愈，另加一条心跳兜底。
    - **滚轮小步长上滚被吞**：从贴底状态往上滚一格，此前会被「吸底对齐帧」原样抹回去，
      表现为滚轮按了没反应；现在判定由真实输入发起、并在一个 250ms 窗口内按**之后**的读数重判。
    - **底部上滚**同样不再被对齐帧抹掉。

## 🖼️ 三、图片进模型 + Responses API（配置 Schema v22）

11. **图片可以发给模型了**：拖进对话的图片按扩展名与文档分开，作为多模态 content parts
    下发给模型；附件 chip 直接显示缩略图。
    - 能力开关在 **每个模型**上（`支持图片输入`，**出厂关闭**）—— 关掉时图片会降级成
      一行「未读取」说明，而不是硬发出去（给不支持视觉的模型发图会被服务端 400）。
    - 会话历史**只存路径、不存 base64**，跨轮次续聊时按路径重新读盘；
      单张图读取上限 2 MiB。
12. **新增 Responses API 协议**：`接口类型` 可选 `openai-responses`（走 `/responses`，
    `store: false`），与 chat-completions 共用同一层超时 / 取消 / 退避重试。

## 🎛️ 四、生成参数随模型走（配置 Schema v23）

13. **「上下文窗口 / 支持图片输入 / 思考等级」从供应商级下沉到模型级**：
    现在在设置页「AI 模型」里，**每个模型行内有一枚「参数」开关**，
    展开后调的是**那个模型自己**的参数。此前这几项挂在供应商上，
    跟「模型列表里当前选中哪个」没有关系，换个模型参数不会跟着变。
14. **彻底移除 `temperature`**：配置里删掉、界面里删掉、**请求体里也不再下发**
    （对齐主流 Agent 的做法；不是内部固定值，也不是保留成死字段）。
    分类管线自己写死的 `0.2` 不受影响。

## 🛡️ 五、稳定性与安全大修（全仓审查后的 39 条）

本版把一份覆盖全仓约 9 万行的审查报告里 P0 / P1 / P2 共 **39 条**全部修完，
另有审查后回归修复 6 条。挑对你有感知的说：

15. **Center 服务器不再被一条畸形消息打死**（P0，远程 DoS）：WS 入站加了形状校验、
    单帧上限与统一异常兜底；回执按连接隔离，不能跨连接伪造或错投。
16. **「停止」按钮真的能停了**（P1）：流式请求的 `AbortSignal` 此前没有正确传到传输层；
    顺带修掉每个数据块都重建解码器导致的**中文乱码**。
17. **退出不再出现半关停僵死**（P1）：退出协议改成先挡新请求再收尾，
    收尾落盘不会被截断。
18. **工具消息配对修复**（P1）：历史窗口裁剪会切断 assistant 的 tool_call 与 tool 结果，
    导致下一轮 400；`quick` 会话与自动化、Center 来源的 job 也不再被判成非法 origin。
19. **MCP 凭据丢失修复**（P1）：服务器名或 provider 名含 `.` 时凭据永远存不进去
    （MCP 的 env 明文会直接丢）；现在改为**逐段解析**路径、候选择优。
    同时给 MCP 服务器名 / provider id 加了长度与字符集约束 `/^[A-Za-z0-9_-]+$/`（禁用 `.`），
    **存量含点的名字会在启动时被规整改名（数据不丢）**。
20. **快照回滚也过项目根边界**（P2）：`restoreSnapshot` 此前注释声称有守卫、实现里没有。
21. **免确认命令模式收紧**（行为变化，见下）：`git *` 这类模式从「放行任意拼接的整串」
    变成「**每一段都命中才放行**」；含 `$( )` / 反引号 / `&&` / `||` / `|` 等语句构造时
    **整体不免确认**，退回弹卡。
22. **`modes.work.workspaceDir` 对 AI 转只读**：它同时是权限边界根，让 AI 改它等于自我提权；
    你在设置页里照常可改。同时 `tts` / `stt` / `imagegen` 三组对 AI 放行（凭据子路径仍拒绝）。
23. **Center 认证端点按源 IP 限速**（login 5 次/60s、register 10、deviceStart 30，超限 429），
    口令哈希改为异步 scrypt（不再阻塞事件循环）。
24. **其余一批**：设置页关闭 Center 变成可逆暂停（再启用立即重连）、轮换 MCP 凭据值也会触发重连、
    daily 自动化错过补偿改为跨进程幂等、窗口几何落盘加 250ms 去抖、
    `web_fetch` 限时限量、技能目录监听补上 error 监听（此前出错静默）。

## ✨ 六、界面细节

25. **权限下拉的长说明文字不再横向溢出**（根因是继承了父容器的 `white-space: nowrap`），
    改为在卡片内折行，同时保留「有项目 / 无项目」两态语义。
26. **上下文详解卡精简为三行**（本轮输入 / 上下文窗口 / 模型行）。
27. **输入区去掉常驻的「Enter 发送」字样**（键位说明只留在输入框的悬停提示里），
    不再挤压模型与思考下拉。
28. **生图模型空状态补上「+ 添加生图模型」主按钮** —— 此前工具行被空态门控，
    形成「没有模型 → 看不见添加按钮 → 永远加不了模型」的死胡同。
29. **设置页「通用」页删掉会话管理说明句**（内容已随第 7 条迁入「会话管理」页）。

## 升级与兼容

### 配置迁移（自动，两步）

- **v21 → v22**：为每个 provider 补 `vision: false`（图片输入出厂关），并归一 `type` 字段；
- **v22 → v23**：把 provider 级的 `reasoningEffort / contextWindow / vision / temperature`
  搬到 `modelParams[当前模型]` 下，然后删除这几个 provider 级字段。
  `model` 为空串时写入空对象；`temperature` 直接丢弃（它已不再是配置项）。
- 你已写的值原样保留，凭据不变。`pnpm verify` 的迁移条数断言随之变为 23 条。

### 需要留意的行为变化

1. **默认工作目录变了**：未绑定项目的历史会话归入 **Agent 对话**分区，
   工作目录为 `桌面\Aurora`，权限边界也随之解析 —— 不再是「无项目 = 完全不弹卡」。
2. **免确认命令模式收紧**：含语句构造（`&&` / `||` / `|` / `$( )` / 反引号）的命令
   一律回到确认卡；多段命令需要**每段**都命中你配置的模式。
3. **含点的 MCP 服务器名 / provider id 会被改名为不含点**（启动时自动规整，数据不丢）。
4. **会话删除是真删**（此前是归档），不可撤销，操作有两步确认。
5. **`temperature` 彻底不存在**：配置、界面、请求体三处都删了；如果你的网关依赖它，
   请在网关侧设默认值。

  ｜ `pnpm build` ✓ ｜ `pnpm verify` **26/26**（`version=23`、迁移 `23/23`）

### 已知限制（未变）

- 安装包**未签名**，Windows SmartScreen 会提示；仍**没有 OS 级沙箱**
  （`run_command` 以当前用户权限运行，项目根边界是应用层的两道校验）。
- 图片输入**未对着真实视觉模型跑过**（本轮验证用的是桩与单测夹具）；
  Responses API 同样只经本地桩验证。
- Code Mode 仍为占位实现；多语言、ARM64 / 便携版、macOS / Linux 未开始。
- `pnpm format:check` 与 `pnpm lint` 在本机（autocrlf）存在改动前即有的存量报错，与本次改动无关。
