# Aurora v0.4.2

本次版本是从 **v0.4.1** 到 **v0.4.2** 的完整更新，重点是重构 Office
结构化工具链：用包内固定版 OfficeCLI 替代旧 `@office-open` 拼接实现，
补齐元素级编辑、结构化校验、渲染回看与页面图 PDF 导出。

## 一、Office 工具链重构

- 引擎固定为 **OfficeCLI v1.0.153（Windows x64）**，SHA256 固定校验；
  安装包内置单文件二进制，不依赖本机 Word / Excel / PowerPoint。
- 运行期强制关闭 OfficeCLI 自动更新、自动安装、技能安装与 resident 模式，
  所有调用使用 argv 数组、`shell:false`，不静默下载、不经过 shell。
- 移除 `@office-open/docx|xlsx|pptx` 运行时依赖，新增 `pdf-lib` 负责 PDF 合成。

## 二、七件 Office 工具

- `office_read`：按 summary / text / element / query / issues / validate
  读取结构、稳定元素路径、问题和校验结果，编辑前仍强制先读。
- `office_help`：查询 OfficeCLI 的可用元素、属性名、取值与示例，
  减少模型猜测 props 造成的失败。
- `office_create`：支持空白创建、`{{placeholder}}` 模板合并，以及 OfficeCLI
  `add/set/remove/move/swap` batch 命令初始化内容。
- `office_edit`：用元素路径和 batch 命令编辑已有文档，不再使用上一版弱类型
  `operations` DSL。
- `office_render`：按页 / 幻灯片 / 工作表生成 PNG 或 HTML，截图会直接回填给
  模型做视觉核对。
- `office_pdf`：逐页 / 逐表截图后用 `pdf-lib` 合成 PDF；文字不可选择，但页数
  与视觉版式稳定，不依赖 OfficeCLI exporter 插件。
- `office_raw_edit`：单独暴露 raw XML，只有显式确认后才可用；普通编辑不会自动
  降级到 raw，也不得在结构化失败后自动改用 COM。

## 三、安全与原子性

- Office 写入继续保留原路径边界、文件锁检查、先读后改、确认卡与写前快照。
- 写入使用保留正确扩展名的同目录临时文件：先 OfficeCLI batch，再 `validate`，
  成功后原子替换；校验失败不碰源文件。
- 写入后自动检查 OpenXML 校验，并附带 `view issues` 调性警告。
- 只读档只保留 `office_read` / `office_help` / `office_render` 等 safe 工具；
  create / edit / pdf / raw 等 confirm 工具整件摘除。

## 四、提示词、设置页与文档

- Work Mode 与 `office-work` Skill 改为“读取 → 查询 schema → batch 编辑 →
  校验 → 渲染回看”的 OfficeCLI 工作流。
- Agent 设置页补充新工具门控与只读档展示；工具图标和中文标签同步更新。
- docs/02 / 05 / 06 / 08 / 09 与项目记忆同步到新引擎口径。

## 五、发布与打包

- 新增 `scripts/fetch-officecli.mjs`，在 dev / package 前按固定版本与 SHA256
  准备二进制；`extraResources` 把引擎与 Apache-2.0 许可证打进安装包。
- 安装包内同时保留 `officecli/VERSION.txt`，运行时版本不匹配会停用整组 Office
  工具，不静默使用未知版本。

## 七、兼容与限制

- Windows 安装包为 x64，**未代码签名**，首装会出现 SmartScreen
  「未知发行者」提示：点「更多信息」→「仍要运行」即可。
- 配置 Schema 仍为 **v30**，本版本没有配置迁移。
- 旧格式 `.doc` / `.xls` / `.ppt`、宏和复杂 COM 能力仍只作为显式兜底，
  不会在结构化工具失败后自动回落。
- PDF 导出采用页面图合成，文字不可选择；复杂模板的矢量 PDF 导出不在本版本
  的强承诺内。
