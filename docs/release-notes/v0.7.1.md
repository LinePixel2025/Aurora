# Aurora v0.7.1

本次版本汇总 **v0.7.0 → v0.7.1** 的全部更新。主线是**智慧提醒延迟投递**（Schema v44）：
免打扰期结束后摘要可延迟 N 分钟再投，默认 0 = 立即（与 v0.7.0 行为逐字一致）；同批包含
桌面小组件 desktop 层置顶重申修复，以及 Center 鸿蒙遥控台接入 API（Center 0.7.0，版本线独立）。

本版配置 Schema **v43 → v44**（一条自动迁移，幂等且不覆盖用户已写值）；插件清单与宿主 API
仍为 **v1**（无变化）；Aurora Center 服务器自上一桌面 tag 以来已升级到 **0.7.0**（鸿蒙遥控台
接入 API，见第三节；Center 版本线独立，本版不再另升）。已有配置 / 会话 / 插件 / 自动化数据全部保留。

## 一、智慧提醒延迟投递（主线，Schema v44）

- **新设置 `notifications.smartDelayMinutes`**（0–120 分钟，默认 0 = 立即）。设置 → 提醒 →
  智慧提醒区组新增「结束后延迟投递」滑杆（0 显示「立即」，总开关关闭时置灰）；字段保持扁平，
  天然被 `notifications.*` 可写通配覆盖（AI 可照用户要求调整），`settings-hint` 清单同步。
- **语义**：免打扰期结束（时段出窗 / 下课 / 总开关或时段被清空）且队列非空时记下结束时刻，
  延迟 N 分钟后再结算投递（30s 评估节拍，误差 ±30s）；到期时刻 = 结束时刻 + **当前**设置值
  （live 重算：中途改延迟按新值顺延，改 0 立即投）。
- **延迟期间再次进入免打扰** → 取消待投、继续攒，出窗后按新的结束时刻重新计时（新旧队列合并结算）；
  **延迟期间关总开关**仍到期投递（不丢提醒）；延迟期间新到的提醒照常逐条投递（不入队）。
- **跨重启**：结束时刻落盘队列文件（`pendingSince`），重启已到期 → 补结算；未到期 → 到点投；
  仍在窗内 → 取消待投继续攒。旧版队列文件（无 `pendingSince`）保留「启动即补结算」补偿。
- **队列文件** `userData/smart-reminder-queue.json` version 1 → 2（新增 `pendingSince`；
  读取对 v1 宽容，缺省按无待投）。结算 / 再次入窗时清除该键。
- **诊断**：`SmartReminderDiagnostics` 新增 `pendingSettleAt`（待投摘要预计投递时刻），
  冒烟据此断言「期结束未立即结算」与「改 0 立即结算」（+2 条断言）。
- 文档：[07 §4](../07-ui-spec.md)、[08 §1 / §1.2 / §2 / §6](../08-settings-onboarding.md)。

## 二、桌面小组件 desktop 层置顶修复

- owner 写入（`SetWindowLongPtr GWLP_HWNDPARENT`）会让 Windows 重排窗口带区、剥掉
  `WS_EX_TOPMOST`；desktop 层的异步 PowerShell 操作可能迟于层级切换落定，把刚设好的清单置顶
  静默清掉。attach 迟到分支与 detach 落定后均按当前层级**幂等重申**置顶。
- 注：全屏游戏运行期间系统本身压制其它窗口置顶，冒烟置顶断言需在无游戏环境跑。

## 三、Center 鸿蒙遥控台接入 API（Center 0.7.0，版本线独立）

- **持久会话**：login persistent 扩展（90 天、重启存活、每用户 ≤10）、refresh 轮换（旧令牌即失效）、
  logout 级联清推送登记。
- **推送**：登记 / 偏好 API + Push Kit v3 发送器（服务账号 JWT、失效 token 自动剔除、harmony 在线抑制、
  载荷最小化、每用户限速）。
- **待办快照** `GET /api/pending`（确认卡登记；网页端不回放行为不变）；WS `web.hello` 连接标识；
  REST 快捷批复 confirm/ask resolve（通知栏动作直达）。
- **管理端**：会话查看 / 吊销、推送配置（私钥只写不回显）；删户级联清理。
- docs/12 §15 同步；附鸿蒙客户端新项目开工提示词与设计提案（docs/proposals/）。
- 口径：Center 自身更新**不打 tag、不上传 GitHub Releases**（docs/09 §7）；本节为相对上一桌面 tag
  的提交汇总，Center 换装按 `packages/center/deploy/README.md` 独立执行。

## 四、配置与数据迁移

- `v43 → v44`：为已有 `notifications` 补 `smartDelayMinutes: 0`（0 = 期结束立即结算，
  升级后行为与 v43 逐字一致）；用户已写字段原样保留。迁移链 v0 → v44 共 **44** 条，`pnpm verify` 断言同步。
- 智慧提醒队列文件 version 1 → 2（见第一节）；损坏 / 旧版均按宽容路径重建，不丢已投递提醒。

- `smartDelayMinutes` 默认 0：不设置的用户投递时机与 v0.7.0 完全一致。
