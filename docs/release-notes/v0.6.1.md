# Aurora v0.6.1

本次版本汇总 **v0.6.0 → v0.6.1** 的全部更新。主线只有一个：**适配阿里云 DashScope 语音模型
的下架潮，修复朗读（TTS）全面失效**。2026-10-31 起，「千问AI平台」网关把模型目录从 518 缩到
371：旧 `qwen-tts` / `qwen-tts-latest` / `qwen3-tts-plus` 一律下架（请求回 `Model not exist`），
`qwen-audio-3.x-tts-*` 与 CosyVoice / Sambert 系列依旧只走 WebSocket 实时；叠加部分用户把
LLM 栏习惯的 `/compatible-mode/v1`（或少了 `/v1` 的 `/compatible-mode`）baseUrl 粘进了 TTS
供应商，旧版端点构建器不容忍这些尾巴，拼出不存在的路由 —— 两层叠加表现为**每次朗读都 404**。
本版把这两层都根治，并让「平台下次再下架模型」从「又失效了」变成**自动回退 + 设置页可见**。

本版**不改配置 Schema**（仍为 **v39**，无迁移）、**不改插件清单与宿主 API**（仍为 **v1**），
已有配置 / 会话 / 插件 / 自动化数据全部保留；Aurora Center 服务器**不随本版升级**
（仍为 0.5.2，版本线独立，本版无 Center 代码改动）。

## 一、TTS（朗读）：端点粘尾巴容忍 + 模型级失效自动回退

- **端点构建容忍四种粘尾巴**（`apps/desktop/src/main/tts.ts` 的 `dashscopeEndpoint()`）：
  baseUrl 尾上粘着 `/compatible-mode/v1`、`/compatible-mode`、`/api/v1`、`/api` 时，
  **整段换成完整原生路径**再拼 `/services/aigc/multimodal-generation/generation`。
  DashScope 原生路由只挂在服务根的 `/api/v1` 下，`…/compatible-mode/services/...` 一律 404
  —— 这是本轮线上 404 的直接根因。裸域名、Center 网关 base（`…/api/model-gateway/tts`）
  行为不变或更优。
- **模型级失效自动回退**：dashscope 合成遇到 404 + `Model not exist`（模型已下架）或
  400 + `url error`（模型不在 HTTP 端点族）时，**自动改用 `qwen3-tts-flash` 重试一次**
  —— 只换模型，音色等其它配置不动（`qwen3-tts-flash` 是当前网关与官方
  `dashscope.aliyuncs.com` 都实测 200 的唯一 HTTP 合成模型，内置音色 Cherry / Serena / Ethan
  等可用）。重试成功：正常返回音频，并**把该 provider 的 `model` 字段写回设置**
  （`settings.mutate()`，设置页同步可见，下次合成不再多付一次失效请求）；重试也失败：
  报一条同时带「原模型为何不可用」与「备用模型失败原因」的中文错误。
- **回退边界**：鉴权（401/403）、限流（429）、服务端错误（5xx）与网络异常**不触发回退**
  （换模型也不会好）；`openai-compat` 类型**不做**模型回退（各网关模型空间不同，
  静默换模型没有依据）；配置模型本身就是 `qwen3-tts-flash` 时不重复重试。
- **错误提示更新**：404 的 dashscope 自查提示改为「请检查 baseURL 主机名与网络可达性；
  模型已下架（响应含 Model not exist）时换用 qwen3-tts-flash」；400 `url error` 的提示改为
  「该模型不走 HTTP 合成端点（qwen-audio-3.x-tts / CosyVoice / Sambert 是 WebSocket 实时
  专用），请换用 qwen3-tts-flash 或检查 baseURL」。
- **设置页无需任何迁移操作**：升级后保持原配置直接点朗读即可 —— 旧 baseUrl 会被容忍、
  下架模型会触发回退并把模型写回 `qwen3-tts-flash`。

## 二、STT（语音输入）：同款端点容错

- `stt.ts` 的 `dashscopeAsrEndpoint()` 与 TTS 侧对齐：`/compatible-mode/v1`、
  `/compatible-mode`、`/api/v1`、`/api` 尾巴一律整段换成完整原生路径。此前 STT 侧已容忍
  `/compatible-mode/v1`，本版补上少 `/v1` 的残缺形态。
- STT 的 DashScope 原生协议**不受本轮模型下架影响**：`qwen3-asr-flash` 在官方端点实测仍可用
  （鉴权与模型解析正常）。模型列表里选 `qwen-audio-3.1-asr-flash` 等兄弟模型仍需注意它们
  与 `qwen3-asr-flash` 的请求参数形态不同（与此前版本一致，本版未改）。

## 三、附带修复：dashscope 型 Center 官方 TTS 的路由

- 桌面端为 dashscope 类型的 Center 官方 TTS 供应商构建的请求 URL 此前是
  `…/api/model-gateway/tts/services/aigc/multimodal-generation/generation`，而 Center 网关
  的 `routeKind` 只接受 `/audio/speech` 或 `/api/v1/services/...` —— **该形态必然 404**。
  本版端点构建改为拼完整路径后，桌面发给 Center 的 rest 变成
  `/api/v1/services/aigc/multimodal-generation/generation`，与 Center 路由表匹配，
  且 Center 侧 `joinUpstream()` 会正确去重上游 `/api/v1`。**Center 服务器代码零改动、
  无需换装。**

## 四、兼容与迁移

- **配置 Schema 仍为 v39**：无新增 / 修改字段、无迁移；TTS 供应商的 `model` 字段会在
  自动回退成功后被写为 `qwen3-tts-flash`（普通配置值变更，不是 Schema 变更）。
- **插件清单 / 权限 / 宿主 API 仍为 v1**：已有插件无需修改。
- **Aurora Center 服务器仍为 0.5.2**：版本线独立，本版不换装、不建 tag、不上传 GitHub；
  桌面安装包照常上传 Center 更新源（双投）。
- 现有配置、会话、插件、自动化数据全部保留（`%APPDATA%/Aurora` 不在安装目录内）；
  升级路径与 v0.6.0 相同（Center 源优先，GitHub Releases 回退）。
- 已知边界（与 v0.6.0 一致）：复刻音色（`longanlufeng` / `loongstella` 等声音复刻 id）
  仍不被 HTTP 合成端点接受 —— 复刻音色要在朗读里可用，得等平台侧的非实时复刻模型或
  Aurora 支持 WebSocket 协议。
