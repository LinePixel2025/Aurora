# Aurora v0.2.0 更新说明

发布日期：2026-09-27 ｜ 安装包：`Aurora-Setup-0.2.0.exe`（Windows x64，未签名）

这一版的主题是 **「把 Aurora 搬进浏览器」**：全新的 **Aurora Center**（独立服务器 + 网页控制台 +
CLI）让任何浏览器都能远程使用你机器上的 Aurora——远程开会话、收回答、收文件、改开关、切模式；
同时带来两项 **Agent 能力增强**：对话创建自定义技能（`create_skill`）与模式能力对齐。

配置 Schema **v15 → v16**（新增 `center` 分组），覆盖安装时自动迁移，配置 / 会话 / 凭据全部保留。

---

## 🌐 一、Aurora Center：网页控制中心

### 它是什么

一个**独立运行的小服务器**（`packages/center`，纯 Node，Windows / Linux 都能跑）。
安装了 Aurora 的桌面端作为**客户端**主动连上它（出站连接，本机不开任何入站端口）；
之后你在任何浏览器里登录 Center，就能看到你的机器并远程操作。

```
浏览器 ──登录/控制──▶ Aurora Center 服务器 ◀──出站 WebSocket── 桌面端 Aurora
                        （数据目录 ~/.aurora-center）
```

### 快速上手（三步）

1. **服务器**（任一台内网 / 公网机器，Node ≥ 18）：

   ```
   aurora-center init      # 建数据目录 + 首个管理员（初始口令只显示一次）
   aurora-center start     # 默认 0.0.0.0:8787
   aurora-center token create --user <你的用户名>   # 生成配对令牌（只显示一次）
   ```

   更多子命令：`users add/list/passwd/remove`、`token list/revoke`、`status`、`update --check`。

2. **桌面端**：设置 → **Aurora Center** 页 → 填服务器地址 + 粘贴配对令牌 → 开启连接。
   状态卡会实时显示在线 / 离线 / 错误。

3. **浏览器**：打开 `http://<服务器地址>:8787` 登录即可。

### 能做什么

- **远程会话**：在网页上对你的机器发消息（**单独开一个会话**，`center-` 前缀），Aurora 的
  回答实时回流——正文流式、思考折叠、工具卡、错误提示，与本地主界面同一套体验。
  远程会话在桌面端主界面的历史里**同样可见**，可以本地接手继续聊。
- **远程收文件**：在远程会话里让 Aurora「把 xxx 发过来」，它用新增的 `center_send_file`
  工具上传（**逐次确认**，和写文件一样会弹卡），网页上直接出现下载卡。
- **远程配置**：远程切换客户端**模式**（课堂 / 工作 / 代码）、开关 Agent 的电脑操控工具
  （总开关与文件 / 检索 / 打开路径 / 终端四个子开关）。
- **用户与管理员**：普通用户只见**自己名下**的客户端（配对令牌归属决定）；**管理员可见并可
  控制全部客户端**（跨属主），另可管理用户、重置口令、吊销令牌、解除客户端登记。

### 安全边界（刻意的设计，不是遗漏）

- **远程配置走客户端白名单**：只有「模式」与「Agent 工具开关」可远程改。
  **权限档位、免确认命令模式、项目、循环预算、写前快照等一律不可远程改**——
  那等于把确认闸门交给远端。
- **三个本地许可开关**（远程会话 / 远程配置 / 文件发送）在桌面端设置页随时可关；
  关掉后 Center 的对应命令会被本机直接拒绝（网页端如实显示原因）。
- **`center.*` 整组对 AI 只读**：AI 的 `set_setting` 不能自行启用 Center 或改连接目标——
  连接目标是数据外发通道，这个决定只能由你做。
- **敏感工具确认弹在客户端本机**：远程会话里 AI 要写文件 / 跑命令时，确认卡仍弹在你的
  桌面屏幕上；远程端会看到"正在等待本机确认"。**不做远程代批准**。

## 🧩 二、Agent 能力增强

### create_skill：对话创建你自己的技能

对 Aurora 说「帮我做一个 xxx 的技能」，它会收集名称、触发场景与指令正文，按内置技能同款
格式写入你的用户技能目录（`%APPDATA%\Aurora\skills\<名>\SKILL.md`）。写完**即刻生效**——
技能目录有监听，新技能下一次对话就进 `use_skill` 清单，无需重启。写文件仍走全部权限与
确认链路（该弹卡就弹卡），`scripts/` 附属脚本照旧**永不自动执行**。

### 模式能力对齐

定稿并落地一条原则：**模式差异只体现在「自主感知」与「特化功能」两处，绝不裁剪 Agent 的
基础能力**。任何模式下工具清单一致（受全局门控约束），课堂 / 工作 / 代码的差异只在
"主动知道什么"（感知订阅）与"专属功能"（分类管线、办公指引等）。能力矩阵由回归测试钉住，
未来不会悄悄出现"某模式下工具变少"。

## 🔒 三、安全与修复（本版开发期内自查发现并修复）

- **Center 配对令牌的凭据链完整接入**：`center.token` 与 API Key 同链路（safeStorage 加密
  落盘、渲染层只见"已配置"标记、日志与导出脱敏）。自查发现并修复了脱敏清单漏掉
  `center.tokenEnc` 的问题——按老规矩，密文绝不进渲染层。
- **配置保存链补齐**：设置页对 `center` 分组的保存此前会被主进程静默忽略（返回成功但不落盘），
  本版补上合并分支，且运行期剥掉补丁里的密文字段——构造出的补丁洗不掉已存的令牌。
- **配对异步窗口丢消息竞态**：客户端在配对校验完成前发出的状态上报会被服务器丢弃，
  导致网页端短暂显示"工具全关"的占位状态。已改为排队回放，并有竞态回归用例。
- **文件上传超限的报错语义**：超限此前会以"流提前关闭"掩盖真实错误（报 500），
  现在如实返回"超过上限"（413），且不留半截文件。
- **错误日志不再记录 `?token=`**：文件下载直链场景的登录令牌不进日志。
- **技能目录监听更稳**：首次启动时用户技能目录还不存在，监听会自动建目录再挂载，
  不再每次启动刷一条告警。

## ⚠️ 仍是已知限制（不是 bug）

- **Center 可见远程会话明文**：转发路径上的服务器天然可见全部远程对话——与"管理员可见
  所有客户端"的产品语义一致。敏感环境请把 Center 部署在自己控制的内网；无端到端加密。
- **`aurora-center update` 依赖 npm 通道**：设计上以 npm 为发布 / 更新源；当前 `@aurora/center`
  包**尚未公开发布**到 npm，`update --check` 会如实报"查询失败"。自建环境更新方式：
  拉取仓库后 `pnpm install && pnpm build`，或等 npm 包发布。
- **文件上传不走代理**：`advanced.proxy` 对 Center 连接与上传无效（v1 明确不支持）；
  Center 地址应是用户显式配置的可信目标。
- **Center 不存储会话历史**（只转发事件流）；上传的文件暂存于 Center 数据目录，**无自动清理**，
  需要时手动清理 `<数据目录>/files/`。
- 三档权限 + 项目根边界仍**不是** OS 级沙箱（与 v0.1.6 相同）；全局快捷键 `Alt+Space`
  在 Windows 上常被占用，注册失败属预期路径。

## 📦 安装与升级

- 直接用 `Aurora-Setup-0.2.0.exe` 覆盖安装：配置、会话历史、分类流水、技能与凭据**全部保留**；
  配置 Schema v15 → v16 自动迁移（只新增 `center` 分组，已有值原样保留）。
- **不使用 Center 的用户零变化**：不配置就是默认关闭——不出站连接、不注册新工具、
  设置页之外无任何入口。
- 安装包**未签名**，Windows SmartScreen 可能提示"未知发布者"，选择「仍要运行」即可。
- 更新包经 `latest.yml` 提供 sha512 校验，应用内「检查更新」与手动下载均走同一来源。
