# Aurora v0.8.0

本次版本汇总 **v0.7.2 → v0.8.0** 的全部更新。主线三条：**子代理系统重构**（Schema v46）、
**会话级 Plan Mode**（Schema v45，同时移除 Code Mode）、**设置页 Agent 栏目拆分**。
同批还包含工具选择顺序与工具面预算护栏、中断工具调用配对修复，以及依赖与工程基线升级。

本版配置 Schema **v44 → v46**（两条自动迁移，均幂等、不覆盖用户已写值）；插件清单与宿主
API 仍为 **v1**（无变化）；Aurora Center 版本线不变（0.7.0，本次不升）。已有配置 / 会话 /
插件 / 自动化数据全部保留。

## 一、子代理系统重构（Schema v46，主线）

把子代理从「隐式能力」做成**可配置、可选型、可围观**的一等能力，分配置面、派发协议、
围观面板三块落地。设计见 [06 §19.6 / §19.7](../06-agent-core.md)。

### 1.1 配置面：`agent.subagents[]`

- 新增数组配置，每项字段：`id`（稳定标识，`task.agent` 用它寻址）/ `name`（展示名）/
  `description`（**选型依据**，原样进入工具描述名册）/ `instructions`（子代理系统提示词）/
  `enabled` / `access`（`read` · `write` · `execute` 三档）/ `model`（`{ providerId, model }`，
  两者都空 = 跟随会话模型）/ `builtin`（出厂预设标记）。
- **出厂预设两个**：**Searcher**（`read`，代码库调研 / 定位 / 汇总）与 **Coder**（`execute`，
  实现型子任务：改文件 + 跑构建 / 测试自检）。预设可编辑 / 禁用，保留 `builtin` 便于一键恢复。
- 上限 **20 个**、id 唯一（数组级校验）；名册会原样进工具描述，无限增长会白占工具面预算。
- **整组在 `SETTINGS_READONLY_PREFIXES`**：AI 的 `set_setting` 一律拒绝。给自己加一个
  `execute` 档子代理、或把它指向另一个模型，都是绕过确认链的自我扩权路径，只能由用户在设置页操作。
- **迁移 `v45 → v46`**：只补缺失的 `agent.subagents`（写入两个预设）；已有数组原样保留、
  幂等；`agent` 分组缺失时不凭空造对象。

### 1.2 派发协议：`task.agent` 与运行期名册

- `task` 新增 `agent` 参数；工具描述在**每次工具表 sync 时**按启用项重建名册
  （`- <id>（<name>，<档位>）：<description>`），`agent` 的枚举值就是启用中的 id 列表。
  名册为空时不渲染该参数，描述回落通用文案。
- 解析顺序 **id（大小写不敏感）→ name**；未知 / 已禁用 id 一律 `isError` 并列出可用项，
  **不静默回落**通用子代理。指定 `agent` 时 `permission` 参数被忽略，档位由定义决定，
  防止模型用旧参数把只读档拉高。
- **三档工具面** `read` / `write` / `execute`：只读档没有写工具；`write` 与 `execute`
  共用**同一把写锁**整段串行，避免并行子代理交错读改写同一文件。
- 子代理仍拿不到 MCP / `task` / `ask_user` / `submit_plan`；`run_command` 只走
  `SUBAGENT_EXECUTE_TOOLS` 固定白名单。子代理仍**不能递归派生子代理**。
- 系统提示词改成**触发式派发**：读 ≥3 个文件 / 跨 ≥2 个目录才能答清的调研先派只读子代理；
  改代码 / 跑命令的实现型子任务派可写（可执行）子代理；提示词要求自包含（目标 / 路径 /
  验收），独立任务同轮并列、有依赖按顺序。

### 1.3 独立模型与真实回执

- 模型解析优先级固定为 **子代理配置 > 会话覆盖 > 全局**；配置的模型不可用时回落，
  并把「已回退」如实写进工具结果与快照，**不静默换模型**。
- `SubagentSnapshot` 新增可选字段 `agentId` / `agentName` / `access`（实际授予档位）/
  `model`（**实际**使用的模型），老快照照常读；`permission` 保留兼容。
- 配置在运行中被改 / 删**不影响 in-flight 运行**：名称、档位、模型在派发时定格进快照。

### 1.4 设置页「子代理」页与右栏查看器

- 设置页新增「子代理」页：列表行 = 启用 checkbox + 名称 + id + 「内置」徽章 + 档位 / 模型摘要；
  行内可改名称 / 用途说明 / 三档权限 / 模型来源与模型，展开区编辑指令；行尾「恢复预设」
  （仅内置）/「删除」（二次确认）。保存走整数组权威更新，回执经页级 Toast。
- 右栏新增**子代理单例查看器**：对话里 `task` 工具行的子代理徽章、或「子代理」页面每条运行卡
  都能打开；同一时刻跟一次运行，再点另一枚只换焦点、不刷标签。数据源与工具卡展开体同源，
  运行中打开即可边跑边看，不需要轮询；查看器只读，不提供干预入口。

## 二、Plan Mode（Schema v45，同时移除 Code Mode）

会话级只读规划：Agent 先只读调研、产出可审阅的 Markdown 实施计划，用户批准后再恢复工具面执行。
设计见 [06 §29](../06-agent-core.md)。

- **入口**：`/plan`（进入）、`/plan <任务>`（进入并立即发送任务）、`/plan off`（退出）；
  输入区显示「计划模式 / 计划待批准」芯片。v1 不做 Shift+Tab。
- **状态在会话**：`sessions/<id>.json` 的 `meta.plan = { active, record? }`，零迁移；
  它不是 `IMode`，不进 `MODE_IDS`、不写 `config.json`。
- **文件**：每次 `submit_plan` 写入 `<userData>/plans/<sessionId>/<yyyyMMdd-HHmmss>-<planId>.md`
  并更新同目录 `index.json`（标题 / 时间 / 状态，最多 200 条，索引损坏时扫描 md 重建）。
  正文不写项目工作区；会话真删除时 best-effort 删除该目录。
- **只读工具面**：请求级白名单只含读文件 / 检索 / Office 只读 / `web_fetch` / 浏览器读操作 /
  看图 / 剪贴板读 / `use_skill` / 自感知 / `center_status` / `todo_*` / `ask_user` 与
  `submit_plan`；**不含** `task`、`run_command`、写盘 / 设置 / 通知 / 自动化 / Computer Use /
  浏览器写操作 / 插件 / MCP。未进入计划模式时普通会话工具面不变。
- **`submit_plan`**：要求 `#` 开头、≤ 32,000 字符；先写 md + index、再写会话 meta，
  文件写失败不更新 meta。同轮 / 后续提交新计划时旧 pending 记录标 `superseded`。
- **批准**：用户点计划卡的「开始执行」→ 主进程**先**退出计划模式（保证执行轮拿到正常工具面）
  → 再发送「开始执行计划」并附已批准计划；send 失败 / 会话恰好忙则回滚为待批准。
  批准不改变 `agent.permissionMode`。
- **运行中守卫**：进入 / 退出 / 批准都要求会话空闲（`E_BUSY`），避免同一请求的下一轮
  突然获得写工具。
- **右栏计划面板**：多计划时顶部横向 chips + 下方单个只读阅读区；只有一个计划时不渲染选择条，
  正文去掉重复的一级标题。左栏固定入口「计划」（待批准时带圆点），计划卡头部可跳转侧栏。
- **IPC**：`chat:planStatus` / `chat:setSessionPlanMode` / `chat:approvePlan` +
  `plans:list` / `plans:read`；计划模式只在本机 chat 窗口生效，Center 不暴露计划状态 / 文件。
- **Code Mode 移除**：删除 `packages/modes/src/code.ts` 与占位配置组；迁移 `v44 → v45`
  删 `modes.code`、把 `modes.current === 'code'` 归一为 `classroom`（出厂默认模式）。

## 三、设置页 Agent 栏目拆分

原「Agent 设置」单页把五件不同的事折叠在同一页，16 项侧栏在默认窗高下已放不下。本版拆开：

- 侧栏改为**四组 16 页**：本机（通用 / 会话管理 / 模式 / 提醒）、智能（AI 模型 / 语音 /
  Computer Use / 文件自感知）、**Agent**（电脑操控 / 内置浏览器 / 子代理 / 技能 / MCP 服务器）、
  系统（Aurora Center / 插件 / 系统）。
- 五个页面都是「页头 + 常显静态区组」，页内不再有可折叠 section-card；原字段锚点、
  `data-empty` 与保存语义不变。技能 / MCP 组的 `data-group` 锚点保留，截图探针无需改名。
- **导航可用性**：侧栏导航独立滚动区；切换页面时内容区回到顶部；深链直接打开靠后页面时，
  当前项自动滚入可视范围。
- **旧深链单向映射**：`?page=tts → voice`、`?page=agent → agent-tools`、
  `?page=skills → agent-skills`、`?page=mcp → agent-mcp`。
- 截图探针按新页面 id 拆分并补齐各页门控；`settings-snapshot-list` 与 `settings-general`
  两处历史 FAIL 在拆页后复跑已 PASS。

## 四、工具选择顺序与工具面预算护栏

- **不物理合并工具**：`sensitivity`、注册门控、权限档都是工具级静态属性；跨 `safe` / `confirm`
  或跨门控合并会放宽确认或让不该出现的工具进清单。重叠工具改为在**提示词层做路由**：
  读 Office / 取网页 / 截屏 / 打开网页 / 看图来源 / 通知渠道六条选择顺序，
  且只在成对工具同时可见时生成。
- **工具面预算（ratchet）**：`TOOL_FACE_BUDGET = { maxTools: 65, maxChars: 42_000 }`
  （`apps/desktop/src/main/tools/budget.ts`）。`syncToolRegistries()` 结束时度量一次，
  超出只在跨阈值时 `warn` 一次、回到预算内 `info` 一次；**只告警，不阻断请求、不改注册集合**。
  2026-11 基线：内置全量 62 个工具 / 34,272 字符，留约 7.7k 余量；单测锁住该基线。

## 五、工具调用配对修复（防服务端 400）

- **根因**：OpenAI 兼容服务要求「`assistant(tool_calls)` 之后紧跟每个 `tool_call_id` 各自的
  `tool` 消息」。流在 `[DONE]` 前中断、用户中途停止、进程被强杀或旧会话文件，都可能留下半组历史；
  下一次发消息会被服务端以 400「insufficient tool messages」拒绝，表现为「执行过一次中断的任务后，
  再发任何消息都报错」。
- **循环侧补落盘**：流中断时为本轮每个未执行的 `tool_call` 补一条失败 `tool` 结果；中途停止时
  为未执行的调用同样补一条。文案如实写「未返回结果」，**不编造工具输出**。
- **请求组装层兜底**：新增 `repairToolCallPairs()`，按 `toolCalls` 顺序补齐缺失结果、丢弃孤儿 /
  重复结果、为旧的无 `toolCallId` 结果补归属。修复只发生在**组装请求**时、不写回会话，
  因此已有坏历史也能直接继续对话，历史不会越修越长。

## 七、兼容性与升级

- **Windows 10 x64（含 19045）**：全部核心功能可用；无桌面模糊，窗口与面板为实色。
- **Windows 11 22H2+**：原生 Acrylic 行为与 v0.7.2 一致；Win11 21H2 与 Win10 同路径。
- **配置升级**：Schema v44 → v46 两条自动迁移（移除 Code Mode、补子代理预设），
  幂等、不覆盖用户已写值；`pnpm verify` 断言 `v0 → v46` 共 **46 条**迁移。
- **Code Mode 用户**：`modes.current = code` 自动归一为 `classroom`；Code Mode 无独有能力，
  文件 / 命令 / 子代理能力均由 Agent 工具面承接。
- **计划与子代理数据**：计划文件在 `<userData>/plans/`；子代理配置在 `config.json` 的
  `agent.subagents`，不进会话文件；升级不丢历史计划 / 会话 / 快照。
- 插件清单与宿主 API 仍为 **v1**；Aurora Center 版本线不变，不影响已配对客户端。
