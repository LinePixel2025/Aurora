# Aurora v0.5.2

本次版本汇总 **v0.5.1 → v0.5.2** 的全部更新。核心是**桌面小组件窗口层级与原生毛玻璃**：
插件现在可以声明小组件只在桌面可见（不置顶），也可以为独立小组件窗口启用 Windows 原生 Acrylic；
同时把 v0.5.1 之后落地的**独立插件开发工具包**（`plugin-dev-kit/`）一并带入本版。

配置 Schema 保持 **v36**，没有新增迁移；Aurora Center 代码版本线仍独立（线上 0.4.9），
本次双投的仍是桌面安装包的三个更新资产。

## 一、桌面小组件窗口层级

### 1. 清单字段

`manifest.json` 的 `contributes.widgets[]`（`slot: "desktop"`）新增：

```json
{
  "id": "week-overview",
  "title": "班级速览",
  "slot": "desktop",
  "windowLevel": "desktop",
  "windowMaterial": "acrylic",
  "schema": "ui/widget-overview.json",
  "defaultSize": { "width": 320, "height": 300 }
}
```

- `windowLevel`：`floating`（默认，置顶，0.5.1 行为不变）/ `normal`（普通 z-order）/
  `desktop`（不置顶并尽力贴合桌面层）；
- `windowMaterial`：`none`（默认，不透明卡片）/ `acrylic`（Windows 原生 Acrylic）；
- 只对桌面小组件生效；`slot: "edge-bar"` 声明非默认值会在清单校验阶段被拒绝；
- 不新增插件权限 / 插件 API，旧清单无字段时自动按 `floating` / `none` 处理。

### 2. `normal` 与 `desktop`

- `normal`：移除 `alwaysOnTop`，浏览器 / Office / 全屏视频等普通窗口可以正常覆盖小组件；
- `desktop`：在 `normal` 基础上做 Win32 **owner 亲和**（指向桌面 `SHELLDLL_DefView`），
  并带最小化恢复守护，让 Win+D / Win+M / 任务栏「显示桌面」后仍尽量可见；
- `desktop` 是**尽力而为**：拿到不到 owner 或恢复守护连续失败时，保持普通窗口行为并记录诊断；
  它不是壁纸层嵌入、桌面图标层或点击穿透，也**不采用** WorkerW 重挂父窗口
  （会破坏 Electron 的透明表面与命中测试）。

### 3. 用户覆盖与布局

- 设置 → 插件 → 详情中，每个桌面 widget 的「显示在桌面」旁新增层级下拉：
  **跟随插件 / 置顶 / 普通 / 桌面层**；
- 覆盖值写到 `<userData>/plugin-widget-layout.json` 的可选 `windowLevelOverride`，
  缺省 = 跟随清单；布局文件版本仍为 `1`，**不进 settings、不升 `CONFIG_VERSION`**；
- 已创建的窗口原地切层级，不重建、不丢位置 / 尺寸 / 页面状态；隐藏中的 widget 只落盘，下次创建生效。

## 二、桌面小组件原生毛玻璃

- `windowMaterial: "acrylic"` 时，宿主在 Windows 11 22H2+ 且外观设置里的**毛玻璃开关开启**时
  为小组件窗口启用 `BrowserWindow.setBackgroundMaterial('acrylic')`；
- 窗口 shape 按卡片四角裁成 1px 阶梯圆角，避免原生材质从 CSS 圆角外露出矩形；
- 材质成功才给小组件页面传 `material=acrylic`，之后外观开关变化通过 `plugins:widgetMaterial`
  事件同步；渲染层只在「材质已生效 + 毛玻璃开启」时使用玻璃令牌，否则保持原有不透明卡片；
- 非 Windows / 旧 Windows / `setBackgroundMaterial` 或 shape 失败时自动回落，不裸漏桌面；
- 这是**桌面小组件窗口**的能力，不新增插件自建窗口类型。

## 三、独立插件开发工具包（v0.5.1 之后落地）

- 新增可整体拷走的 [`plugin-dev-kit/`](../../plugin-dev-kit/README.md)：
  契约全文、开发指南、模板、两个示例（hello-aurora / class-board）与零依赖校验器；
- `plugin-dev-kit/tools/check-plugin.mjs` 可在没有 Aurora 源码的环境独立校验清单、权限、
  声明式 schema、路径与小组件约束；
- 文档与 [docs/14](../14-plugin-system.md) / [docs/15](../15-plugin-development-guide.md) 同步，
  本版把 `windowLevel` / `windowMaterial` 一并写进契约与模板。

## 四、兼容性与升级说明

- 配置 Schema 仍为 **v36**，无 v36 → v37 迁移；已有配置、会话、插件与布局文件原样使用；
- 旧插件无需修改：未声明新字段时与 0.5.1 行为完全一致；
- 使用新字段的插件建议在清单里设置 `minAuroraVersion`，因为旧宿主会静默忽略未知字段；
- 安装包仍为 Windows x64、未签名；首次运行 SmartScreen 提示时选择「更多信息 → 仍要运行」；
- 自动更新优先走当前配置的 Aurora Center 更新源，GitHub Releases 作为过渡回落；
  桌面安装包的 exe / blockmap / latest.yml 三个资产在两端保持一致。
