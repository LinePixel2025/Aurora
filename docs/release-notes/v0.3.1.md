# Aurora v0.3.1 更新说明

发布日期：2026-10-01 ｜ 安装包：`Aurora-Setup-0.3.1.exe`（Windows x64，未签名）

v0.3.0 之后的**补丁版**，四块内容：**Agent 能看图了**（`view_image` / `screenshot` /
`clipboard_read_image` 三件套）、**语音输入支持阿里云百炼原生 ASR**（不走兼容层，录音不转码直传）、
**主界面左栏「添加项目」修好并可见**、**Center 部署模板跟着当前版本走**。

**有一处配置迁移**：Schema 从 **v23** 升到 **v24**（只归一 `stt.providers.*.type`，
旧配置升级后请求体逐字不变）。覆盖安装即用，已有设置与凭据一个都不会被改。

## 🖼️ 一、Agent 能看图了：图像工具三件套（新）

上一版做完了「把图片拖进对话」（图片作为输入进模型），这一版补齐**Agent 自己看图**的能力 ——
它能读一张本地图片、截当前屏幕、读剪贴板里的图片，并把看到的图作为本轮输入继续推理。

| 工具 | 它做什么 | 确认档 |
|---|---|---|
| `view_image` | 读一张本地图片（和 `read_file` 同权限档，纯读） | 不需要确认 |
| `screenshot` | 截当前屏幕（主屏 / 全部屏幕） | **逐次确认** |
| `clipboard_read_image` | 读剪贴板里的图片 | **逐次确认** |

几件你会实际感受到的事：

1. **「屏幕上是什么」终于能直接问**。工具表里带了截图能力时，系统提示词会多一行规范：
   用户问屏幕内容或指着某个报错窗口时**直接截图自己看，不要反问用户描述**。
   工具不可用时这一行自动消失，不会出现「让模型去调一个不存在的工具」。
2. **门控按模型能力生效**：只有**当前生效模型**开了图片输入（模型的 `vision` 开关）时，
   这三个工具才会出现在工具表里（是「根本不注册」而不是「注册了再拒绝」）。
   在对话窗的模型下拉里换模型**下一次请求即生效**，不用重启。
3. **产物存在 app 自己的目录**：截图进 `<userData>/screenshots/`、剪贴板图片进
   `<userData>/clipboard/`，各留最近 50 张。这两个目录**不受项目根边界限制**（否则
   「生成一张图再看看」这种最自然的用法会被边界挡死）；`view_image` 读别处的图仍走
   与 `read_file` 完全一致的项目根边界，越界时**如实报错**并提示可以让你把图拖进对话窗。
4. **生图不受影响**：`generate_image` 任何模型都能用（生图不需要模型自己会看图）；
   开了 `vision` 之后模型可以顺手看一眼自己刚生成的图。
5. `screenshot` 支持选主屏还是全部屏幕（多显示器场景）。

## 🎙️ 二、语音输入支持阿里云百炼原生 ASR（配置 Schema v24）

此前语音输入只有 OpenAI 兼容那一条路（`POST /audio/transcriptions`）。百炼的
`qwen3-asr-flash` **没有这条兼容路由**，所以这一版直接把原生同步接口接上了：

- 设置页「语音 → 添加语音输入模型」里，**「接口协议」是编辑卡的第一项**：
  `openai-compat`（OpenAI 兼容，含各类兼容网关）或 `dashscope-native`（阿里云百炼原生）。
- 预设两条：**OpenAI 语音识别** 与 **阿里云百炼原生 ASR**（`qwen3-asr-flash` + 官方域名），
  照着预设改 `baseUrl` / API Key 即可。`baseUrl` 填服务根（`https://dashscope.aliyuncs.com`），
  也容忍写成 `…/api`、`…/api/v1`、`…/compatible-mode/v1` 或完整端点这四种常见粘法。
- **音频不转码**：浏览器录出来的 webm/opus 直接以数据 URI 发上去，省掉一次转码。
  实测 4 秒语音约 0.5–0.7 秒返回。
- 用 MaaS 专属网关（例如你已经在用的 qianwenai）只需把 `baseUrl` 换成网关地址，**协议不用改**。
- 失败按「code：message」报出来（`code` 才是能对照阿里云文档的东西），不编造空文本。
- **迁移 v23 → v24 只归一 `type` 字段**：v23 及更早的配置本来就等价于 `openai-compat`，
  升级后请求体逐字不变；已经手改成 `dashscope-native` 的**不会被动**。

## 🗂️ 三、主界面左栏「添加项目」修好，并且看得见了

你报的「在左栏『项目对话』里加完项目，并没有真正添加」——底层链路其实是好的
（弹选择框 → 写配置 → 落盘，实测都通），真因是两个：

1. **两处入口口径不一致**：设置页「会话管理 → 添加项目」加完会把新项目设为**当前项目**
   （界面上就是「已启用」），而左栏那个 `+` 只把项目加进列表、**不动当前项目** ——
   于是「加上了」和「生效了」在左栏这条路径上分了家。**现在两处完全一致：加完即当前项目。**
2. **整条链静默失败**：旧实现把「你取消了选择」和「选择框出错了」压成同一个结果、直接返回，
   出错时界面没有任何提示、日志里也没有痕迹。现在三态分开：**出错会把原因显示出来**
   （左栏左下角的提示条），成功也会给一句「已添加项目「X」并设为当前项目」。

配套的可视化：**左栏项目分组头上多了一枚「当前」徽标** —— 当前项目在主界面里此前
**没有任何表示**（右栏那张项目卡早先已下线），加完项目有没有生效只能去设置页看。
顺带修了一处时序问题：选择框是模态的、可能停留很久，现在提交前会**重读最新配置**，
不会用弹框前的旧快照覆盖掉期间在别处做的项目改动。

> 补充一句口径说明（也写进了 docs/06 §5.1）：「当前项目」**不等于**某个会话的工作目录。
> 每个会话的工作目录按「会话绑定项目 → 会话空间目录 → 全局当前项目 → …」解析，
> 想在某项目里干活，入口是**该项目分组头上的 `+`**（新建即绑定该项目）。

## 升级与兼容

- **配置迁移 v23 → v24**：只有 `stt.providers.<id>.type` 会被归一（补缺失 / 非法值），
  旧配置升级后行为不变。你已写的值原样保留，凭据不变。
- **没有破坏性变更**，也不需要重配任何东西。覆盖安装即可。

### 需要留意的行为变化

1. **图像工具是注册级的**：模型没开 `vision` 时这三个工具不存在（不是"调用被拒"）。
   想让 Agent 看图，先去设置页把当前模型的「图片输入」打开。
2. **`screenshot` / `clipboard_read_image` 每次都要确认**（`auto` 档也一样）——
   它们读的是屏幕与剪贴板这类敏感内容，这是有意的。
3. **左栏「添加项目」现在会切换当前项目**（此前不切）。这与设置页那条路径一直是同一件事；
   如果你只想登记、不想切换，加完在设置页把当前项目点回原来那个即可。

- `pnpm typecheck` ✓（5 个包 + 主进程 + 渲染层）｜ `pnpm test` **127 文件 / 2208 用例**全绿
  ｜ `pnpm build` ✓ ｜ `pnpm verify` 26/26（`version=24`、迁移 `24/24`）
- 端到端自测 `AURORA_SMOKE` **178/178 passed**、0 FAIL
- 窗口截图核对 `AURORA_CAPTURE` **72 张图 / 72 条检查项，0 FAIL**
  （其中 `chat-session-groups` 新增「当前项目徽标恰有一枚」的断言）

### 已知限制（未变）

- 安装包**未签名**，Windows SmartScreen 会提示；仍**没有 OS 级沙箱**
  （`run_command` 以当前用户权限运行，项目根边界是应用层的两道校验）。
- 图像工具与百炼原生 ASR 的**真实调用只在本机分别实测过单条链路**
  （截图 / 剪贴板读取 / `qwen3-asr-flash` 转写），未做长会话回归。
- Code Mode 仍为占位实现；多语言、ARM64 / 便携版、macOS / Linux 未开始。
- `pnpm format:check` 与 `pnpm lint` 在开发机（`core.autocrlf=true`）存在改动前即有的存量报错，
  与本次改动无关；CI 的 LF 检出不受影响。
