# Aurora v0.2.1 更新说明

发布日期：2026-09-27 ｜ 安装包：`Aurora-Setup-0.2.1.exe`（Windows x64，未签名）

这一版只做一件事：**把「连接 Aurora Center」从折腾变成一步**。
v0.2.0 的配对方式是「管理员先发配对令牌 → 用户复制粘贴到客户端」——而且实测发现配对
根本走不通：客户端 ID 从未被生成，连接器永远停在「尚未配置」，两端毫无反应
（v0.2.0 的已知缺陷，本版修复）。v0.2.1 起，配对改为**账号登录**：桌面端填一次
服务器地址 + Center 账号口令，自动换取凭据并连上服务器；你在 Center 网页端用
**同一个账号**登录，就能看到并控制自己的机器。

配置 Schema **v16 → v17**（`center` 分组新增 `account` 字段），覆盖安装时自动迁移，
配置 / 会话 / 凭据全部保留。

---

## 🔑 一、配对方式重构：账号登录（替代配对令牌）

### 新流程（两步）

1. **桌面端**：设置 → Aurora Center → 填**服务器地址**（如
   `http://120.24.223.65:8787`）+ **Center 账号**与**密码** → 点「**登录并连接**」。
   客户端立即向服务器换取凭据、记住账号并自动连上——状态卡转绿即成功。
2. **网页端**：浏览器打开 Center → 用**同一个账号**登录 → 你名下的机器就在列表里，
   远程开会话 / 收文件 / 改开关 / 切模式，与之前完全一致。

### 与旧方式的差异

| | v0.2.0（配对令牌） | v0.2.1（账号登录） |
|---|---|---|
| 前置条件 | 管理员先创建令牌并安全传递给用户 | 只需一个 Center 账号（管理员建好即可） |
| 客户端操作 | 粘贴一长串令牌 + 保存 | 输账号密码点一下 |
| 客户端归属 | 令牌首次连接时绑定 | 登录成功即归属该账号 |
| 凭据失效后 | 重新找管理员要令牌 | 设置页重新登录一次 |
| 旧入口 | — | 已从设置页移除；服务器端令牌通道保留兼容 |

### 安全细节

- 密码**只在登录请求里使用一次**：不落配置、不进日志、页面不回显；本机只保存
  服务器颁发的客户端令牌（safeStorage 加密，凭据链路与 API Key 同款）。
- 每次登录都会**吊销同设备的旧令牌**——换账号或重新登录后，旧凭据立即失效。
- `center.*` 整组依旧对 AI 只读：Agent 无法自行改服务器地址、换账号登录或启用连接。

## 🛠 二、修复

- **客户端 ID 从未生成（v0.2.0 配对无反应的根因）**：设置页声称「首次启用时由主进程
  生成并持久化」，但主进程没有对应逻辑——连接器因 clientId 为空永远报
  「尚未配置服务器地址或配对令牌」，Center 端自然看不到任何客户端。现在 clientId
  在首次登录时生成并持久化。
- **保存链路确认**：`settings:update` 的 `center` 分组已在主进程登记并运行期剥离
  `tokenEnc`（防构造 patch 洗密文），设置页保存真实落盘（v0.2.0 页内预留的
  「保存未生效」报警不再触发）。

## ⚙️ 三、服务器端（Aurora Center 0.2.1）

- 新增 `POST /api/client/login`：`{ username, password, clientId }` → 客户端令牌
  （归属该用户、创建即绑定该设备）。口令错误 401，缺字段 400。
- 手动配对令牌（CLI `token create` / Web 管理端）**仍然可用**，作为兼容路径。
- 其余行为不变：属主过滤、管理员跨属主控制、远程配置白名单、文件上传下载。

---

## 📦 升级与部署

- **桌面端**：覆盖安装即可；若之前配过 Center，升级后需在设置页重新登录一次
  （旧令牌若已失效，登录即自动换新）。
- **服务器**：按 `packages/center/deploy/README.md` 重新打包上传，
  `docker compose up -d --build`（数据在 `./data`，不受影响）。
  注意：CLI 新建 / 改密的账号要**重启容器**后才对运行中的服务器生效。
- ⚠️ **明文传输提醒**：Center 不自带 TLS——公网部署请置于 TLS 反代之后（cloudflared /
  OpenResty + 证书），客户端与浏览器都填 `https://` 地址；否则登录口令与会话内容
  均明文过网（docs/12 §11）。

## 🛡 四、服务器热修（Aurora Center 0.2.2，同日追加）

真实客户端上线验证中抓到三个服务器侧缺陷，随 0.2.2 修复：

- **登录间歇性 500（并发落盘相撞）**：账号登录的令牌落盘与设备首次握手的绑定落盘
  并发时共用同一个临时文件名，后者 rename 失败直接 500。已改为同文件写串行化 +
  临时文件名带随机后缀。
- **属主不跟随换绑**：客户端登记后不再更新属主，设备换账号登录后新属主在网页端
  永远看不到本机。现属主跟随当前有效令牌；未释放的属主受抢注护栏保护（登录 409 /
  配对令牌拒绝绑定他人设备）。
- **服务器零日志**：CLI `start` 未给服务器传日志器，全局异常兜底完全不可观测。
  现在启动即输出结构化日志（docker logs 直接可查）。
