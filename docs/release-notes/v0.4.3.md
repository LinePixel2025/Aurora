# Aurora v0.4.3

本次版本是从 **v0.4.2** 到 **v0.4.3** 的完整更新，桌面端与 Aurora Center 同步升级。
重点包括请求级 Agent 工作折叠、会话自动标题与级联清理、自感知手动过期、提示条交互与
品牌图标更新，以及 Center 网页端的同步展示与服务端部署版本对齐。

## 一、Agent 对话按请求折叠

- 同一次 Agent 请求产生的用户消息、助手中间正文、思考和工具调用统一携带 `requestId`，
  正常完成后收成一个工作胶囊；会话文件版本升级到 **v7**，旧历史缺少字段时按相邻助手消息回退分组。
- 最终结论固定为该请求最后一条正文非空的助手消息，并显示在工作胶囊之后；该请求产生的图片去重后
  固定显示在最终结论之后，不再由工具轮抢跑。
- 展开工作胶囊可以按发生顺序查看思考、工具调用和中间正文；失败、取消、轮次暂停或预算暂停时不套用
  最终折叠，保留完整过程现场，方便继续排查。
- 流式期间继续实时展示逐消息轨迹，不提前计算最终结论；完成后只做一次稳定分组，避免每个正文增量
  重复扫描仍在增长的消息内容。
- 摘要同时包含去重后的步骤数与端到端总用时；历史水合有可靠时间戳时回放用时，否则省略，不伪造数据。
- 桌面端与 Aurora Center 网页端共用 `packages/shared/src/browser/agentTurns.ts` 的分组语义；
  `session.history` 增加可选 `requestId`，Center 仍不缓存会话正文。

## 二、会话自动标题与级联清理

- 首个用户需求发出后，主进程异步复用该会话当前模型生成 6–14 字任务标题，成功后在左栏和主区
  原位更新，并写入会话元数据；不新增聊天消息、不切换会话、不计入 `meta.usage`。
- 没有标题时继续使用首条用户消息前 24 字作为回退；生成失败静默保留回退标题并记录 pending，
  下次发送再重试。`awareness-`、`auto-`、`-sub` 后台会话不参与自动标题，旧会话也不会批量回填。
- 空会话设置标题只更新内存，不先创建空会话文件；标题变化同步失效会话摘要缓存，避免左栏短暂显示
  “新会话”与主区新标题打架。
- 删除会话时先通过 running job 守卫，再清理 `todos/<sessionId>.json` 与
  `todos/<sessionId>-sub.json`，最后删除会话并广播；todo 清理失败时不删会话、不广播。
- 删除会先取消防抖、清脏标记并排空在途写入，防止待写任务把待办文件重新写回来；归档仍保持可逆，
  不清理 todo。

## 三、自感知、记忆过期与提示条

- 记忆库新增“立即过期”：过期只停止把笔记提供给后台候选与 `awareness_*` 工具，不删除状态和
  Markdown，也不从记忆库隐藏；用户可改为永不过期或重新选择到期时间恢复。
- 手动立即过期使用固定状态，源文件重新分析不会自动续期；继承默认有效期的记忆仍会按更新时间续期。
- 文件进入 `extracting` / `analyzing` / `writing` 阶段时，在提示条所在显示器工作区顶部显示
  2px 彩色流光与约 20px 柔光；只动画合成层属性，不逐帧发送 IPC。排队和空闲阶段不显示，
  分析结束后短时淡出。
- 流光遵守提示条显示位置、首次引导、勿扰与游戏模式门控；窗口鼠标穿透、不可聚焦。
- 提示条分析进度条显示当前文件的等待 / 提取 / 分析 / 写入阶段，空闲、未启用或知识库不可用时整条隐藏；
  今日分析配额继续只由上方指标表达。
- 修复提示条触摸展开、弹出动画与置顶恢复：显示 / 展开 / 收起后统一使用
  `screen-saver` 等级，监听原生置顶丢失并立即恢复；保留 10 秒低频 watchdog，不进行高频 `moveTop()`。

## 四、窗口、自动化与品牌

- 自动化历史与编辑器改为单例独立窗口（`780×720`，最小 `560×480`），主界面只保留自动化列表；
  历史和编辑不再受主区 stacking context 裁切，关闭窗口只隐藏，不中断已有数据。
- 自动化窗口复用现有 `automation:list` / `history` / `save` 等通道，由
  `automation:openWindow` 和 `automation:windowRequest` 在页面加载完成后投递请求。
- 应用图标升级为圆角矩形品牌稿，并由唯一设计稿重新生成托盘、窗口 / 任务栏和 exe 图标；
  主界面、设置、提示条、首次引导与 Center 顶栏统一使用共享品牌标。
- 主界面聊天空态改用透明品牌标，去掉底色与阴影；圆角只存在于图标生成链，不手改派生 PNG / ICO。
- 自动化探针、提示条探针与品牌截图基线同步更新，窗口矩形和可见命中区按实际布局验收。
- 修复移动端 Center 左侧抽屉被共享入场动画终帧持续覆盖的问题：抽屉在窄屏禁用该动画，
  关闭态重新由其 `opacity` / `transform` 决定，打开 / 关闭、点击命中与自动收起保持可见可验。

## 五、Aurora Center 同步升级

- Center 服务端与 Web 控制台版本更新到 **0.4.3**；桌面端和 Center 同轮发布。
- 网页端接收并保留消息的可选 `requestId`，把同一次 Agent 请求的思考、工具和中间正文折叠展示，
  最终结论与图片仍排在胶囊外；旧客户端或旧历史缺少字段时按相邻助手消息回退。
- Center 继续只转发、不缓存远程会话正文；历史回放仍由客户端读取并返回，服务器只负责鉴权与路由。
- `packages/center/deploy/docker-compose.yml` 的镜像 tag 从陈旧的 `0.4.0` 修正为 `0.4.3`，
  部署 README 同步更新；发布仍坚持“先构建 `dist` / `dist-web`，再打镜像”，不在容器内安装 npm。
- 线上更新保持数据目录 `./data` 不变，升级前做目录备份，再执行 `docker compose up -d --build`。

## 八、兼容与限制

- Windows 安装包为 x64，仍 **未代码签名**；首次安装会出现 SmartScreen「未知发行者」提示，
  点击「更多信息」→「仍要运行」即可。需要管理员权限时会另行弹出 UAC。
- 配置 Schema 保持 **v30**，本版本没有配置迁移；会话文件版本升到 v7，但 `requestId` 是可选字段，
  不执行磁盘迁移，旧文件可直接读取。
- 旧历史没有 `requestId` 时只能按相邻助手消息做近似折叠；这是兼容回退，不修改原始消息顺序。
- Center 公网部署仍建议经 TLS 反代或 Cloudflare Tunnel；本项目不提供端到端加密，服务器可看到远程会话
  明文，文件暂存按既有 24 小时策略自动清理。
- `.doc` / `.xls` / `.ppt`、宏、复杂 COM、不可选择文字的 Office PDF 导出等限制与 v0.4.2 相同。
