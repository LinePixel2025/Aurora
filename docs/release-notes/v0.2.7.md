# Aurora v0.2.7 更新说明

发布日期：2026-09-29 ｜ 安装包：`Aurora-Setup-0.2.7.exe`（Windows x64，未签名）

这一版做的是**「少点干扰、少点等待」**：把输入框和设置页里那些"说了两遍的话、包了三层的边框"
收拾干净，出厂权限从「每次都要问」提到「项目内直接做、越界才问」，
并让 Center 网页端上的设备上线 / 下线**立刻可见**（此前最坏要等 90 秒）。

**没有任何配置迁移**：Schema 仍是 **v19**，覆盖安装即用，不用重新配置。

> ⚠️ 权限默认值只影响**新装**：已经装过 Aurora 的机器保留你当前选的档位，不会被改动。

---

## ⌨️ 一、输入框：不再有半句被切掉，也不再像一条设置工具栏

上一版把「模型 / 思考等级」两个下拉搬进输入框时，留下了两个明显问题：

1. **占位文案会断在半句上**：「输入消息，Enter 发送，Shift + Enter 换行；输入 / 调用命令与技能，
   可直接拖入文件」有 40 多字，而输入框的高度由**内容**决定（空的时候就是一行）——
   换行后的第二行直接被裁掉，用户看到的是「…可直接拖入文」这种断句。
2. **三枚控件太抢眼**：权限 / 模型 / 思考三个下拉各是 40px 高、各自带一圈边框，
   并排在一起像一条设置工具栏，把输入框顶得很高。

现在：

- **占位只剩一句**：`输入消息…`（回复中显示 `正在回复中，可继续输入…`）。
  键位提示搬到工具行右侧的 `Enter 发送 · Shift + Enter 换行`，
  `/` 命令与「可直接拖入文件」放进输入框的悬浮提示 —— 信息没丢，只是不再挤在占位里。
- **三枚「芯片」**：统一 28px 高、圆角胶囊、**静止态没有边框也没有底色**（只有文字与原生箭头），
  鼠标悬停 / 键盘聚焦时才浮出一层浅填充。权限芯片仍是琥珀色常驻 —— 闸门开着这件事必须一直看得见。
- 输入卡内边距与行距一并收紧，三段（文字 → 工具行 → 上下文详解条）读起来是一整条。

命中区仍达标：28px 高于 WCAG 2.2 SC 2.5.8 的 24×24 下限，发送 / 麦克风保持 32px。

## 🧹 二、设置页与引导窗：说明文案大扫除

你反馈的「设置界面的文字还是太过冗杂了」在 23 个文件里清了一遍（净减 84 行）：
删除文档编号引用（`docs/06 §11` 这种）、删除实现细节（「主进程自动拼 /services/…」）、
删除比喻（「最彻底的刹车」），同一条信息只讲一遍。

改动前后（「智能与工具 → 电脑操控工具」区组说明，**180 字 → 48 字**）：

> 旧：让模型能执行命令、读写文件与打开路径（docs/06 §11）。**本页操作直接影响真实系统**：
> 命令执行与工作目录之外的文件写入是敏感操作，逐次确认后才执行（工作目录之内的 write_file /
> edit_file 免确认；确认开关在「系统」页，关闭后将不经确认直接执行）；工作目录**不是沙箱** ——
> 模型仍可显式传入其它路径，安全边界是「逐次确认 + 输出上限 + 总开关」。
>
> 新：让模型执行命令、读写文件与打开路径。默认档（完全权限）下项目根之内免确认、
> 越界仍逐次确认，未配置项目时只写日志留痕；档位在「系统」页或对话窗输入框的权限钮上切换。
> 工作目录**不是沙箱**，模型仍可传入其它路径。

**默认值、单位、取值范围、边界条件、失败后果、修复路径一律保留**（例如「0 = 不限」
「超出即拒绝并提示分段读取」「关闭后改动将不可回滚」都还在）；区组标题、按钮、徽标文案未动，
所有界面探针依赖的原文（如「只读模式：仅注册只读工具（不含写入与命令）」）一字未改。

## 🔓 三、出厂权限从「变更前确认」提到「完全权限」

三档权限（只读 / 变更前确认 / 完全权限）的默认档改为 **完全权限**：

| 档位 | 行为 |
|---|---|
| 只读 | 写文件 / 执行命令类工具**根本不注册**给模型 |
| 变更前确认 | 敏感工具每次执行前弹确认卡片 |
| **完全权限（出厂默认）** | **有项目时**：项目根之内免确认，越界仍逐次确认 |

为什么要改：Aurora 是系统级 Agent，出厂就逐次确认会让绝大多数正常操作
（改自己项目里的文件、跑一条构建）都要先点一次卡片。放宽的同时保留两道**真实**护栏：

1. 免确认只在**当前项目根之内**，越界照样弹卡；
2. 真正落盘前还有一层 realpath 前缀校验（越界即 `E_PATH_OUTSIDE_WORKSPACE`），
   指到根外的写入会被直接拒绝。

**一处必须说清的口径**：如果你**还没有登记项目**（设置 → 通用 → 项目，或右栏「会话项目」），
那么"根内 / 越界"就没有判据，此时完全权限档**完全不弹卡**（只写日志留痕）。
想要确认卡兜底，把档位切回「变更前确认」（设置 → 系统，或输入框上的权限芯片），
登记一个项目后完全权限档就会按"根内免确认、根外询问"工作。
权限芯片的悬浮提示与菜单项把这两种状态都写明了。

存量配置不受影响：**已安装**的机器保留现有 `permissionMode`，本次不迁移、不动 `CONFIG_VERSION`。

## 🔌 四、Aurora Center：上线 / 下线的状态刷新不再"慢半拍"

网页端显示的在离线 = 服务器此刻还有没有这条连接（没有轮询，靠推送）。慢的从来不是推送，
而是几处"看不出问题"的定时器，逐段收紧：

| 环节 | 旧 | 新 |
|---|---|---|
| 半开连接（拔网线 / 休眠 / 进程被硬杀）判离线 | 30s × 3 拍 = 最坏 **90s** | 15s × 2 拍 = 最坏 **30s** |
| 客户端检测服务器失联 | 无（只能等系统 TCP 超时） | 新增心跳看门狗：45s 没收到 ping 主动断开重连 |
| 客户端断线重连的退避上限 | 30s | **5s**（±20% 抖动） |
| 网页端自身断线重连上限 | 15s | 5s |
| 启动到拨号 | 被 MCP 建连串行阻塞（单台连不上的服务器可推迟 30s） | MCP 不再阻塞启动链 |
| 管理端「全部客户端」表 | 一次性快照，**停在该页永不更新** | 读实时推送（REST 只做首次水合） |
| 重连竞态 | 旧连接的迟到断开会把刚上线的新连接删掉（设备显示离线且不自恢复） | 断开时做连接身份校验 |

## 升级方式

1. 直接运行 `Aurora-Setup-0.2.7.exe` 覆盖安装（保留配置与会话）；
2. 或等应用内的「设置 → 常规 → 更新」检查到 v0.2.7 后一键升级。

## 已知限制（本版未变）

- 安装包**未签名**，Windows SmartScreen 可能提示"未知发布者"。
- Center 仍是**纯 HTTP**：登录密码与令牌明文过公网，建议只在内网或反代 + 证书下使用。
- `Alt+Space` 全局快捷键在 Windows 上常被系统占用，注册失败是预期路径（改绑即可）。
- Code Mode 仍是占位实现；多语言、ARM64 / 便携版、macOS / Linux 未开始。
