# Aurora v0.4.0

本次更新把桌面客户端从 Electron 33 升级到 **Electron 44.5.1**，并修复升级暴露出的窗口材质、
原生最大化、提示条透明窗口与剪贴板 API 兼容问题。

## 运行时升级

- Chromium：130 → **152**
- Node.js：20.18 → **24.18.1**
- V8：13.0 → **15.2**
- Electron：33.4.11 → **44.5.1**

升级带来更现代的网页平台、安全和网络栈，同时主进程、utility process 与原生模块统一使用
Electron 44 的运行时 ABI。

## 原生最大化与 Acrylic

- Electron 33 下 `backgroundMaterial: 'acrylic'` 在系统最大化后可能变灰、变白或永久破坏材质。
- Electron 44 已修复该链路；主界面、设置窗和记忆库恢复真正的系统 `maximize()` / `unmaximize()`。
- 移除旧版的工作区缩放、逻辑最大化状态与异步重试补丁。
- 实测最大化与还原后，Windows DWM 的 `DWMWA_SYSTEMBACKDROP_TYPE` 都保持 `3`（Acrylic）。
- 系统吸附、窗口动画和最大化语义恢复为 Windows 原生行为。

## 提示条与透明窗口

- Electron 44 会对透明 frameless 窗口施加约 33 DIP 的平台最小宽度，收起态请求 8px 时会被夹取。
- 提示条继续请求目标尺寸，但使用实际窗口宽度贴回工作区边缘。
- 通过 `setShape()` 把可见与可交互区域精确裁成：
  - 收起态 8px
  - 展开态 328px
- 多余透明区不再绘制，也不接收鼠标事件。

## Electron 44 API 迁移

- 剪贴板 API 全面 Promise 化：
  - `readText()` / `writeText()` 改为异步；
  - 图片读取改用 `clipboard.read()` + `ClipboardItem`；
  - `readImage()` 等旧窄接口移除。
- `console-message` 改用事件对象字段：
  - `level`
  - `message`
  - `lineNumber`
  - `sourceId`

## 兼容说明

- Windows 安装包为 x64，未代码签名。
- Electron 44 不再发布 Windows 32 位和 Linux armv7l 版本。

  但仍需真实文档夹具验证后再升级。
