# Aurora v0.1.4 更新说明

发布日期：2026-09-26 ｜ 安装包：`Aurora-Setup-0.1.4.exe`（Windows x64，未签名）

这一版的主题是 **「让 AI 真的能改代码」**：把电脑操控工具从 5 个扩到 **8 个**，
补上了三个一直缺的能力 —— 精确改文件、按内容找代码、按文件名找文件。

在 v0.1.3 之前，Aurora 的 AI 要改一个文件里的两行，只能**整篇重写**
（token 翻几十倍，而且极易改坏）；要定位一个函数，只能一层层列目录翻。
这版之后它能**先搜、再读、只改那一处**，剩下的字节一个不动。

顺带把两件事一起做了：`run_command` 补上「免确认命令模式」这个中间档
（此前要么每条命令都弹卡片、要么把安全闸门整个关掉），
以及**把系统提示词做成可缓存前缀**、并把「缓存命中多少」显示到界面上。

**配置 Schema 升到 v12**（自动迁移，无需重新引导；安装后直接覆盖升级即可）。

---

## ✨ 一、AI 现在可以精确改文件了（新工具 `edit_file`）

这是本轮最实质的改动。此前 `write_file` 只能整篇覆盖，改两行也要把整个文件重写一遍。

**新工具 `edit_file`** 做的是「精确替换」：给它一段原文和一段新文字，
它只替换命中处，**文件其余部分逐字节不变**。为此做了几件不那么显眼但很要紧的事：

- **改前必须先读**：没在本会话里用 `read_file` 读过这个文件，`edit_file` 会直接拒绝。
  这一条是为了让模型手里**真的握着当前内容**再动手，而不是凭记忆改。
  你在会话里手动改过文件、或模型用 `write_file` 覆盖过之后，「读过」的记录会失效。
- **行尾（换行风格）保真**：CRLF 的文件改完还是 CRLF，LF 的还是 LF ——
  不会出现「改了一行，整个文件的行尾都变了、`git diff` 全文变色」那种事故。
- **唯一性校验**：要替换的原文在文件里出现**多处**时，工具会**拒绝**并告诉你出现了几次，
  要求补足上下文（或明确要求「全部替换」）。避免「以为改了一处、其实有十处」。
- **几种情况直接拒绝，宁可不改也不写坏**：原文找不到、原文为空、
  新旧内容相同、文件含**孤立的回车符**（旧 Mac 行尾）、
  文件**行尾风格不统一**（同时含 CRLF 与 LF 行 —— 这种文件无论怎么改都会波及全文件行尾）。
- **单文件上限 1 MiB**，超过就拒绝并建议改用别的办法（整篇替换在大文件上不可控）。
- **非 UTF-8 编码的文件会被拒绝**：GBK / UTF-16 这类文件按 UTF-8 往返一定会损坏内容，
  这一版**宁可拒绝也不写坏**（这是独立代码复审抓出来的问题，见文末「本版修复的问题」）。

⚠️ **`edit_file` 没有备份，也没有撤销**。它把改动直接写进原文件（原子写只保证「写盘过程不会写坏」，
不保证内容可回滚）。改错了只能靠你自己的版本控制 / 备份 / 编辑器历史恢复 ——
想让 AI 改代码的话，**先把项目放进 git 是最省事的保险**。

`edit_file` 与 `write_file` 共用「文件」开关，属**敏感工具**：每一次调用都会先弹确认卡片，
卡片上能看到要改的原文与新文字。

## ✨ 二、AI 能自己找代码了（新工具 `grep` / `glob`）

- **`grep`**：按正则搜索文件**内容**，返回「文件路径 + 行号 + 命中那一行」。
  拿到位置后它会用 `read_file` 的 `offset` 直接跳到那一段 —— 不必把大文件整篇读进来。
  支持 `include` 过滤（`*.ts`、`*.{ts,tsx}` 这类）。
- **`glob`**：按**文件名**模式找文件（`**/*.ts`、`src/**/*.ts`、`*.{md,txt}`），只返回路径。

两者都是**只读**工具（不弹确认），但**只读不等于没有开销**：它们会递归扫描整个搜索根。
为此内置了几道闸门，并且**都会如实标注**、不会假装找全了：

- 自动跳过 `node_modules` / `.git` / `dist` / `out` / `build` / `.next` / `coverage` / `.turbo`；
- 不跟随符号链接（避免目录环把扫描卡死）；
- 单文件超过 1 MiB 不扫内容（`glob` 只比名字，不受这条限制）；
- 结果条数上限（缺省 200 条，可在设置页调到最多 1000），触顶会标注「结果已达上限」；
- 另有文件数 / 总字节数双预算，触顶会标注「结果可能不完整」；
- `grep` 的正则还拦掉「嵌套无界量词」这类会把事件循环卡住的写法（如 `(a+)+`），
  并给单次搜索加了 10 秒的墙钟上限 —— 到点就停、如实标注，不会让应用卡住。

## ✨ 三、读文件不再只能读开头（`read_file` 契约升级）

此前 `read_file` 只能从文件开头读、超出上限就截断 —— **大文件的后半段根本读不到**。
现在：

- 返回的**每一行都带行号前缀**（`12: 内容`），模型引用原文时能对上位置；
- 新增 `offset`（从第几行开始，1 起始）与 `limit`（读多少行，缺省 2000、上限 5000），
  **任意一段都能读**，不必整篇读进来；
- 单行超过 2000 字符会截断并标注原长；
- 文件超过 16 MiB 时明确告知「只解析了开头，建议用 `grep` 定位」，而不是给一个假的「总行数」。

## ✨ 四、少弹几次卡片：免确认命令模式

此前 `run_command` **每一条命令都弹一次确认卡片**，写代码时会被烦死；
而全局关掉确认（「不用确认敏感工具」）等于把安全边界一起关掉。这版补上了中间档：

设置 → 电脑操控 → **免确认命令模式**，填几条命令模式（如 `git status*`、`npm test*`），
**命中即跳过确认卡片直接执行**，没命中的照旧逐次确认。规则：

- **整条命令的 glob 全串匹配、大小写不敏感**：`*` 匹配任意字符、`?` 匹配一个字符；
- 模式里**只允许字面字符、`*` 和 `?`**。出现别的东西（尤其是花括号 `{}`）会被拒绝保存 ——
  `{a,*}` 这类写法编译出来相当于「放行所有命令」，是会悄悄拆掉闸门的写法，整类禁掉；
- ⚠️ **`*` 也会匹配 `;` / `&&` / `|` 这些命令分隔符**：填 `git status*` 等于放行
  **「以 `git status` 开头的任意命令串」**，包括 `git status; <别的命令>`。
  要真正收窄就写完整命令（`git status`），或明确到参数级（`git log --oneline *`）。
  **命中免确认 = 放行了整串命令**，不只是第一个动词；
- 命中后**仍会写一条审计日志**（记下命令与命中的模式），「为什么这次没弹卡片」可回溯；
- **它只是「减少打扰」，不是安全加固**：命中模式的命令会无人确认地执行，
  身份与能力和你自己在 PowerShell 里敲同一条命令没有区别。要安全边界就**保持列表为空**；
- 这份列表**只能你自己在设置页维护**：AI 的「改自己的设置」明确碰不到它
  （否则它给自己加一条 `git*` 就等于摘掉自己的确认闸门，属于自我提权）。

出厂默认是**空列表** —— 也就是「全部逐次确认」，与升级前的行为完全一致。

## ✨ 五、更快、更省：提示词缓存命中，界面上能看见了

这是个偏底层但直接影响花钱的改动。

各家网关（DeepSeek / OpenAI / 硅基流动等）都有**服务端前缀缓存**：如果每次请求的开头部分
逐字节相同，那部分就按「缓存命中」的低价计费。而 Aurora 此前的系统提示词把
**每轮都变的内容排在了第 3 位**（当前时间、前台窗口），把它后面约三千字符的静态文本
**每轮都顶出缓存**，等于每轮都在重复付一遍全价。另外工具一改设置就会重排工具表，
也会让前缀失效。

这一版：
- 系统提示词小节改成**静态在前、易变在后**（人设 → 模式 → 技能 → 工具 → 规范 → 设置 → 安全规则 →
  再是历史摘要 → 任务清单 → 系统状态）；
- 工具表改成**按名字排序**输出，设置改动不再打乱顺序；
- 对话框底部的「上下文详解」里现在会显示**缓存命中 512（40%）** 这样的信息 ——
  「缓存到底有没有生效」从此可观测，而不是只能靠推理。

> 说明：这一版只做「前缀稳定化 + 命中观测」，**不引入任何新配置项**，
> 也不往请求里塞各家不认的字段（那类字段在不少网关会直接报 400）。

## 🔧 六、本版修复的问题（独立复审发现的）

发布前做了一轮独立的对抗性代码复审，抓出两个真问题，这一版一并修掉了：

1. **非 UTF-8 文件会被静默改坏**（严重）：`edit_file` 读整文件时按 UTF-8 解码，
   GBK 编码的文件会被替换成「容错字符」再写回 —— **整个文件的非 ASCII 内容被无声改写**，
   而且没有备份。现在改为读入时做**全量二进制探测 + UTF-8 逐字节往返校验**，
   非 UTF-8 文件一律拒绝改动。附带把「NUL 字节出现在文件前 8 KiB 之后」的二进制文件也堵住了。
2. **`grep` 的某些正则会冻结应用**：回溯型正则（如 `(a+)+`）撞上长重复行时单次匹配可能几十秒，
   而 `grep` 不弹确认、又在主进程里跑。现在静态拦掉「嵌套无界量词」，并给搜索加了 10 秒墙钟上限。
   （根因是「不可信正则 + 主进程同步执行」，彻底做法是把扫描移进独立进程，属后续单独跟踪项。）

另外修掉：`edit_file` 的新文字里含**孤立回车符**会把文件写成一个此后自己都改不了的状态（现改为拒绝）；
`grep` 的 `include` 参数没有长度上限；「改自己的设置」的工具描述没写明免确认列表不可改；
免确认匹配与真正执行的命令串在首尾空白上口径不一致。

## ⬆️ 八、升级说明

- 直接用 `Aurora-Setup-0.1.4.exe` 覆盖安装；配置、会话历史、分类流水、技能与凭据全部保留。
- **配置自动迁移 v11 → v12**（补上「文件检索」开关与免确认模式列表两项，默认值 = 升级前行为），

  「免确认命令模式」默认空列表（全部逐次确认），按上面第四节的说明谨慎添加。

  命令通道与课表契约完全不变。
- 自动更新：已安装旧版的用户会在后台收到更新提示（更新源 `LinePixel2025/Aurora-releases`）。

## 📌 九、已知限制（本版未做）

- `edit_file` **没有撤销**（同第一节的警示）；也没有 `apply_patch` 这类补丁格式工具。
- 图片内容 OCR 仍**未启用**（读文件只拿文件名与尺寸，不识别图里的文字）；
  LSP 诊断、git 快照 / 回滚、死循环检测都不在本版范围。
- 免确认模式的列表**没有界面化的语法提示校验**（非法模式在保存时报错，但输入时不会实时提示）。
- 设置页「免确认命令模式」在列表**非空**时的界面表现没有纳入截图自动化（空态已覆盖）。
- `grep` 病态正则的**根因**（在主进程同步执行）未消除，只加了静态过滤 + 墙钟护栏。
