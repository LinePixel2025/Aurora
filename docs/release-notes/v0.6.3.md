# Aurora v0.6.3

本次版本汇总 **v0.6.2 → v0.6.3** 的全部更新。五条主线：**多会话并行展示隔离**（每个会话
一套运行态，后台进度可见、切回流式会话不再丢前半段）、**轮终改动文件卡片与任务完成提醒**
（配置 Schema 随此升级到 **v41**）、**内置浏览器按标签切换 UA 与 Agent 操控流光**、
**智慧提醒统一拦截所有提醒入口**（显式流光与提问旁路播报也先攒后汇总）、
**桌面小组件移除毛玻璃**（统一不透明卡片，旧字段仅兼容）。

本版配置 Schema 从 v40 升到 **v41**（新增任务完成提醒字段的默认值，迁移自动完成，无感）；
插件清单与宿主 API 仍为 **v1**；Aurora Center 服务器**不随本版升级**（仍为 0.5.2，版本线
独立，本版无 Center 代码改动）。已有配置 / 会话 / 插件 / 自动化数据全部保留。

## 一、多会话并行：运行态按会话隔离，后台进度可见

- **每个会话一套运行态**：消息、流式状态、在途请求、已完成请求集合、草稿、子代理与用量全部按
  `sessionId` 保存，当前会话只是投影。切回一个仍在流式输出的会话，能看到**完整回复**，不再只有
  后半段或 done 之后仍是半截。
- **后台会话照常接收增量**：非当前会话的文本增量也进入自己的 reducer，这是「切回正在跑的会话
  能看到前半段」的唯一来源；隐藏后台会话（`auto-` / `awareness-` / `-sub`）在不是当前会话时
  跳过，避免大段正文常驻聊天渲染进程。
- **左栏与头部展示后台进度**：会话行新增运行 / 未读 / 需注意状态点，头部有后台会话汇总药丸；
  活动态独立于运行态，不随运行态淘汰丢失。
- **敏感确认卡支持并存**：确认卡从单槽位改为按 `confirmId` 的数组，多个会话同时请求确认时
  不再互相覆盖，也不需要等前一张超时。
- **自动朗读只读当前会话**：记录进入流式时的会话 id，只有收尾的仍是当前会话才触发 TTS，
  切到空闲会话不会再误读旧回复。
- **运行态有界**：最多保留 8 个会话运行态，当前 / 流式 / 有暂停提示的永不淘汰；淘汰后切回
  由历史水合恢复。`chat:sessions` 摘要新增 `running` 初值，但实时状态仍以事件流为准。

## 二、轮终改动文件卡片与任务完成提醒（v41）

- **轮终改动卡片**：一次 Agent 请求正常收敛后，在最后一条回复的正文 / 图片之后显示
  「已编辑 N 个文件」卡片；逐文件列出 `+新增` / `-删除` 行数，二进制、过大或无快照时如实标注
  「二进制 / 过大 / 未知」，不假装 0 行。默认折叠 4 行，可展开「全部 N 个文件」；点击文件在右栏
  「文件」标签预览。卡片只在主进程与渲染层内存中流转，不写会话文件、不进 Center、重启即失。
- **任务完成提醒**：Job 正常收敛（`status: 'done'`）后发一条「任务完成」提醒，正文带会话标题与
  改动文件数，点击打开主界面并切回该会话。`error` / 用户取消 / 轮次上限 `paused` **不发**。
- **两项新设置**（设置 → 提醒 → 任务完成提醒）：`taskDoneEnabled` 总开关（关掉后完全不发，
  也不进免打扰队列）与 `taskDoneBackgroundOnly`「仅主界面不在前台时提醒」（默认开；关掉则每次
  完成都提醒）。判定在主进程完成，焦点用 `windows.isFocused('chat')`，不另发 IPC。
- 配置 **v40 → v41** 自动迁移：为已有 `notifications` 补齐两个默认值（开 + 仅后台），用户已写的
  通道 / 智慧提醒 / 提醒细节原样保留。

## 三、内置浏览器：按标签切换 UA + Agent 操控流光

- **UA 按标签隔离**：浏览器工具条新增 UA 选择，用户与 Agent 标签都可独立选择
  「Chromium 兼容默认」、常见桌面 / 移动端预设或自定义 UA（非空、最多 512 字符）。
  Agent 标签初始值仍受 `agent.browser.compatUserAgent` 控制（关闭时保持原生 UA）；
  普通标签缺省使用去除 Electron / Aurora 标识的兼容 UA。
- **切换语义**：选择只存于本次运行、不持久化；切换会重建该标签并重载当前 `http(s)` 页面，
  可能丢失未提交状态；Agent 控制期间禁用切换，需先停止控制再调整，避免替换主进程登记的 guest。
  自定义 UA 不改变 Chromium 版本、Client Hints 或 TLS 指纹。
- **Agent 操控流光**：某个标签存在 Agent 会话且 Agent 正忙时，浏览器内容区四边显示 **2px
  流光**；Agent 就绪、停止或释放后隐藏。流光鼠标穿透、不挡页面交互，并遵循系统「减少动态效果」
  偏好。
- 截图探针补充对应判据：流光用结构 + 空闲负对照 + 克隆节点量真实 CSS，不依赖「恰好在忙」的瞬时态。

## 四、智慧提醒：统一拦截所有提醒入口

- **修复旁路**：开启智慧提醒后，此前只拦截默认通知路由，插件 `ctx.banner`、Agent
  `notify_banner` 与 `ask_user` 的旁路流光仍会立即弹出。本版把这四条入口统一接入同一个抑制闸，
  免打扰期内**不弹卡、不播提示音或语音**，全部进入同一汇总队列。
- **排队项出队重查**：已经排在流光队列里但尚未展示的提醒，出队前重新检查免打扰状态；排队期间
  刚进入免打扰时不会继续弹出，而是转入汇总队列。
- **结束后统一汇总**：免打扰期结束（时段出窗 / 下课 / 总开关或时段被清空）且队列非空时，
  由模型把所有来源的提醒总结成一条摘要投递；总结失败 / 未开启时回落逐条纯文本，不丢提醒。
- **摘要不会二次入队**：汇总走专用投递路径，并在默认通知与流光载体两层跳过抑制闸，避免摘要
  自己再被收集成环。
- `ask_user` 只静默额外的旁路播报，提问卡与作答流程不变。

## 五、桌面小组件：移除毛玻璃，统一不透明卡片

- 桌面小组件统一使用**不透明卡片**：不再启用原生 Acrylic、不再按窗口矩形裁剪圆角 shape，
  渲染层也移除了 `data-material`、材质订阅与玻璃令牌映射；外观毛玻璃开关不再改变小组件材质。
- 兼容性：旧清单的 `windowMaterial: "acrylic"` 继续通过清单校验并保留在插件摘要里，但宿主
  忽略该声明；`plugins:widgetMaterial` / `onWidgetMaterial` 契约保留，实际材质始终为 `"none"`。
- 小组件层级（floating / normal / desktop）、桌面 owner 亲和、最小化恢复守护、点击不抢前台
  （`focusable: false`）、固定 / 缩放与页面型插件隔离链路均保持不变。
- 设置页插件详情与插件配置窗口不再显示「毛玻璃」徽章；截图探针改为验证实色背景、无
  `backdrop-filter`、无材质 DOM 路径。

## 六、兼容性与升级

- 配置 v40 → v41 自动迁移（补任务完成提醒默认值），升级无感；插件 API 仍为 v1，插件不需要改动。
- 自动更新：Center 更新源优先，GitHub Releases 回退，与 v0.6.2 相同。
- 已知边界（沿旧）：Windows 系统占用 `Alt+Space` 全局热键注册失败是预期路径（会回传原因，
  不静默）；未配置 STT / TTS provider 时对应按钮不渲染；桌面小组件窗口不可激活，卡内文本输入
  拿不到键盘焦点。
