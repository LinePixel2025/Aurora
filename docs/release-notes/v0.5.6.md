# Aurora v0.5.6

本次版本汇总 **v0.5.5 → v0.5.6** 的全部更新：新增一条**独立的提醒通道「流光提醒」**
（屏幕顶端光谱流光 + 置顶卡片，可朗读 / 提示音），设置里新增**「提醒」页**（默认提醒方式
与提醒细节），并修好卡片「弹出来没有动效」的问题。

配置 Schema 从 **v36 升到 v38**（两条迁移：`v36 → v37` 新增 `notifications.channel`，
`v37 → v38` 补提示音 / 音量 / 朗读 / 卡片大小 / 停留时长）；旧配置升级后行为与升级前一致。
插件契约不变（`ctx.banner` 复用既有 `notifications` 权限，属新增 API，不破坏现有插件）。
Aurora Center 代码版本线仍独立（不建 tag、不上传 GitHub Releases），本次双投的仍是桌面安装包
的三个更新资产。

## 一、流光提醒（Banner Notification）通道

一条与系统通知、ClassIsland 提醒并列的**第三条提醒通道**：屏幕顶端出现 Apple Intelligence
风格的弥散光谱流光，提醒内容以置顶卡片从流光中浮现。

- **两扇内部窗口**（都不在 `WINDOW_NAMES`、不写几何持久化）：
  - `banner-glow`：覆盖整块显示器、完全鼠标穿透，只在屏顶画 64px 光谱带（`display.bounds`
    定位，避免任务栏缝隙）；
  - `banner-card`：紧凑置顶卡片，居中、贴顶下浮 16px，**不做穿透**（关闭按钮可点），
    `focusable: false` + `showInactive()` 不抢焦点。
  - 窗口矩形严格等于「卡片 + 24px 阴影外边距」（含 Windows 无边框窗口的边框差自校准）——
    透明 ≠ 穿透，多出来的区域就是挡点击的死区。
- **主进程 `BannerService`**（不 import electron）：一次只显示一条、其余排队（上限 8 条）、
  3 秒同内容去重、停留时长 2–30s、`durationMs + 1.5s` 兜底收尾；失败一律折成
  `{ ok: false, reason }`，绝不抛进 Agent 工具循环或插件调用。
- **三个来源汇聚到同一个 `show()`**：① Agent 工具 `notify_banner`（`safe`、不受
  `agent.tools.enabled` 门控）；② 插件 `ctx.banner`；③ `ask_user` 提问卡片弹出时，**交互窗
  不在前台**才补一条（`speak: false`）。
- **渲染层**：标题 + 正文、等级语义色条、`--bg-overlay` + hairline + `--radius-lg` + `--shadow-2`
  的克制分层；Web Audio 现场合成两声提示音（不新增音频资产）；已配置 TTS 时朗读
  `title + body`，未配置静默跳过。
- **IPC**：`banner:show` / `banner:dismiss` / `banner:measure`（渲染层量内容高度回报，
  主进程据此调窗口），`shared` 与 `preload` 通道表双侧同步。

## 二、「提醒」设置页（默认提醒方式 + 提醒细节）

设置侧栏「基础」组新增**提醒**页（铃铛图标），全部即时生效：

- **默认提醒方式** `notifications.channel`：系统通知 / 流光提醒 / 两者都发 / 不打扰（只记日志）。
  管的是 Aurora 自己发起的提醒（分类完成 / 课前提醒 / 引导 / `notify_user`）——
  `notify_banner` 与 `ctx.banner` 是显式请求流光，不受它影响。
  去重先于通道判定：`both` 下同一条提醒也只算一次。
- **流光提醒细节**：提示音（总闸）、音量 0–100（提示音与语音播报共用）、语音朗读（总闸，
  仍需 TTS 已配置）、弹窗大小（紧凑 360 / 标准 420 / 宽大 480，只改卡片宽度）、
  停留时长（2–30s，滑杆 + 4/6/10 秒快捷档）。
  `sound` / `speak` 是**总闸**：关掉后连请求级 `sound: true` / `speak: true` 也不越过；
  开着时请求级仍可让某一条静音 / 不读。
- 「发送测试提醒」按钮走主进程**同一条**提醒路由（`notifications:test`），验证的是真实生效路径。
- 这些偏好对 AI 开放（`notifications.*` 登记在可写覆盖表），可以让你用一句话让 Agent 帮你切换。

## 三、卡片与光带的入场 / 退场动效

- 修掉「弹出来没有动画」：原先卡片挂载时就带着终态 class（浏览器不会播 transition），
  且主进程先推载荷后显示窗口（页面在隐藏窗口里拿不到绘制帧）。现在入场 / 退场走 Vue
  `<Transition>`，主进程改为「等页面加载 → 显示窗口 → 再推载荷」。
- 卡片从流光里落下（-26px + scale 0.93 + 淡入，540ms 春季曲线），标题 / 正文再晚 60ms 淡入；
  退场 320ms 缩回淡出，光带同步淡出，点关闭时也先播完再回执（不会被关窗截断）。
- `prefers-reduced-motion: reduce` 退化为 120ms 线性淡入淡出、无位移。
- 截图探针新增「动效声明」判据（样式表里的 enter / leave 规则、光带的 transition 时长），
  防以后被删或改名而没人发现。

## 五、升级与兼容

- 配置迁移：`v36 → v37` 只在缺 `notifications` 时补 `{ channel: 'system' }`；
  `v37 → v38` 以默认值为底补五项细节 —— 两段都保留用户已写值，补出来的值等于 v0.5.6
  之前写死在代码里的行为，因此**升级后观感不变**，可在设置页按需打开。
- 提醒页细节区在「系统通知」通道下置灰（系统通知没有这些参数），文案仍可读。
- 安全口径不变：提醒正文可能含用户输入，日志只记标题与长度；凭据仍然只走 safeStorage。
