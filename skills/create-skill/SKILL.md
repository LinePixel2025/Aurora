# create-skill

## 目标

把用户的重复性工作流固化成一个可复用的 Skill，落盘到**用户技能目录**后自动进入
`use_skill` 清单（目录监听会自动重扫，无需重启、无需手动刷新）。

## 工作流程

1. **收集信息**（一次问全，不要逐项追问）：
   - 技能名：小写字母 / 数字 / 连字符（如 `weekly-report`），与目录名一致；
   - 一句话 description：这个技能做什么（会展示在技能清单里）；
   - 适用场景（when_to_use，可选）：什么情况下该用它；
   - 指令正文：用户希望技能每次执行时遵循的步骤、口径与产出格式。
2. **生成 SKILL.md**：frontmatter 与正文格式如下（与内置技能完全一致）：

   ```
   ---
   name: <技能名>
   description: <一句话说明>
   when_to_use: <适用场景，可选>
   ---

   # <技能名>

   <指令正文：步骤、约束、产出格式。写得越具体，技能越可靠。>
   ```

3. **落盘位置**（用户技能目录，`skills.userDir` 为空时是默认目录）：
   - Windows 默认：`%APPDATA%\Aurora\skills\<技能名>\SKILL.md`
   - 目录不存在就先用 `write_file` 直接写文件（写文件会自动建父目录）。
   - 如果用户自定义过技能目录，以用户告知的路径为准；拿不准就先问一句。
4. **可附脚本（可选）**：技能目录下可以放 `scripts/` 子目录存放参考脚本。
   注意：`scripts/` 里的文件**永远不会被自动执行**，只会在技能注入时列出文件清单
   —— 它们是给用户手动使用的，不是给模型执行的。别在正文里写"运行脚本"这类指令。
5. **收尾**：写完后告诉用户「技能已创建并立即生效」，并提醒：可以在
   设置 → 技能 里启用 / 停用或删除它；说 `/技能名` 或 `@技能名` 可以显式调用。

## 约束

- 写文件走 `write_file` 的**全部**权限与确认链路（该弹卡就弹卡）——本技能只是
  教你怎么写 SKILL.md，不授予任何额外权限。
- 覆盖已存在的同名技能前必须先向用户确认（读一下现有内容、说明会被覆盖）。
- 技能正文里不要包含密钥、令牌等敏感信息。
